# etl/backends — backend abstraction, numpy reference backend, StableHLO exporter

## Intent

Turn verified frontend Graphs into executable programs. Four responsibilities:

1. **Backend contract** — `Capabilities`, `Backend` ABC, backend `Executable` protocol, registry.
   This is the plug-in seam for compilers.
2. **Shared pluggable-compiler framework** (`compiler.py`, `inline.py`, `external_split.py`, `external_validate.py`, `adapters/`) — `CompilerBackend` / `CompilerExecutable` plus the shared inlining/splitting machinery, so every compiler adapter reuses the exact same lowering logic as the numpy backend.
   Three adapters are IMPLEMENTED in `adapters/`: `"iree"`, `"xla"` (PJRT C API driven with ctypes — user-provided plugin `.so`, no jax/jaxlib), `"tvm"` — each does lower (shared) → compile (native compiler on the StableHLO text) → load → run.
3. **Reference numpy CPU backend** (`numpy_backend`, default) — a pure-Python numpy interpreter proving the IR semantics; the only concrete-computation path besides `core`'s concrete creators.
4. **StableHLO export utility** (`stablehlo`) — emits StableHLO MLIR text so external compilers (`iree-compile model.mlir -o model.vmfb`) can take over compilation.
   Export-only, NOT a compilable backend.

**Ownership (binding):** `LoweredProgram` and `CompiledArtifact` are owned by THIS package, not by `pipeline`; `pipeline` orchestrates staging and re-exports them.

**Authority split (do not restate subordinate files here):** adapter contracts, per-adapter capabilities and known issues live in `./adapters/CONTEXT.md` (with narratives/measurements in `./adapters/PER-ADAPTER-NOTES.md`); the exporter's per-op mapping, emitters, deferral list, dynamic-dims matrix, dtype map and option values live in `./stablehlo/CONTEXT.md` (measurement evidence in `./stablehlo/EMISSION-NOTES.md`); the numpy interpreter's internals live in `./numpy/CONTEXT.md`; test coverage per file lives in `../../tests/backends/CONTEXT.md`.

See `../../CONTEXT.md` (principles, staging pipeline, error strategy) and `../CONTEXT.md` (cross-module contracts) — both binding.

## Constraints (binding)

- **Import acyclicity** (from `../CONTEXT.md`): top-level imports restricted to `etl.core` and `etl.ir`.
  `etl.ops` may be imported ONLY inside function bodies (block-impl registration).
  `etl.persist` may be imported ONLY inside function bodies (persist sits ABOVE backends in the DAG — a top-level import would be a cycle).
  NEVER import `etl.pipeline` (pipeline imports backends).
- **Errors**: capability violations and unsupported ops raise `core.BackendError` — always naming the op/feature.
  Load-time mismatches (backend/device/ABI/custom-op availability) raise `core.PersistenceError` — never silently re-lower/re-compile.
  `lower()` surfaces `core.VerificationError` from `graph.verify()`.
  Runtime shape failures raise `core.ShapeError`.
  No silent fallbacks or partial semantics.
- **No hidden staging**: `load()` never traces/lowers/compiles.
  Artifacts are self-describing (backend name/version, target, signature, required custom ops, IR format version).
- **Files < ~1000 lines** — kernel modules are pre-split by category (`numpy/kernels/`); stablehlo mapping data lives separately from the writer (the writer itself is the known exception — see `./stablehlo/CONTEXT.md`).
- **CPU only in v1**: the numpy backend never requires or touches GPU.

## Numpy backend design (reference CPU interpreter)

**Capabilities**: name `"numpy"`; `dynamic_shapes=True`; `dtypes=` all numpy dtypes; `collectives=True` (single-process simulation); `runtime_calls=True`; `external_calls=True` (host-mode slots only — a resolved numpy slot registered `device_resident=True` raises `BackendError`); `custom_blocks=True`; `async_collectives=False` (simulation is synchronous); `sparse_ops=True` (the ONLY backend with sparse support in v1 — the 16 `sparse_*`/`dense_dot_sparse` ops are numpy-implemented only).

**Staging flow** (see `numpy/__init__.py`):
- `lower(graph, options=None)`: (1) `graph.verify()`; (2) `kernels.register_all()` (idempotent) + capability pre-check on the current module state (effect flags vs `Capabilities`, kernel-table membership re-checked AFTER inlining as the drift net); (3) inline `block_call` portable decompositions as a graph→graph expansion via the SHARED fixpoint `inline.py::inline_portables(module, keep_backend_impls="numpy")` (a block with neither portable nor registered numpy impl ⇒ `BackendError` naming the block); (4) defensive post-inline `graph.verify()`; (5) record `Signature` from the Graph's LIVE attributes; (6) `payload` = versioned self-describing `ir.Module` serialization (`ir.serialize_module`).
- `compile(lowered, options=None)`: validate `lowered.backend == "numpy"`; wrap the serialized module into a `CompiledArtifact` (`target="cpu"`, records required custom ops + `runtime_dependencies={"numpy": <version>}`).
  No machine code exists — the artifact IS serialized IR.
- `load(artifact, device=None)`: validate backend/device (None or CPU; else `BackendError`/`DeviceError`); `ir.deserialize_module`; build a `NumpyExecutable`.
  Never re-compiles.

**Interpreter execution model** (`NumpyExecutable.run(flat_input_tensors)`):
- **Execution order = block op order.** This IS the effect ordering (write/read/collective/callback ops anchor order); pure ops could be reordered but program order is kept for determinism.
- **Shape inference: reuse, don't duplicate.** Runtime shapes are computed from concrete input shapes using the SAME ops-level inference rules with symbolic dims bound to concrete values (`numpy/shapes.py` evaluates `DimExpr` against name→int bindings).
  The backend carries NO second copy of shape rules.
  Free symbolic dims at run time ⇒ `ShapeError`.
- **dtypes**: numpy dtype ↔ etl dtype is 1:1; kernels validate support; no promotion beyond what ops define.
- **Control flow**: `cond`/`while_loop`/`scan` region ops are interpreted by recursively running region blocks — genuinely dynamic runtime control flow (the graph is NOT specialized per iteration).
- **`runtime_call`**: executes the Python callback synchronously at the op's position — a documented sync point (no async execution in v1).
- **`block_call` dispatch**: portable decompositions are inlined at `lower()` time, so the interpreter only ever dispatches blocks that have a registered numpy impl (`kernels/custom.py`); otherwise `BackendError`.
- **`external_call` dispatch**: resolved by name at the op's position via `etl.external.get_external_kernel_entry(name, "numpy")`; all matching/validation rules are in the frontend contract (`../CONTEXT.md`, "External kernels").
- **Collectives**: ALL collective ops dispatch through the canonical `CollectiveExecutor` hook in `etl.dist.context` (`set_collective_executor`/`get_collective_executor`); the numpy backend installs its default `SingleRankCollectiveExecutor` (identity semantics on one rank) into that slot at import, and tests simulate multi-rank in-process by installing a custom executor.
  `numpy/collectives.py` only defines the default executor class.
  Group semantics are simulation-only in v1.
- **rank/world_size**: resolved at RUN time from a per-execution `dist.context.RankContext` (default rank 0 / world_size 1; overridable per run via `numpy/exec_context.py`'s thread-local `set_rank_context` or the `run(..., rank_context=...)` kwarg) — never constant-folded at lower/compile time.
- **`NumpyExecutable` persistence**: `.save(path)` saves the underlying `CompiledArtifact` — the executable is reconstructed explicitly at `load`; device handles are never serialized.

**Kernel split** (`numpy/kernels/`): `elementwise.py` (arith/activations/comparisons/select/cast/broadcast), `reductions.py` (reduce_*, argmax/argmin), `indexing.py` (reshape/transpose/slice/concat/pad/gather/scatter/tril/triu/cumsum), `linalg.py` (dot/conv/solve), `sorting.py` (sort/argsort), `structural.py` (tile/flip/roll/diag/nan_to_num), `control_flow.py` (if/while/call region execution), `collective.py` (collective dispatch via the hook + rank/world_size), `custom.py` (`runtime_call`, `block_call`, `external_call`, `constant`), `sparse.py` (the 16 sparse kernels: from_dense/to_dense, coo↔csr/csc conversions, add/multiply/negate/multiply_dense, reduce_sum, transpose, reshape, concatenate, sparse_dot_dense/dense_dot_sparse), `random.py` (the 6 random kernels over all 3 algorithms). `kernels/__init__.py` assembles the dispatch table from every category module's `register_kernels(table)` (`register_all()` is idempotent, duplicate registrations raise); `dispatch(op_name)` maps op name → kernel and raises `BackendError` naming the op for an unknown name (capability-drift safety net). The kernel contract (`kernel(ctx, op, operands)` + `KernelContext`) and the interpreter loop live in `numpy/interpreter.py`; per-category semantics in `numpy/kernels/`; details in `./numpy/CONTEXT.md`.

## StableHLO exporter — scope & ownership

`stablehlo.export(graph_or_module, options=None) -> str` emits StableHLO MLIR text (module + `func.func` + `return` shell) from a verified module, and is used BOTH as standalone compiler input (`iree-compile model.mlir -o model.vmfb`) and as the LOWERING PAYLOAD of every compiler adapter (`CompilerBackend.lower`). It is an export utility, NOT a `Backend`: no compile/load/run, no runtime.

- **Authoritative detail lives in `./stablehlo/CONTEXT.md`**: the per-op mapping table (direct mnemonics, decompositions, `SPECIAL_EMITTERS` compositions for gather/scatter/sort/argsort/arg-reduce/tile/eigh/diag/random), the v1 DEFERRED list, the per-op dynamic-dims allow/reject matrix, the dtype→MLIR `DTYPE_MAP`, and every exporter option with its accepted values.
  Measurement evidence (what each composition costs and why) is in `./stablehlo/EMISSION-NOTES.md`.
  Mapping data: `./stablehlo/ops.py`; text emission: `./stablehlo/writer.py`.
- Anything unmapped or deferred raises `core.BackendError` naming the op at export/`lower()` time — never invalid MLIR reaching a compiler, never a silent approximation.
- `scan` has no IR OpDef: `etl.scan` desugars at trace time into `while` + `gather` + `scatter`, so scan graphs export and run.
- Adapter-side dynamic-shape support is per-op PARTIAL; the exporter is the gate (allow/reject lists in `./stablehlo/CONTEXT.md`).

## Serialization compliance

`LoweredProgram.save`/`CompiledArtifact.save` delegate to the `etl.persist` container format (lazy import): magic header + format version + JSON metadata + payload + SHA-256 integrity. Metadata is self-describing: backend name/version, target, signature (TreeSpecs + specs + static values), required custom ops, IR format version. `load()` validates the recorded backend against the registry (numpy reconstruction handled by `NumpyBackend`) — mismatch or missing custom op ⇒ `PersistenceError`. Never silently re-traces/re-compiles.

## Compiler adapter framework (design)

`compiler.py` is the pluggability seam: a new StableHLO-consuming compiler backend is a `CompilerBackend` subclass declaring `name`/`capabilities`, implementing `check_available()` (dependency probe with a `pip install etl[...]` hint), `compile()` (invoke the native compiler on the payload's `mlir_text`; JSON-safe artifact payload), and `load()` (rebuild the executable — never recompiling), plus a `CompilerExecutable` subclass implementing `run()`. The shared `lower()` does everything else (verify → capability pre-check — incl. dynamic dims in function signatures when `dynamic_shapes=False` → portable block inlining → StableHLO export — the per-op dynamic-dims gate for `dynamic_shapes=True` backends → Signature → MLIR payload). The "How to add a new adapter" recipe lives in `compiler.py`'s docstring.

**The three implemented adapters** (`./adapters/`) are optional and lazily activated; a missing compiler dependency raises an explicit `core.BackendError` (pip hint for iree/tvm; `plugin_path`/`ETL_PJRT_PLUGIN` guidance for xla, which needs a user-provided PJRT plugin `.so` — no pip package exists). Shared capability floor: `collectives=False`, `runtime_calls=False` (rejected at `lower()`), `custom_blocks=False` (portable-only inlining), `async_collectives=False`, `sparse_ops=False`; `dynamic_shapes` is per-op partial; `external_calls=True` for iree (segment split + host/device dispatch) and `False` for xla/tvm (portable inline at `lower()`, else explicit `BackendError`).

**Per-adapter capabilities, compile targets/drivers, supported dtypes, device kinds, persistence and validated hardware are owned by `./adapters/CONTEXT.md`** (narratives + measurements in `./adapters/PER-ADAPTER-NOTES.md`). Adapters never silently fall back to the numpy backend.

## Backend options override (binding)

Every pipeline stage — `lower`, `compile`, `load`, `run` (plus the `build`/`evaluate` sugar and `etl.bind`-ed executables) — accepts backend options via the existing `**options` kwargs. The mechanism (design doc: "we only took care of the graph, provide a clean pipeline, and everything else should be hack-able") is general: users can override ANY compiler flag or related option without etl hardcoding them.

- **Option NAMES are validated; option VALUES never are** — the exceptions are `opt_level` (etl-defined: etl translates its value per backend, so etl validates it — see the `opt_level` bullet below) and the reserved StableHLO-exporter lower options, whose values the Writer validates (see the reserved-keys bullet below).
  Each backend/executable declares `KNOWN_OPTIONS: dict[str, frozenset[str]]` (stage → key set).
  `etl/backends/options.py::validate_options(options, known, backend_name, stage)` validates a stage's options against the **union of all stages' sets** (a key valid for any stage passes, accepted-and-ignored elsewhere — `build`/`evaluate` forward one dict to every stage).
  A key in no stage's set raises `core.BackendError`: "the {backend} backend does not recognize the {stage} option '{key}' — known options by stage: lower: …, compile: …, load: …, run: …".
  Flag/option VALUES always pass through — the compiler validates them (etl never parses compiler flags).
  `STAGES = ("lower", "compile", "load", "run")`.
- **Precedence (binding): explicit kwarg > env var (`ETL_<BACKEND>_*`) > etl default.** Env vars are read lazily at call time by `etl.pipeline_options.apply_env_options` (table in `etl/pipeline_options.py::ENV_OPTION_TABLE`); empty/whitespace env = unset; malformed env values raise `core.BackendError` naming the variable and value.
  Env application is stage-scoped (e.g. `ETL_IREE_RUNTIME_ARGS` applies only at the load stage).
  Value formats (parsers in `etl/pipeline_options.py`): the flag-list rows `ETL_IREE_COMPILE_ARGS`/`ETL_IREE_RUNTIME_ARGS` are split with `shlex.split` — QUOTING IS PROCESSED, so a quoted flag survives as one entry — and must yield ≥1 flag; `ETL_XLA_COMPILE_OPTIONS` is base64 of the serialized proto bytes; `ETL_TVM_PASS_CONFIGS` is a JSON object; `ETL_OPT_LEVEL`/`ETL_EIGH_ALGORITHM`/`ETL_SPLIT_REDUCTION` are backend-agnostic spellings (ONE row per compiler adapter, same option key).
  Full env-name table + precedence doc: `etl/pipeline_options.py` and `../CONTEXT.md` ("Backend options override").
- **Backend defaults are minimal, documented, and OVERRIDABLE.** A user flag with the same NAME as an etl default drops the default (never both) — etl must never force flags users cannot override.
  The numpy reference backend documents-ignores unknown options (`run(..., rank_context=...)` still flows through the options dict; the caller's dict is never mutated).
- **Per-adapter `KNOWN_OPTIONS` key ownership** (semantics + values in `./adapters/CONTEXT.md`): iree — lower `rng_bit_generator`/`sort_emission`/`while_init_rewrite`/`dot_precision`/`eigh_algorithm`/`split_reduction`, compile `target_backends`/`iree_compile_args`/`opt_level`, load `iree_runtime_args`; xla — lower `rng_bit_generator`/`dot_precision`/`eigh_algorithm`/`split_reduction`, compile `plugin_path`/`xla_compile_options`/`opt_level`, load `plugin_path`; tvm — the same four lower keys, compile `tvm_target`/`tvm_pass_configs`/`opt_level`, no load key.
  Run-stage sets are v1-empty for all three (non-empty → loud `BackendError`), by design.
- **Reserved exporter lower options** (forwarded by `CompilerBackend._exporter_options` to `etl.backends.stablehlo`; declared in each consuming adapter's `KNOWN_OPTIONS["lower"]`; KEY validation is the framework's, VALUE validation is the Writer's with a loud `core.BackendError` naming the accepted forms): `rng_bit_generator` (bool or a collection of algorithm names, default = the adapter's `Capabilities.rng_bit_generator` — per-call override of the native-emission capability), `sort_emission` (`"pair"` | `"count"` | `"auto"`, default = `default_sort_emission`, whose class default is `"pair"` while the iree adapter sets `"auto"` and upgrades to `"count"` for cuda targets), `while_init_rewrite` (bool, default `True`), `dot_precision` (`"DEFAULT"` | `"HIGH"` | `"HIGHEST"`, default `"DEFAULT"` = no `precision_config` emitted; only `"HIGHEST"` disables XLA/ROCm's TF32-class fp32 `dot`), `eigh_algorithm` (`"jacobi"` | `"jacobi_batched"`, case-insensitive, whitespace-stripped, default = `default_eigh_algorithm` = `"jacobi_batched"`), `split_reduction` (bool, default = `default_split_reduction` = `True`).
  The BOOL-valued ones (`split_reduction`, `while_init_rewrite`) are coerced to a real `bool` by `options.normalize_bool_option` inside `_exporter_options`, so env-style strings (`"0"`/`"false"`/`" off "`) cannot fall into the `bool("0") is True` trap.
  `eigh_early_exit` (and `split_reduction_threshold`/`split_reduction_non_exact`) are EXPORT-ONLY — no adapter declares them, so `etl.build(..., eigh_early_exit=...)` raises the unrecognized-option `BackendError`; entry point is `stablehlo.export(graph, options={...})`.
- **DENY list (iree)**: a small documented set of flags is rejected with actionable reasons (`--iree-hal-target-backends` → use `target_backends`; `--iree-input-type` → StableHLO is always the input; `--iree-vm-bytecode-module-output-format` → the adapter requires the default VM flatbuffer output).
  Everything else in `iree_compile_args`/`iree_runtime_args` passes through to the compiler/loader.
  Details: `./adapters/CONTEXT.md`.
- **`opt_level` — the first etl-defined, etl-validated option** (compile stage, all three compiler adapters; `normalize_opt_level` + the `OPT_LEVEL` key constant live in `etl/backends/options.py`, exported in `__all__`, also consumed by the pipeline env-var resolution for `ETL_OPT_LEVEL`): accepted values `"O0"`..`"O3"` (case-insensitive, whitespace-stripped), `"0"`..`"3"`, or ints 0..3 (bool rejected) — anything else raises a loud `core.BackendError` naming the option and the accepted forms, never silently swallowed.
  Per-backend translation: iree → the derived flag `--iree-opt-level=O{N}` (O-form REQUIRED — iree-base-compiler 3.11 rejects numeric levels), which joins etl's defaults in the name-collision machinery: a user `--iree-opt-level=…` in `iree_compile_args`/`ETL_IREE_COMPILE_ARGS` wins and the derived flag is dropped — never both (the conflict rule); xla → injected into the serialized `CompileOptionsProto`'s `executable_build_options` (wire-format field 24, `c0 01 <N>`) by `xla_util.set_opt_level`, and an optimization level already present in the user's `xla_compile_options` bytes wins unchanged (never override, never both); tvm → forwarded to `build_vm_executable(..., opt_level=N)` as a version-adaptive kwarg (installed TVM 0.26 has no `opt_level` kwarg and PassContext provably does not reach the LLVM codegen, so a build without the kwarg gets a loud `BackendError` naming `opt_level` and the installed TVM; never silently dropped); numpy documents-ignores it.
  Unset `opt_level` = byte-for-byte unchanged behavior on every backend.
- **Lower-stage backend-agnostic env spellings.** The two reserved exporter lower options have per-backend env rows in `etl/pipeline_options.py::ENV_OPTION_TABLE` — `ETL_EIGH_ALGORITHM` (`eigh_algorithm`: `"jacobi"` | `"jacobi_batched"`, case-insensitive, whitespace-stripped, default `"jacobi_batched"`) and `ETL_SPLIT_REDUCTION` (`split_reduction`: bool — `1`/`0`, `true`/`false`, `yes`/`no`, `on`/`off`, case-insensitive, default `True`) — registered for all three compiler adapters with ONE option key each.
  These are not raw pass-through values: `eigh_algorithm` is validated by the Writer (`stablehlo/writer.py::_normalize_eigh_algorithm`) and `split_reduction` is coerced by `options.normalize_bool_option`, so a malformed env/pipeline value raises a loud `core.BackendError` naming the option, the value and the accepted forms (precedence unchanged: explicit kwarg > env var > adapter class default).
- **`normalize_bool_option(option, value) -> bool`** is the shared coercion for BOOL-valued options: real bools, ints 0/1, and case-insensitive `"true"`/`"false"`/`"yes"`/`"no"`/`"on"`/`"off"`/`"1"`/`"0"`; anything else raises a loud `BackendError` naming the option, the value and the accepted forms.
  It is a TYPE COERCION, not a per-backend semantic mapping.

## Known Issues

- **StableHLO writer semantics surfaced by adapters** (in this package's `stablehlo/`): mixed-dtype elementwise/compare/select operands (including Python scalar constants) are equalized by the writer with `stablehlo.convert` (see `stablehlo/CONTEXT.md`), and `stablehlo.add` on i1 is XOR (XLA semantics) vs numpy bool+ = OR.
  Dynamic-shape broadcasts are supported — the writer emits `stablehlo.dynamic_broadcast_in_dim` (output_dimensions built via `get_dimension_size` chains) whenever a broadcast's result has dynamic dims, validated end-to-end through iree and tvm at multiple concrete sizes; broadcasts with no full-shape source raise `BackendError` naming "dynamic broadcast" (see `stablehlo/CONTEXT.md`).
- **Sparse ops (v1, numpy-backend-only):** the 16 `sparse_*`/`dense_dot_sparse` ops (etl.sparse family) are implemented ONLY by the numpy backend; compiler backends (stablehlo export, iree/xla/tvm adapters) defer with an explicit `BackendError` naming the op and suggesting densification via `etl.sparse.to_dense` — never silent.
- **External kernels on compiler backends (v1 dispatch/fallback semantics):** the iree adapter splits `external_call` graphs at lower() into segments (see `external_split.py`) and dispatches each boundary through `get_external_kernel_entry(name, "iree")`: HOST-mode kernels (default registration) stage the boundary tensors device→host→device (a `UserWarning` is emitted ONCE per executable at the first boundary that actually stages), while DEVICE-RESIDENT kernels (`device_resident=True`, explicit per-backend slot only) receive device tensors directly and return device tensors / duck payloads — kernel authors may isinstance-check the PUBLIC `etl.backends.adapters.iree.IreeDevicePayload` (`.device_array` HAL handle, `.shape`, `.dtype`, `.to_host()`, `.device`) and e.g. run additional vmfb modules on the SAME HAL device; results are validated metadata-only (never a forced host copy), so fully device-resident boundaries never warn (numpy-returning device kernels stage back — boundary marked staged).
  Lower-time restrictions (MODE-AWARE): no control-flow bodies around calls, ≥1 operand, kernels assumed pure, sequential plan order, and — for HOST-mode boundaries only — STATIC (integer) result dims (host staging needs concrete shapes); DEVICE-RESIDENT boundaries allow symbolic / runtime-dynamic result dims (e.g. vmap/vectorize batch dims on a batched-variant kernel), validated metadata-only at run time with the ACTUAL runtime shapes — the stablehlo exporter's per-op symbolic-shape support decides what compiles (unsupported segment ops still raise explicit `BackendError`, never silent). xla/tvm have no host-dispatch: an `external_call` op with a registered portable decomposition (`etl.external.get_portable`) is INLINED at lower() through the shared portable-splicing machinery with a `UserWarning` per kernel name (the original call's effect/callback ordering is replaced by the inlined graph's op order); an op WITHOUT a portable raises an explicit `BackendError` naming the op/backend and listing the options (iree/numpy backends, or `etl.register_external_kernel(name, fn).portable(decomp)`).
  The stablehlo exporter itself still defers `external_call` (pure export utility — direct-export users see the deferral).
  Never silent.
- **Adapter-specific known issues live in `./adapters/CONTEXT.md` (authoritative; per-probe measurements in `./adapters/PER-ADAPTER-NOTES.md`)** — iree legalization limits (native `rng_bit_generator` PHILOX, `collective_broadcast`, u32/u64 reduce) and target/driver quirks, ROCm/HIP while-loop fragility, the XLA user-provided-PJRT-plugin requirement plus its interpreter-exit abort caveat, TVM's jaxlib-bindings dependency and compile-time op gate, and the pyproject extras (repo root — escalated).

## Notes for agents

- **Implementation status: complete.** All behavioral bodies in `backend.py`, `program.py`, `compiler.py`, `inline.py`, `registry.py`, `numpy/`, `stablehlo/`, and `adapters/` (iree/xla/tvm) are implemented; no `NotImplementedError` stubs remain in this node (the abstract `compile`/`load`/`run` methods of `CompilerBackend`/`CompilerExecutable` are adapter contracts, by design; `check_available` is a concrete default no-op).
  `etl.pipeline` (orchestration above this package) and sibling test suites are handled elsewhere.
- Optional adapters are NEVER imported at `etl`/`etl.backends` import time — `registry.get("iree"|"xla"|"tvm")` imports + registers them on first use (`import etl` leaves `sys.modules` free of iree/jax/jaxlib/tvm).
  `program.py._require_registered_backend` routes through `get()`, so persisted adapter artifacts auto-activate on load.
- The IR op names for control flow are `if`/`while` (trace lowers `cond`/`while_loop`/`scan` into them) and the dist broadcast collective is `broadcast_collective` — frontend names differ from IR names; kernels and the stablehlo writer dispatch on IR names.
- `runtime_call` carries its callback as a STRING registry id (resolved via `etl.ops.constant._get_callback` at run time) — artifacts with `runtime_call` require the same callback registrations at load time; callbacks are never serialized.
- Block-impl convention (finalized with `etl.block`): the interpreter invokes registered numpy impls as `impl(*numpy_arrays, **static_args) -> ndarray | tuple[ndarray]`; portable decompositions are spliced into the graph at `lower()` time via `etl.block.registry`.
- Collective protocol limitation: `dist.context.CollectiveExecutor` has a single `axis` param for `all_to_all` (kernel forwards `split_axis`) and no `reduce_op` for `reduce_scatter` — documented in `numpy/kernels/collective.py`.
- `../../tests/` is a sibling: read-only, escalate writes to root.
