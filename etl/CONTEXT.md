# etl package — public API contract

## Intent

The `etl` package: an explicit, minimal tensor graph runtime.
See root `../CONTEXT.md` for the binding principles, the four-concept value-model table, the import-acyclicity contract, the error strategy, and the non-goals — all binding here.
This file owns the **public API surface** (names that must exist) and the **cross-module contracts** every submodule must honor; per-feature implementation detail lives in the child nodes listed in the routing table.
This file must stay under the ~64 KB per-file read limit — push new detail down to the owning child node instead of growing it.

Pipeline objects are distinct public types (`Defn` → `Graph` → `LoweredProgram` → `CompiledArtifact` → `Executable` → `Tensor`); no function silently consumes an earlier-stage object and performs the missing steps.

## Public API surface (the contract — must exist, exact names)

**Staging & pipeline** (owned by `pipeline.py`):
- `@etl.defn` → `Defn` (calling a `Defn` with concrete tensors must raise `TraceError` directing to `trace`/`evaluate`)
- `etl.trace(fn_or_defn, *specs) -> Graph` (accepts nested structures of `TensorSpec` + static values)
- `etl.lower(graph, backend=None, **options) -> LoweredProgram`; `etl.compile(lowered, backend=None, **options) -> CompiledArtifact`; `etl.load(artifact, backend=None, device=None) -> Executable`
- `etl.run(executable, *args) -> outputs` (structured inputs/outputs via TreeSpec; validates static fields)
- `etl.bind(obj, **bindings) -> BoundExecutable|callable` (pure argument-supply sugar; validates names/dtypes/shapes/devices; never alters the graph)
- `etl.build(fn, *specs, backend=None, device=None, **options) -> Executable` — documented shorthand for trace→lower→compile→load
- `etl.evaluate(fn, *args, backend=None, device=None, **options)` — documented shorthand: derive specs → build → run (deriving a spec from a concrete tensor snapshots shape+dtype only)
- `etl.build_cached(fn, *specs, backend=None, device=None, cache=None, **options) -> Executable` — documented shorthand for a MEMOIZED `build` (see "Memoized build sugar" below)
- `etl.CompileCache` — the in-memory LRU compile cache backing `build_cached` (default `maxsize=128`)
- **`build`/`evaluate`/`build_cached` env defaults** (explicit kwargs ALWAYS win; env read lazily at call time): unset `backend` from `ETL_BACKEND` (default `"numpy"` when unset/empty); unset `device` from `ETL_DEVICE` (`"kind[:index]"`, e.g. `"cpu"`/`"cuda:0"`/`"rocm:0"`/`"vulkan:0"`, parsed to `core.Device`; malformed → `DeviceError` naming the variable and value); unset `target_backends` from `ETL_TARGET_BACKENDS` (comma-separated), otherwise an iree-family backend (name startswith `"iree"`) infers it from the resolved device (`cuda` → `["cuda"]`, `rocm`/`hip` → `["rocm"]`, `vulkan` → `["vulkan-spirv"]`, `cpu` → `["llvm-cpu"]`). AMD ROCm devices are spelled `"rocm"` (canonical) or the accepted alias `"hip"` — both valid and equivalent, never rewritten. The explicit stage functions (`lower`/`compile`/`load`) keep their documented defaults. Implementation: `pipeline._resolve_backend_device`; regression suite `tests/pipeline_env_defaults_test.py`.
- `etl.io` — namespaced submodule (like `etl.random`, NOT flat top-level names): `etl.io.prefetch(host_tensor, device) -> AsyncCopy`, `etl.io.sink(device_tensor) -> AsyncCopy`, `etl.io.wait_all(timeout=None)`, class `etl.io.AsyncCopy` (see "etl.io" below)

## Backend options override (binding)

Design principle: *"we only took care of the graph, provide a clean pipeline, and everything else should be hack-able"* — etl never hardcodes compiler flags users cannot override.
- **Every stage accepts options**: `lower(graph, backend=..., **options)`, `compile(lowered, backend=..., **options)`, `load(artifact, backend=..., device=..., **options)`, `run(executable, *args, **options)`, and `build`/`evaluate`/`build_cached` forward ONE options dict through every stage. Option keys are ADDITIVE (existing signatures keep working).
- **Option keys are validated by the framework; option values are the consumer's job.** Each backend/executable declares `KNOWN_OPTIONS: dict[stage, frozenset[str]]` (`lower`/`compile`/`load`/`run`); `etl.backends.options.validate_options` validates a caller's dict against the UNION of all stage sets — a key valid for ANY stage passes and is accepted-and-ignored at the others (so one dict can be forwarded), a key valid for NO stage raises `core.BackendError` listing the per-stage known sets. Flag/option VALUES otherwise pass through to the compiler (or, for exporter options, to the stablehlo Writer) — etl never parses compiler flags.
- **The only values etl itself validates** (`normalize_opt_level` / `normalize_bool_option` in `etl/backends/options.py`): `opt_level` (below), and BOOL-valued options — TYPE-COERCED to a real `bool` (real bools, ints 0/1, and `"1"/"0"/"true"/"false"/"yes"/"no"/"on"/"off"` case-insensitively; anything else → loud `BackendError` naming the option, value and accepted forms), so an env-style string like `"0"` can never hit the `bool("0") is True` trap.
- **Precedence (binding): explicit kwarg > env var > etl default.** Env vars are read lazily per call; empty/whitespace = unset; malformed → `core.BackendError` naming the variable and value. Env vars are stage-scoped; full table + parsers in `etl/pipeline_options.py`:

| Env var | Backend / stage | Option key | Value format |
|---|---|---|---|
| `ETL_IREE_COMPILE_ARGS` | iree / compile | `iree_compile_args` | shlex-split flag list (quoting IS processed, ≥1 flag) |
| `ETL_IREE_RUNTIME_ARGS` | iree / load | `iree_runtime_args` | shlex-split flag list |
| `ETL_IREE_VULKAN_TARGET` | iree / compile | `vulkan_target` | SPIR-V target profile string (`rdna3`, `sm_80`, `adreno`, …; whitespace-stripped — the VALUE is the compiler's to validate) |
| `ETL_XLA_COMPILE_OPTIONS` | xla / compile | `xla_compile_options` | base64 of serialized `xla.CompileOptionsProto` bytes |
| `ETL_TVM_TARGET` | tvm / compile | `tvm_target` | plain string (whitespace-stripped) |
| `ETL_TVM_PASS_CONFIGS` | tvm / compile | `tvm_pass_configs` | JSON object (must decode to a dict) |
| `ETL_OPT_LEVEL` | iree/tvm/xla / compile | `opt_level` | `'O0'`–`'O3'` (case-insensitive), `'0'`–`'3'`, or ints 0–3 (etl-validated value) |
| `ETL_EIGH_ALGORITHM` | iree/tvm/xla / lower | `eigh_algorithm` | `"jacobi"` or `"jacobi_batched"` (whitespace-stripped; VALUE validated by the Writer) |
| `ETL_SPLIT_REDUCTION` | iree/tvm/xla / lower | `split_reduction` | bool spellings (coerced by `normalize_bool_option`) |

- **Backend-agnostic spellings.** An option every compiler adapter accepts IDENTICALLY gets ONE `ETL_<OPTION>` spelling rather than one variable per backend (`ETL_OPT_LEVEL`, `ETL_EIGH_ALGORITHM`, `ETL_SPLIT_REDUCTION`); such a row is repeated under each adapter's `(backend, stage)` key, so `lower` carries env rows like `compile`/`load` do.
- **`opt_level` — the first-class etl-defined compile-stage option.** Values `'O0'`–`'O3'` (case-insensitive), `'0'`–`'3'`, or ints 0–3, normalized to 0..3 by `etl.backends.options.normalize_opt_level`; a bad value raises a loud `core.BackendError` naming the option and accepted forms (raw compiler flags remain pass-through). Per-adapter translation: iree derives `--iree-opt-level=N`; xla sets the `CompileOptionsProto` optimization-level field; tvm sets its build optimization level; numpy documents-ignores it. Conflict rule (binding): an explicit raw flag with the same underlying name (e.g. `--iree-opt-level=N` in `iree_compile_args`, or an already-set field in `xla_compile_options`) WINS over the derived value — never both. `etl.bench` defaults compiler backends to `opt_level="O3"` (env-aware, explicit wins, numpy unaffected).
- **`vulkan_target` — the SPIR-V target-profile compile-stage option.** A non-empty string deriving the iree-compile default flag `--iree-vulkan-target=<profile>`, joined into the SAME defaults list as `opt_level` so the identical conflict rule applies (a raw `--iree-vulkan-target=<p>` in `iree_compile_args` WINS — never both). UNSET derives NO flag (byte-identical existing behaviour for every target); a non-str/empty value, or a value supplied without `vulkan-spirv` in `target_backends`, raises a loud `core.BackendError`. The value itself is the compiler's to validate — etl never parses compiler flag values. Purpose: without a profile, `vulkan-spirv` codegen uses IREE's default `vp_android_baseline_2022` (16384-byte workgroup memory, 128 threads), which cannot compile 124M-parameter-class graphs. Env `ETL_IREE_VULKAN_TARGET`.
- **Reserved lower-stage exporter options** (forwarded by `CompilerBackend._exporter_options` to `etl.backends.stablehlo`; the framework validates KEYS, the Writer validates VALUES with a loud `BackendError` naming the accepted forms). Declared in `KNOWN_OPTIONS["lower"]` by iree (all six) and by xla/tvm (`rng_bit_generator`, `dot_precision`, `eigh_algorithm`, `split_reduction`):
  - `rng_bit_generator` — bool or a collection of random algorithm names; default = the adapter's `Capabilities.rng_bit_generator` (per-call override of the native `stablehlo.rng_bit_generator` capability).
  - `eigh_algorithm` — `"jacobi"` | `"jacobi_batched"`, case-insensitive, whitespace-stripped, default `"jacobi_batched"` (all mutually disjoint rotations of one odd-even round-robin round per `stablehlo.while` iteration vs `jacobi`'s single rotation per iteration, which is the plain sequential composition; batched is 65–74× faster at n=100 and 4–5.7× at n=10).
  - `split_reduction` — bool, default `True`: two-stage split reductions for rank-0-result reductions (`False` = the byte-identical single-stage text; measured 7.1–8.1× on those ops).
  - `sort_emission` — `"pair"` | `"count"` | `"auto"`, default = `CompilerBackend.default_sort_emission` (`"pair"` base, `"auto"` on iree, upgraded to `"count"` for cuda targets).
  - `while_init_rewrite` — bool, default `True`.
  - `dot_precision` — `"DEFAULT"` | `"HIGH"` | `"HIGHEST"`, default `"DEFAULT"` (no `precision_config`, byte-unchanged export); only `"HIGHEST"` disables XLA/ROCm's TF32-class fp32 `dot`.
- **Three Writer sub-knobs are `stablehlo.export`-ONLY** — not forwarded by `_exporter_options`, in no adapter's `KNOWN_OPTIONS`, and with no `ETL_*` row, so they are passed directly to `stablehlo.export(graph, options=...)`: `eigh_early_exit` (bool, default `False`; llvm-cpu-only convergence early exit), `split_reduction_threshold` (int ≥ 2, default 1024 — the `total_reduced` gate), `split_reduction_non_exact` (bool, default `False` — opts float `sum`/`prod`/`mean` into splitting, which reassociates the accumulation).
- **Backend defaults are minimal, documented, and OVERRIDABLE** — a user flag with the same NAME as an etl default drops the default (never both). iree keeps exactly `--iree-input-demote-f64-to-f32=false` (always) and `--iree-llvmcpu-target-cpu=generic` + `--iree-llvmcpu-link-embedded=false` (llvm-cpu only), and forces no process-global runtime flag (iree's own stream-ordered `--cuda_async_allocations=true` default stands; any loader/HAL flag is overridable per load via `iree_runtime_args` or `IREE_PY_RUNTIME_FLAGS`); a small DENY list is rejected with actionable reasons — `--iree-hal-target-backends` (use `target_backends`), `--iree-input-type` (StableHLO is always the input), `--iree-vm-bytecode-module-output-format` (the adapter requires the default VM flatbuffer output). The numpy reference backend documents-ignores unknown options. Per-adapter details: `./backends/adapters/CONTEXT.md`; framework contract: `./backends/CONTEXT.md`.

## Device kinds (binding)

Accepted `core.Device` kinds: `"cpu"` (always available, host memory), `"cuda"`, `"rocm"` (canonical AMD spelling; `"hip"` is an accepted equivalent alias, preserved as spelled), and `"vulkan"` (the IREE Vulkan/SPIR-V HAL — served by the iree adapter only; numpy/xla/tvm do not accept it and raise an explicit `BackendError`).
`Device(kind, index)` indices are PER-KIND ENUMERATION indices, not IREE HAL device ids: for cuda/rocm/hip the adapter maps `index` → the HAL's 1-BASED `device_id = index + 1`, while vulkan HAL device ids are QUERIED PER-PROCESS UUID HASHES, so the adapter maps `Device("vulkan", index)` → `query_available_devices()[index]` and creates the device from that info dict — a vulkan index has no ordinal meaning, and an out-of-range index raises an explicit error naming the requested index and the enumerated count.
One HAL device is cached per `(kind, index, runtime_args)` in a THREAD-LOCAL adapter cache shared by `load()` and the placement provider (HAL devices are thread-affine; repeated device creation is slow and leaks).
Compile spelling: a `"vulkan"` device on an iree-family backend infers `target_backends=["vulkan-spirv"]` (there is NO `--iree-hal-vulkan-target`; the optional SPIR-V profile knob is the `vulkan_target` compile option / a raw `--iree-vulkan-target=<profile>`); the artifact label for that target is `"vulkan"`, and a vulkan device only runs an artifact compiled for `vulkan-spirv` (mismatch → explicit `BackendError`, never a silent recompile).
Staging stays honest and kind-neutral: vulkan runs are DEVICE-RESIDENT exactly like cuda/rocm — outputs wrap `IreeDevicePayload` on `Device("vulkan", N)` and are never auto-copied, host inputs are rejected at the run boundary, `.numpy()` on a vulkan output raises with the explicit `.to(cpu)` remedy, and same-device inputs pass through with zero host round-trips.
`Tensor.to(Device("vulkan", N))` goes through a vulkan device-transfer provider the iree adapter registers in BOTH the per-backend and the flat DEFAULT slot; vulkan deliberately does NOT use the CUDA pinned/DMA staging tier (its ordering guarantee is a CUDA-driver property, unverified elsewhere) and takes the plain `asdevicearray` host→device copy instead.
`etl.devices("vulkan")` enumerates the IREE Vulkan HAL devices (lazy iree import; returns `[]` — never raises, never invents a device — when iree is absent, the driver cannot initialize, or no device is visible).
`etl.devices()` (kind `None`) deliberately lists `cpu + cuda + rocm` only: enumerating vulkan would instantiate the IREE Vulkan runtime and the system Vulkan loader, and on a software-Vulkan host it would report a CPU rasterizer as an accelerator — ask for `devices("vulkan")` explicitly.
Software-Vulkan hosts: IREE 3.11 hard-codes a device-NAME denylist that hides Mesa lavapipe (`llvmpipe…`) with no env override, so a lavapipe-only host enumerates nothing unless `VK_ICD_FILENAMES` selects a differently-named ICD — recipe, the default-profile budget and this host's GPU-Vulkan verdict: `./backends/adapters/CONTEXT.md` + `../bench_logs/vulkan_findings.md`.

## Value model (owned by `core`)

- `etl.TensorSpec(shape, dtype, device=None, name=None)`; `etl.dim(name_or_int)` → `Dim`; `etl.dtype(obj)`; dtype constants `etl.float16/float32/float64/int8/int16/int32/int64/uint8/uint16/uint32/uint64/bool_/complex64/complex128` (numpy dtype objects; `bool_` avoids shadowing the builtin).
- Concrete creators `etl.tensor(data, dtype=None, device=None)`, `etl.zeros/ones/full/empty(shape, dtype=...)`, `etl.from_numpy(array)`, `etl.from_dlpack(capsule_or_tensor)` are **host-only**: they produce ndarray-backed tensors on `Device("cpu", 0)`, so `device=` accepts only `None`/`Device("cpu", 0)` (anything else → creator-naming `DeviceError`); placing data elsewhere is the explicit post-creation `t.to(device)`.
- `etl.constant(tensor) -> SymbolicTensor` — graph-time only, snapshots data, warns above `ETL_LARGE_CONSTANT_BYTES` (default 1 MiB). **Snapshots HOST data only**: a non-cpu tensor raises `DeviceError` (no implicit D2H — `t.to(core.Device("cpu", 0))` first). Owned by `ops`; `core` provides the `register_constant_builder` hook `ops` populates.
- Devices: `etl.devices(kind=None) -> list[Device]`, `etl.split_tensor(tensor, axis, devices)`, `etl.replicate_tensor(tensor, devices)` — the latter two are **v1 host-only data preparation** (source ndarray-backed on `Device("cpu", 0)`, every target `Device("cpu", 0)`; anything else → `DeviceError`).

## Tensor ops (owned by `ops`; SymbolicTensor-in/SymbolicTensor-out; Python scalars auto-promote to scalar constants; concrete `Tensor` args raise `TraceError`)

`add, subtract, multiply, divide, power, remainder, maximum, minimum, abs, negate, square, sqrt, exp, log, log1p, sin, cos, tan, tanh, sigmoid, relu, gelu, erf, sign, bitwise_and/or/xor/left_shift/right_shift, logical_and/or/not, cast, equal, not_equal, less, less_equal, greater, greater_equal, select, broadcast, reshape, transpose, slice, gather, scatter, concatenate, pad, reduce_sum, reduce_max, reduce_min, reduce_mean, reduce_prod, sum, max, min, mean, prod, argmax, argmin, dot, conv, tril, triu, cumsum, solve, stop_gradient, runtime_call(callback, *operands, result=TensorSpec...), external_call(name, *operands, result=TensorSpec...)`

`sort, argsort, topk, tile, stack, flip, roll, clamp, diag, isnan, nan_to_num, eye, linspace, matmul, cumprod` (sorting: sort/argsort/topk · structural: tile/stack/flip/roll/diag · numeric: clamp/isnan/nan_to_num · creation: eye/linspace · linalg: matmul/cumprod — design notes in `./ops/CONTEXT.md`)

`eigh, cholesky, qr, matrix_rank, svd, matrix_exp` (linalg factorizations, numpy `linalg` semantics; eigh/qr/svd are multi-result tuple ops; cholesky is lower-triangular, non-PD raises at runtime)

**Control flow** (owned by `trace`): `etl.cond(pred, true_fn, false_fn, *operands)`, `etl.while_loop(cond_fn, body_fn, init)`, `etl.scan(f, init, xs, length=None)` — branch/body functions are traced into IR regions.

**Transforms** (owned by `transforms`, graph→graph): `etl.vectorize(graph, axes) -> Graph` (traced Graph only — a bare fn cannot yield a Graph; `TypeError` directs to `etl.vmap`), `etl.vmap(fn_or_graph, in_axes=0, out_axes=0)`, `etl.grad(fn_or_graph, argnums=None)`, `etl.jvp(fn_or_graph, tangents)`, `etl.vjp(fn_or_graph, cotangents=None)` — with a fn/Defn input these return a `TransformCallable` `(*specs) -> Graph` (transforms never execute); with a Graph input they return a `Graph`. `vjp` cotangents default `None` = scalar-one (single scalar output only). Unsupported ops (no rule) raise `TransformError` — never a silent fallback. v1 restrictions (`TransformError`): non-zero `in_axes`/`out_axes` entries (mapped axes must be leading); vectorizing control-flow (`cond`/`while_loop`/`scan`) regions.

**Distributed** (owned by `dist`): `etl.dist.group(name, ranks) -> Group`, `etl.dist.all_reduce/all_gather/reduce_scatter/all_to_all/broadcast/collective_permute(tensor, ..., group=Group)`, graph scalars `etl.dist.rank()`, `etl.dist.world_size()`.

**Sparse tensors** (owned by `sparse`, numpy-backend-only in v1): value model `SparseTensor`, `CSRTensor`, `CSCTensor`, `SparseTensorSpec` (+ `SparseTensorSpec.from_concrete`, the derive-spec entry used by `etl.evaluate`), `is_sparse`; creators `coo(indices, values, shape)`, `csr(indptr, indices, values, shape)`, `csc(...)`, `from_dense(dense)` (polymorphic: concrete → eager validated + canonical-form checked; symbolic → in-graph assembly via `from_parts`, `sparse_from_dense` op); converters `to_dense`/`to_csr`/`to_csc`/`to_coo` (polymorphic: concrete → eager, symbolic → graph op); ops `add`, `subtract`, `multiply`, `multiply_dense`, `negate`, `sum` (alias `reduce_sum`, dense result), `transpose`, `reshape`, `concatenate`, `matmul` (sparse@dense and dense@sparse; sparse@sparse → `TraceError` v1 deferral). Pytree contract: ONE registered base class, children = tensor leaves + `dense_shape` ints + `np.dtype` + format string as static leaves, polymorphic unflatten (first child kind selects spec/symbolic/concrete rebuild). v1 deferrals (explicit errors, never silent): no sparse constant, no sparse@sparse, compiler backends defer with an explicit `BackendError` (densify with `etl.sparse.to_dense`), whole-sparse `bind`, `concatenate`/`csc` vjp `TransformError`s. Full surface: `./sparse/CONTEXT.md`.

**Random** (owned by `random`; `etl/random.py` re-exports the frontend in `etl/ops/random.py`): key-based functional RNG as pure graph ops — `key(seed, algorithm="splitmix64")`, `split(key) -> (key_a, key_b)`, `split_n(key, n) -> tuple`, `uniform(key, shape, low=0.0, high=1.0, dtype=float32)`, `normal(key, shape, mean=0.0, std=1.0, dtype=float32)`, `randint(key, shape, low, high, dtype=int32)`, `permutation(key, n, dtype=int32)`, `multinomial(key, input, num_samples)` (int32 output).
**Multi-algorithm framework (binding):** `key()`'s `algorithm` accepts a validated string or an `Algorithm` enum member (`SPLITMIX64`/`THREEFRY2X32`/`PHILOX4X32_10`, `.value` = canonical names); the canonical constants (`ALGORITHMS`, `DEFAULT_ALGORITHM`, `validate_algorithm`, `algorithm_key_type`) live in `etl/ir/op_defs/random.py` (`ALGORITHMS` and `Algorithm` are re-exported at `etl.random`; no duplicated literals). Every other random function takes NO algorithm param — it infers the algorithm from the key operand's static shape/dtype at trace time and stamps it into the op's `algorithm` attribute (all 6 random OpDefs carry it, default `"splitmix64"`); an unknown algorithm → `ValueError`, a key matching no form → `ShapeError`/`DTypeError` naming the three accepted forms.
Binding design decisions:
1. **Shape/dtype ARE the static algorithm tag** (JAX-style): splitmix64 → rank-0 int64 (`key(seed)` masks to 64 bits); threefry2x32 → `(2,)` int32; philox4x32_10 → `(4,)` int32. `key(seed, algorithm=...)` derives the words via deterministic SplitMix64 mixing (formula in the `etl/ops/random.py` docstring), identical inside and outside a trace.
2. **Deterministic and stateless**: same key + same operands ⇒ BIT-IDENTICAL values, repeatable across separate `run`/`evaluate` calls.
3. **Ops never consume/mutate a key** — call `split`/`split_n` for independent keys (two ops sharing one key are correlated by construction).
4. **Streams**: SplitMix64 seeded with `key ^ SALT` — fixed per-op salts (hex digits of pi) so op kinds sharing one key draw decorrelated streams; `split`/`split_n` are sugar over `random_key_mix` (salts 0 / golden gamma / `i*golden`); the counter-based algorithms fold the per-op salt into the key words and use counter `(p, 0)` per cipher call. The full word-stream contract (element↔flat-word mapping, per-width uniform scaling, Box–Muller pairs, randint/permutation/multinomial post-processing) is the bit-exactness reference in `etl/backends/numpy/kernels/random.py`.
5. **Dtypes & shapes**: uniform/normal → floating (default float32), randint/permutation → integer (default int32), multinomial → int32; `shape` accepts int/`Dim`/`DimExpr` (runtime-dynamic `None` rejected); `low`/`high`/`mean`/`std` may be Python scalars or symbolic tensors broadcastable against `shape`; `permutation` with a static int `n` traces to a static `(n,)` result, a symbolic rank-0 `n` to runtime-dynamic `(None,)`.
6. **Polymorphism**: `key()` is a polymorphic creator (concrete `Tensor` outside a trace — usable as an explicit graph input; Constant op inside); every other function is a graph op (`TraceError` outside a trace or for concrete `Tensor` operands).
7. **Coverage**: the numpy interpreter is the reference for ALL THREE algorithms (pure-numpy uint32 cipher kernels in `etl/backends/numpy/kernels/random.py`); 5 of the 6 ops (`random_key_mix`/`uniform`/`normal`/`randint`/`permutation`) export as v1 StableHLO with algorithm-aware lowering, `random_multinomial` defers with an explicit `BackendError`. `DEFAULT_ALGORITHM` is `splitmix64` (benchmark-driven — fastest on both CPU targets, tied on cuda, winning every ≥4M-element cuda cell; `threefry2x32` is the explicit choice for small-sample/GPU-heavy work; matrix in `etl/bench/rng_bench_results.md`). Lowering paths and the per-adapter `Capabilities.rng_bit_generator` sets: `./backends/stablehlo/CONTEXT.md`.

Transforms (`vmap`/`grad`/`jvp`/`vjp`) have no rules for random ops → `TransformError`. The 6 random OpDefs live in `etl/ir/op_defs/random.py`, category "random", effect "pure" — usable inside `cond`/`while_loop`/`scan` regions.

**Custom ops** (owned by `block`): `etl.block(name, inputs=None, outputs=None, attributes=None, effects=None, batching=None, portable=None)` — decorator/factory returning a callable `BlockOp`; `BlockOp.impl(backend_name)`; `BlockOp.batching_rule(fn)`; `BlockOp.jvp_rule/vjp_rule(fn)`. No rule + no safe policy + no portable decomposition ⇒ `TransformError`.

**Backends** (owned by `backends`): `etl.backends.Backend` (abstract: `name`, `capabilities`, `lower`, `compile`, `load`), `etl.backends.register/get(name)`, `etl.backends.numpy_backend` (default CPU interpreter), `etl.backends.stablehlo` (`export(graph|module) -> str` MLIR text). `etl.lower/compile/load` default to `numpy_backend`.

**Persistence** (owned by `persist`, used by pipeline types): `Graph.save/load`, `LoweredProgram.save/load/.text()`, `CompiledArtifact.save/load`, `Executable.save/load`, `etl.Cache` (explicit; `FileCache(directory)` in `persist`). Loading never silently re-traces/recompiles; incompatibility fails clearly.

**Namespace**: `etl.numpy` (alias `enp`) + `etl.numpy.linalg` — numpy-style graph API producing the same IR as `ops`.

**Structured I/O**: tuple/list/dict/namedtuple/dataclass supported everywhere (trace inputs, run outputs, bind); custom containers register via `etl.register_pytree_node`. **Pytree utilities** (owned by `core`, exported on `etl`): `tree_map(fn, *trees)`, `tree_leaves(tree)`, `tree_structure(tree)`, `tree_flatten(tree)`, `tree_unflatten(leaves, treespec)` — pure sugar over flatten/unflatten (no new semantics). Container edge behavior: `defaultdict`/`Counter` roundtrip (default_factory preserved when `None`/a class, else a clear `unflatten` error); unorderable dict keys, dataclass `InitVar`/`init=False` rebuilds, and `register_pytree_node(object, ...)` raise plain `TypeError`/`ValueError` with actionable messages. **Structure-mismatch diagnostics**: every structural mismatch (`tree_map`, `Graph.flatten_inputs`/`validate_inputs`, `run`/`bind`, transforms' axes/tangent trees) reports the first divergent pytree path with expected/got node descriptions (e.g. `first mismatch at pytree path [0]['z']: expected dict with keys ['a', 'b'], got list of length 3`) via the shared `core.first_mismatch_path`/`format_path` helpers; per-caller lead-in wording is preserved (tests match the substrings).

## Value-model details (binding)

- **Errors**: all public errors derive from `ETLError` (in `core`): `TraceError`, `ShapeError`, `TransformError`, `BackendError`, `PersistenceError`, `DeviceError`, `DTypeError`, `VerificationError`, `BlockError`. No API silently swallows or works around errors; messages include the source location (`model.py:83`) whenever a graph location exists.
- **Shapes**: `Dim(name)` symbolic; `DimExpr` supports `+ - * // % min max` over dims/ints; `TensorSpec.shape` = tuple of `Dim|DimExpr|int|None` (`None` = runtime-dynamic, unchecked). Rank is always known at trace time. Shape inference is `ir`/`ops`'s job via `DimExpr` arithmetic.
- **`Tensor`** — a local physical tensor whose `device` is always physically true. (a) ndarray-backed (v1 default): the data IS host memory, so `device` is always `Device("cpu", 0)` — constructing one with any other `device=` raises `DeviceError`. (b) device-payload-backed: `data` is the payload object and `device` is the payload's device (an explicit `device=` must agree with it). **Host access is explicit**: `.numpy()` on ndarray-backed data returns the same array (zero-copy); on a cpu-kind payload it materializes a lazy FRESH host copy per call; on a non-cpu payload it raises `DeviceError` — there is no implicit device-to-host transfer (`t.to(core.Device("cpu", 0)).numpy()` is the explicit readback). `__dlpack__`/`__dlpack_device__` are zero-copy for host data; on device payloads they raise kind-aware `DeviceError`s (cpu-kind: "`.numpy()` first"; non-cpu-kind: "transfer via `t.to(...)` first"). `__eq__` is metadata-only whenever a payload is involved. **`Tensor.to(device)` is the ONLY transfer API**: equal device → `self` (no copy); `to(cpu)` on a payload = the explicit D2H fresh host copy; `to(non-cpu)` consults the device-transfer provider registry for that kind (per-backend slots filled by each adapter's `register()` under its own name, plus the legacy flat DEFAULT slot where `etl.backends` installs the lazy iree cuda thunk — vulkan has no thunk, the iree adapter's `register()` fills BOTH its per-backend and the flat slot for it; the owning backend's slot wins, then the flat default; no provider for the kind → `DeviceError`); direct payload→non-cpu copies are not implemented in v1 (`DeviceError` suggesting the two-hop `t.to(cpu).to(target)`). Mutable `data` access is documented as unsupported for graph constants.
- **Run boundary (no implicit device↔host transfers)**: `etl.run`/`etl.bind` reject any tensor leaf whose `device` differs from the executable's device with a `DeviceError` naming the input tree path, both devices, "no implicit device", and `t.to(` — BEFORE backend dispatch. A non-cpu executable therefore rejects host numpy inputs and raw ndarrays: host inputs must be explicitly placed (`x.to(Device("cuda", 0))`, `x.to(Device("vulkan", 0))`, …). Run outputs stay device-resident (never auto-copied); read back via `t.to(cpu).numpy()`. llvm-cpu runs keep feeding/reading host data (their tensors are cpu:0).
- **`SymbolicTensor`**: fields `value` (ir.Value), `dtype`, `shape` (tuple of `DimExpr|int`), `location`; SSA identity = `value.id`. Must NOT define `numpy`, `data_ptr`, `__dlpack__`, `__array__`.
- **`Graph` trace semantics**: parameters become `Function` block args; static Python values specialize and are recorded in `static_values` (run validates them); a closure-captured `Tensor` used in ops → `TraceError` ("make it an explicit input or use etl.constant"); `etl.constant` creates a Constant op and warns above `ETL_LARGE_CONSTANT_BYTES`.
- **Staged sugar rules**: `etl.build`/`etl.evaluate`/`etl.build_cached` docstrings must state their exact expansion; no other composition APIs exist in core.

## Serialization contract (binding)

Formats are versioned via constants (`ETL_FORMAT_VERSION`). Artifacts are self-describing: backend name/version, target, input/output signature (TreeSpec + specs), static values, required custom ops, IR format version. `Graph.save` → `.etlgraph` (portable JSON container); `LoweredProgram` numpy → serialized program; stablehlo → `.mlir` text; `CompiledArtifact` → `.etlartifact`; `Executable.save` → backend-dependent (numpy saves the artifact plus an explicit note that it is reconstructed at load). Loading with a mismatched backend/device/ABI → `PersistenceError`, never a silent recompile.

## etl.io — explicit async host-data IO (user-facing module)

`etl.io` (module `etl/io.py`; stdlib + `etl.core` imports ONLY) is explicit copy-queue sugar over `Tensor.to`: it schedules the SAME explicit transfers `Tensor.to` performs synchronously onto a background worker thread, so they run off the calling thread. No hidden staging and no overlap guarantees beyond caller-relative asynchrony: ONE process-global FIFO daemon worker thread (lazily started at the first submission) executes every scheduled copy strictly in issue order — a v1 limitation (true same-device overlap needs runtime async-engine support; see Known Issue #12 in `./backends/adapters/CONTEXT.md`). The worker never dies and never raises: per-copy failures are stored on the handle and re-raised by every `wait()`/`result()`/`wait_all()`.
- `prefetch(host_tensor, device) -> AsyncCopy` — host→device, run through the registered device-transfer provider; the source must be an ndarray-backed `core.Tensor` on `Device("cpu", 0)` (a raw ndarray → `TypeError` telling you to wrap it; a payload-backed host tensor, or a source already at the target, → `DeviceError`; a non-`core.Device` target → `TypeError`).
- `sink(device_tensor) -> AsyncCopy` — device→host, via the payload host-copy path (an ndarray-backed source, or a cpu-kind payload, → `DeviceError` pointing at `t.numpy()` / "no download needed").
- class `AsyncCopy` — `.device` (the target for prefetch, the source for sink), `.direction` (exactly `"host_to_device"` or `"device_to_host"`), `.done` (non-blocking poll), `.wait(timeout=None)` (blocks until the copy finishes and re-raises any stored failure VERBATIM on every call; a timeout raises `TimeoutError` and NEVER cancels the copy — wait again to retry), `.result(timeout=None)` (= `wait()` + the copied tensor). No destructor: GC never auto-waits, and a dropped handle's copy completes independently.
- `wait_all(timeout=None)` — waits for every copy outstanding at call time in issue order, raising the first stored failure.
Schedule-time validation is synchronous on the calling thread; runtime failures surface verbatim at `wait()`/`result()`/`wait_all()`. Re-entry guards: scheduling or waiting from the worker thread would deadlock, so `prefetch()`/`sink()`/`AsyncCopy.wait()`/`wait_all()` there raise `RuntimeError`. Non-cpu-kind copies trigger a lazy, best-effort, one-time CUDA/ROCm primary-context bootstrap on the worker (a throwaway iree HAL device with the adapter's exact 1-based `device_id = index + 1` mapping, on the iree DRIVER name — `rocm`/`hip` → `hip`, else the kind as-is; kept alive in `_bootstrap_devices`; every bootstrap failure is swallowed so it can never mask the copy's own error). Numpy-only environments never import iree. The `atexit` hook drains in-flight copies best-effort and stops the worker cleanly; interpreter exit never blocks.

## Memoized build sugar (etl.build_cache)

`etl.build_cached(fn, *specs, backend=None, device=None, cache=None, **options) -> Executable` (module `etl/build_cache.py`) is documented shorthand for a MEMOIZED `build` — no other behavior: the exact `trace → lower → compile → load` composition runs at most once per distinct cache key, and a hit returns the SAME fully loaded `Executable` with zero pipeline work. Purpose: a true-JIT-style helper for meta-level loops (NAS / genetic programming / genetic algorithms) whose outer loop produces a DIFFERENT static program each iteration (e.g. a random expression tree encoded as a tensor), decodes it, traces + compiles a fresh graph at runtime, and runs it in an inner loop; the returned executable is a NORMAL one (same-device device-resident run loops work unchanged) and static args stay in the run signature, validated at the run boundary.
- **Cache key** — computed BEFORE any tracing as the tagged tuple `(("fn", id(fn)), ("specs", specs), ("backend", resolved_backend.name), ("device", resolved_device), ("options", _canonicalize_options(resolved_options)))`; the entry pins `fn` as its keepalive so `id(fn)` can never alias a later object. The full specs tree (structure AND static content) is encoded via `persist.encode_value`, so each distinct static "program" value = a distinct graph = a distinct entry, while a runtime tensor in a program slot is an ordinary graph input keyed ONCE on its `TensorSpec` — never specialized per value. Options are canonicalized order-insensitively so semantically-equal option sets key identically; unset `backend`/`device` resolve exactly as in `build` and participate in the key. Process-env knobs the compiler stages read themselves (`ETL_OPT_LEVEL`, `ETL_EIGH_ALGORITHM`, `ETL_SPLIT_REDUCTION`, `ETL_IREE_*`, `ETL_XLA_*`, `ETL_TVM_*`) are NOT part of the key — clear the cache (or pass a fresh `CompileCache`) when changing them. An unencodable static leaf raises a pre-cache `TypeError` naming the key component path (e.g. `specs[2]`, `specs[3]['w']`) and its type, pointing at `persist.encode_value`'s coverage and at plain `etl.build` for unkeyable calls.
- **Failure bookkeeping (binding)** — fn validation, backend/device resolution, cache-type checks and encodability all fire BEFORE any cache access; env-resolution failures count NO miss and insert nothing; post-key stage failures count a miss, insert nothing, and re-raise untouched. Only a fully loaded Executable is ever inserted — never a cached failure, never an eager fallback.
- class `CompileCache(Cache)` — in-memory thread-safe LRU (default `maxsize=128`; a non-positive or non-int `maxsize` → `ValueError`): `get`/`put`/`contains`/`clear`/`get_or_compute` plus public `hits`/`misses` (`clear` resets them); the compute function runs OUTSIDE the lock and the first insert wins on races; LRU eviction pops the oldest entry. In-memory only (executables hold device handles/vmfb/compiled code — never persisted). `cache=None` selects the module-level default (a fresh instance isolates callers); there is deliberately NO `cache=False` escape — plain `etl.build` is the no-cache path. `cache` must be a `CompileCache` or `None` and `fn` a callable/`@etl.defn` function — a `Graph` argument raises a `TypeError` directing to the explicit `lower`/`compile`/`load` pipeline.

## External kernels (binding interface contract)

A kernel-agnostic escape hatch for plugging custom (e.g. triton) kernels into `defn` graphs to bypass compiler weaknesses. **No triton (or any kernel) code lives in etl** — the mechanism only declares, registers, and dispatches; the kernel itself is written against this interface in a different repo.

**1. Graph side — `etl.external_call(name, *operands, result=...)`** (frontend op in `etl/ops/external.py`, IR op `external_call`, effect `callback`):
- `name`: non-empty `str`, the STATIC kernel identifier — it specializes the graph exactly like any static parameter. Registration is a RUN-TIME concern: tracing does NOT require the kernel to be registered; running does.
- `*operands`: `SymbolicTensor` or Python scalars (auto-promoted to 0-d constants). No static (Python) parameters in v1.
- `result`: a `core.TensorSpec` (single output) or a non-empty tuple/list of them — the graph's DECLARED output contract. Specs may contain symbolic dims (resolved against runtime input bindings) or `None` (runtime-dynamic, unchecked). Returns a `SymbolicTensor` or a tuple of them.
- Errors: `TraceError` outside a trace / for concrete `Tensor` operands; `TypeError` for a bad `name` or `result`. Works inside `cond`/`while_loop`/`scan` bodies on the numpy backend.

**2. Run-time side — the registry (`etl/external.py`, stdlib-only module-level imports)**:
- `register_external_kernel(name, callable_, backend=None, device_resident=False) -> ExternalKernel` — process-global, PER-BACKEND registry: each name maps to a dict of backend slots (`None` = the DEFAULT slot, used by every backend with no exact slot). Registration OVERWRITES the slot's callable AND mode (last wins — enables hot-reload). `device_resident=True` (explicit opt-in) registers a DEVICE kernel and REQUIRES an explicit per-backend slot (`TypeError` with `backend=None`, because the default slot is also dispatched by the numpy backend, which passes host numpy arrays); in v1 only the iree adapter consumes the flag. `TypeError` for a non-str/empty name, a name containing the reserved suffix `_ETL_BATCH_SUFFIX` (`"__etl_batched"`, reserved for `batch_variant`'s internal registrations — register the base name instead), a non-callable kernel, a non-bool `device_resident`, or a non-None/non-str backend.
- class `ExternalKernel` (handle; attr `name`; every method returns `fn` so it is decorator-friendly): `impl(backend, fn=None, device_resident=False)` per-backend registration; `portable(fn)` (= `register_portable`); `batching_rule(fn)`/`vjp_rule(fn)`/`jvp_rule(fn)` registering transform rules under `external:<name>`.
- **Declarative batched-variant sugar.** `batch_variant(fn=None, *, backend=None, device_resident=False)` registers `fn` under the DERIVED name `f"{name}__etl_batched"` (same backend-slot/`device_resident` semantics as `impl`) and installs the shared pass-through batching rule under BOTH `external:<name>` and `external:<derived>` (the derived key is what a nested-vmap second pass re-resolves). `batch_invariant()` (no callable; returns `self`) declares the kernel invariant to extra leading mapped axes and installs the same rule under `external:<name>` only.
- `register_portable(name, fn)` — the OPTIONAL graph decomposition; `fn` MUST be an `@etl.defn` function (the `__etl_defn__` marker is validated at registration; the reserved suffix is rejected). Traced LAZILY when a fallback rule fires. It ALSO pre-registers fallback rules under `external:<name>`: the vjp fallback always, the batching fallback only when no explicit batching rule exists yet (explicit rules win; later registrations overwrite — last wins). `get_portable(name)` returns it or `None`. `unregister_external_kernel(name)` removes all kernel slots, the portable, and their derived form; `KeyError` if neither the name nor its derived form was ever registered; it does NOT touch the `transforms` registries (rules are graph-level and survive). Slot resolution (both lookups, exact backend slot → default slot → `None`) is specified with the exports in "Cross-module contracts".
- **Callable signature (binding). HOST mode (default)**: `fn(*np_arrays) -> ndarray | core.Tensor | tuple/list of them`, whose count/dtype/shape MUST match the specs declared by the invoking `external_call` (validated: count → `BackendError`, dtype exactly → `BackendError`, shape → `ShapeError`; anything else → `BackendError`, never a guess). **DEVICE mode** (`device_resident=True`, iree only in v1): `fn(*tensors)` receives the boundary's device-resident `core.Tensor`s (`.data` is an `IreeDevicePayload`) DIRECTLY (never `.numpy()`-staged) and may return `core.Tensor`s with device payloads, duck-typed payloads (`shape`/`dtype`/`device`/`to_host()`), raw iree `DeviceArray`s, numpy arrays, or mixes; results are validated METADATA-ONLY (count/dtype/shape, same canonical wording — device results are NEVER host-copied). Both modes share ONE validation implementation (`etl/backends/external_validate.py`).

**Execution semantics (v1)**: the numpy interpreter dispatches by name at the op's position in block op order (effect `callback` anchors ordering; no async execution) via `get_external_kernel_entry(name, "numpy")`; a resolved slot registered `device_resident=True` raises an explicit `BackendError` there (the numpy backend passes host arrays and cannot honor device-resident semantics — register a host-mode numpy slot or run on a compiler backend). Kernel outputs are wrapped in `core.Tensor` and consumed by downstream ops normally. **External-kernel boundaries are the ONLY sanctioned host↔device staging points** — plain runs never stage (the run boundary rejects device-mismatched inputs). An unknown name at run time → `BackendError` naming the kernel and pointing at `register_external_kernel`.

**Transforms**: rules live under the namespaced key `external:<name>` in transforms' public registries and are looked up automatically. WITHOUT explicit rules, a registered PORTABLE makes `vmap`/`vectorize`/`grad`/`jvp`/`vjp` work through the pre-registered decomposition fallbacks (`etl/external_rules.py`): batching re-traces the portable over the batched operand values and tracks `MappedAxes` through the inlined ops; vjp re-traces the portable and runs a LOCAL reverse sweep over only the inlined ops, seeding cotangents on the post-inline result values, with nested `block_call`/`external_call` ops resolved through their own registry keys. Missing rule AND no portable → `TransformError` naming the op (never a silent fallback).
**Batched-variant rule semantics**: the shared pass-through batching rule rebuilds every mapped `external_call` op that resolves to the registered key, carrying name attribute `target_name` (unchanged for batch-invariant, the DERIVED name for batched-variant), with NO operand alignment/reshapes ever — the kernel receives the graph's batched operand stack AS-IS (including unmapped/0-d operands; mixed mapped counts are legal) and is invoked ONCE with it. Batch dims = the leading `k` dims of the first operand with the max mapped count (`k = 0` → an unchanged-shape rebuild); each result type gains `batch_dims + result shape`, the `"result_specs"` attr is re-encoded as the same tuple of `ir.ValueType`s (`ir.verify` requires exact equality), and result axes are `MappedAxes(tuple(range(k)))`. A batched-variant kernel implements the batched math itself; a batch-invariant kernel just treats the extra leading axes as ordinary axes.

**Persistence**: the registry is NEVER serialized — artifacts carry only the `name` string (`result_specs` round-trips through the standard ValueType wire encoding). `Graph.save`/`load` work; any process running a saved graph must re-register its kernels first. The numpy `compile()` records external kernel names in `required_custom_ops` alongside block names (self-description only — kernels resolve LAZILY at run time, never a load-time requirement; block names are still load-time validated).

**Compiler backends**: the iree adapter declares `Capabilities.external_calls=True` and SPLITS the graph at `lower()` into segment programs + a kernel-call plan, then dispatches each boundary in the kernel's registered mode (host staging via the explicit `Tensor.to(cpu)` transfer, or zero-host-round-trip device dispatch) — full contract, mode-aware result-dim gates and payload interop in `./backends/CONTEXT.md`. Backends without host-dispatch (xla/tvm, `Capabilities.external_calls=False`) inline a registered portable with a `UserWarning`, else raise an explicit `BackendError` naming the op + backend and listing the options; the stablehlo exporter still defers direct export (`DEFERRED_OPS`).

Minimal usage:
```python
etl.register_external_kernel("relu_custom", my_kernel)   # default (host) slot
etl.register_external_kernel("relu_cuda", my_kernel, backend="iree", device_resident=True)

@etl.defn
def model(x, w):
    return etl.dot(etl.external_call("relu_custom", x,
                    result=etl.TensorSpec((N, D), etl.float32)), w)

etl.evaluate(model, x_np, w_np, backend="iree")   # llvm-cpu split + host dispatch
exe = etl.build(model, spec_x, spec_w, backend="iree", device=etl.Device("cuda", 0))
host = etl.run(exe, x_cuda, w_cuda)[0].to(etl.Device("cpu", 0)).numpy()  # explicit D2H
```

## Full-model forward (Llama / GPT-2 transformers) — readiness map

One-graph full transformer forward is feasible on **iree** (llvm-cpu/cuda/rocm); `xla` needs fully static shapes + `dot_precision="HIGHEST"` (TF32); **tvm cannot run it** (single-function/single-output, no `gather`/control flow).

- **Absent — must be composed:** `rsqrt` (use `divide(1.0, sqrt(x))` or `power(x, -0.5)`), `softmax`, `layer_norm`, `rms_norm`, `log_softmax`, `iota`, `einsum`, `silu`, `logistic`. Mask primitive is `etl.select(pred, a, b)` (`where` exists only as `etl.numpy.where`); index generation is `etl.arange` (Constant op, static bounds only). Canonical compositions: `ops/CONTEXT.md`.
- **`etl.gelu` is the exact erf form** (not HF's tanh approximation) — and `erf`/`gelu` are both exporter `DEFERRED_OPS`, so a GPT-2-style GELU FFN cannot be lowered on any compiler adapter; use the tanh-approx formula (`tanh`/`power` export) or stay on numpy. Llama SiLU is fine (`sigmoid` → `stablehlo.logistic`).
- **Also deferred** (`backends/stablehlo/ops.py`): `cumsum`, `cumprod`, `tril`, `triu`, `flip`, `roll`, `nan_to_num`, `diagonal`, `solve`, linalg factorizations, `runtime_call`/`external_call`/`block_call`, all `sparse_*`. Build causal masks from `arange` compares broadcast together — never an `(S,S)` `etl.constant` (`_constant_text` inlines the payload).
- **`gather` IS exportable** (single-axis; static operand + index SHAPES, runtime index VALUES) ⇒ `etl.gather(embed_table, ids, axis=0)` works on iree. `etl.slice` requires static lengths — there is no dynamic slice.
- **Batched `dot` works**: `(B,H,S,D) × (B,H,D,S)` with matched static batch dims emits one `dot_general`; contracting dims are fixed to lhs-last × rhs-second-last. Symbolic reshape / symbolic batch *broadcast* defer, so attention head reshapes need static shapes.
- **Weights**: pass `{"w1": TensorSpec((in, out), float32), ...}` as ONE positional defn arg (dict pytree; keys sorted, order-insensitive, no input-count limit). Cost ≈2–3.5 µs/leaf per `run` (400 leaves ≈ 1 ms), and non-cpu executables require pre-placed device tensors. Never `etl.constant` a weight (export inlines the payload).
- **Unmeasured**: compile-time / vmfb scaling for thousands of ops + 100+ inputs (largest validated graph ≈11 inputs). Capture weights inside `while` bodies rather than carrying them (iree `AffinityAnalysis` SEGV at ≥3–4 carries with `select`).

## Notes for agents

- Keep modules thin and single-purpose; files under ~1000 lines (split along declared boundaries instead).
- Shared capability goes to the lowest common ancestor module per the contracts above — do not duplicate (e.g. numpy kernels live ONLY in `backends/numpy`).
- `etl/__init__.py` re-exports this exact surface; when adding a public name, update `__init__.py` and this contract together.
- Keep this file to the API contract + routing table: new per-feature detail belongs in the owning child node's CONTEXT.md plus a routing-table row here.
- **`run`'s per-call host cost is leaf-driven, not graph-driven** — measured on MI300X/rocm with a 12-in/12-out step: per-IO leaf ≈2–3.5 µs, per-op ≈0, so cost tracks leaf count and never graph size (pytree nesting is irrelevant). `_prepare_flat_inputs` + `_unflatten_outputs` cost ≈24–31 µs and the backend invoke dominates the rest.
- **Both halves of that cost are plan-driven, and plans cache metadata only, never values** — `pipeline.py` caches per-leaf `(is_tensor, path tuple, spec dtype, spec shape, all-static flag, spec device)` plus a pre-sized output-leaf layout: an all-static shape check is one tuple compare, pytree path strings are built only on the failure branch, and `_unflatten_outputs` passes a backend's outputs through untouched when they are already `core.Tensor`s (wrapping/validation on the slow branch only). The iree/xla executables cache per-leaf input contracts + pre-sized output plans and validate in ONE pass (iree payload metadata reads the HAL buffer view; xla folds the device-resident payload/client checks into `_XlaRunPlan`). Every per-call dtype/shape/count/device comparison and every error message is unchanged — there is no skip-validation escape hatch.
- **Measured effect of that design at 12 in/12 out** (`etl.run`, warmup-excluded best-of-240; deltas are stable across sessions while absolute levels drift ~10 % on the shared MI300X VF, so compare deltas): iree/rocm −17.7 µs (−12.8 %), xla/rocm −7.2 µs (−6.0 %), iree llvm-cpu −16.5 µs (−17.1 %), numpy/cpu −0.9 µs (control — numpy's backend path is untouched and its pipeline share alone drops 33.8 → 28.1 µs); per-output slope iree 5.3 → 4.4 µs, xla 4.6 → 4.2 µs, llvm-cpu 3.8 → 2.7 µs.
- The full stage ladder, bare-metal bounds and the remaining levers (PJRT async execute events; `core.unflatten` ≈4.7 µs of the ≈5 µs unflatten) live in `./backends/adapters/CONTEXT.md` Known Issue 14; don't re-derive them.
