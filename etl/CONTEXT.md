# etl package — public API contract

## Intent

The `etl` package: an explicit, minimal tensor graph runtime. See root `../CONTEXT.md` for principles, value model, error strategy, and non-goals — all binding here. This file defines the **public API surface** and the **cross-module contracts** every submodule must honor.

## Public API surface (the contract — must exist, exact names)

**Staging & pipeline** (see also `pipeline.py`):
- `@etl.defn` → `Defn` (calling a `Defn` with concrete tensors must raise `TraceError` directing to `trace`/`evaluate`)
- `etl.trace(fn_or_defn, *specs) -> Graph` (accepts nested structures of `TensorSpec` + static values)
- `etl.lower(graph, backend=None, **options) -> LoweredProgram`
- `etl.compile(lowered, backend=None, **options) -> CompiledArtifact`
- `etl.load(artifact, backend=None, device=None) -> Executable`
- `etl.run(executable, *args) -> outputs` (structured inputs/outputs via TreeSpec; validates static fields)
- `etl.bind(obj, **bindings) -> BoundExecutable|callable` (pure argument-supply sugar; validates names/dtypes/shapes/devices; never alters the graph)
- `etl.build(fn, *specs, backend=None, device=None, **options) -> Executable` — documented shorthand for trace→lower→compile→load
- `etl.evaluate(fn, *args, backend=None, device=None, **options)` — documented shorthand: derive specs → build → run. Deriving a spec from a concrete tensor snapshots shape+dtype only.
- **`build`/`evaluate` env defaults** (process-wide defaulting; explicit kwargs ALWAYS win; env read lazily at call time): unset `backend` resolves from `ETL_BACKEND` (backend name, default `"numpy"` when unset/empty); unset `device` from `ETL_DEVICE` (`"kind[:index]"`, e.g. `"cpu"`/`"cuda:0"` — parsed to `core.Device`; malformed values raise `DeviceError` naming the variable and value); unset `target_backends` from `ETL_TARGET_BACKENDS` (comma-separated list) — otherwise an iree-family backend (name startswith `"iree"`) infers it from the resolved device: `cuda` → `["cuda"]`, `cpu` → `["llvm-cpu"]`. The explicit stage functions (`lower`/`compile`/`load`) keep their documented defaults. Implementation: `pipeline._resolve_backend_device` (also `_parse_env_device`); regression suite `tests/pipeline_env_defaults_test.py`.

## Backend options override (binding)

Design principle: *"we only took care of the graph, provide a clean pipeline, and everything else should be hack-able"* — etl must never hardcode compiler flags users cannot override (the round-4 `--cuda_async_allocations` bug: a hardcoded iree flag disabled the stream-ordered allocator and made every per-call result alloc/free a full device sync, 9.45 ms vs 0.10 ms per call).

- **Every pipeline stage accepts backend options**: `lower(graph, backend=..., **options)`, `compile(lowered, backend=..., **options)`, `load(artifact, backend=..., device=..., **options)`, `run(executable, *args, **options)`, and the `build`/`evaluate` sugar forward one options dict through all stages. Option keys are ADDITIVE (backward compatible — existing signatures keep working).
- **Option names are validated; values never are.** Each backend/executable declares `KNOWN_OPTIONS: dict[stage, frozenset[str]]`; a stage's options are validated against the UNION of all stages' sets (`etl.backends.options.validate_options`) — a key valid for any stage passes (accepted-and-ignored elsewhere, so `build`/`evaluate` can forward one dict), a key in no stage's set raises `core.BackendError` listing the per-stage known sets. Flag/option VALUES always pass through to the compiler — the compiler validates them (etl never parses compiler flags; the single exception is the etl-defined `opt_level`, below).
- **Precedence (binding): explicit kwarg > env var > etl default.** Per-backend option env vars (read lazily at call time, per call; empty/whitespace = unset; malformed → `core.BackendError` naming the variable and value), stage-scoped application, full table and parsers in `etl/pipeline_options.py`:

| Env var | Backend/stage | Option key | Value format |
|---|---|---|---|
| `ETL_IREE_COMPILE_ARGS` | iree / compile | `iree_compile_args` | whitespace-separated flag list (quotes NOT processed) |
| `ETL_IREE_RUNTIME_ARGS` | iree / load | `iree_runtime_args` | whitespace-separated flag list |
| `ETL_XLA_COMPILE_OPTIONS` | xla / compile | `xla_compile_options` | base64-encoded serialized `xla.CompileOptionsProto` bytes |
| `ETL_TVM_TARGET` | tvm / compile | `tvm_target` | plain string |
| `ETL_TVM_PASS_CONFIGS` | tvm / compile | `tvm_pass_configs` | JSON object |
| `ETL_OPT_LEVEL` | iree/tvm/xla / compile | `opt_level` | `'O0'`–`'O3'` (case-insensitive), `'0'`–`'3'`, or ints 0–3 (validated — etl-defined value) |
| `ETL_PJRT_PLUGIN`, `ETL_TARGET_BACKENDS`, `ETL_BACKEND`, `ETL_DEVICE` | (pre-existing) | `plugin_path`, `target_backends`, `backend`, `device` | as documented above |

- **`opt_level` — the first-class optimization-level option (the ONE etl-defined option).** Accepted values: `'O0'`–`'O3'` (case-insensitive), `'0'`–`'3'`, or the ints 0–3 — normalized to 0..3 by `etl.backends.options.normalize_opt_level`; it is the one option whose VALUE etl validates (a bad value raises a loud `core.BackendError` naming the option and the accepted forms; raw compiler flags remain pass-through). Per-backend translation: iree appends `--iree-opt-level=N` to its compile args; tvm sets the tvm build optimization level; xla sets the `xla.CompileOptionsProto` optimization-level field; the numpy backend accepts and documents-ignores it. Declared in the compiler adapters' compile-stage `KNOWN_OPTIONS` (the union rule lets `build`/`evaluate` forward it through all stages). Unset = unchanged current behavior. Conflict rule: an explicit raw flag with the same underlying name (e.g. `--iree-opt-level=N` in `iree_compile_args`, or an existing optimization-level field in `xla_compile_options`) WINS over the opt_level-derived value — never both. Env var `ETL_OPT_LEVEL` (backend-agnostic, applies to whichever compiler backend is in use; read lazily at call time; precedence explicit > env > default; malformed → `BackendError` naming the variable and value — parser `_parse_opt_level` in `etl/pipeline_options.py`). The `etl.bench` harness defaults compiler-backend builds to `opt_level="O3"` (numpy unaffected, user-overridable).

- **Backend defaults are minimal, documented, and OVERRIDABLE.** A user flag with the same NAME as an etl default drops the default (never both). iree keeps exactly: `--iree-input-demote-f64-to-f32=false` (always), `--iree-llvmcpu-target-cpu=generic` + `--iree-llvmcpu-link-embedded=false` (llvm-cpu only); no process-global runtime flag is forced — iree's own cuda `--cuda_async_allocations=true` (stream-ordered) default stands, and users may override any loader/HAL flag per load via `iree_runtime_args` or `IREE_PY_RUNTIME_FLAGS` (design decision, measured: see `etl/backends/adapters/CONTEXT.md`); a small DENY list (`--iree-hal-target-backends`, `--iree-input-type`, `--iree-vm-bytecode-module-output-format`) is rejected with actionable reasons (use `target_backends` / StableHLO is always the input / the adapter requires the default VM flatbuffer output). The numpy reference backend documents-ignores unknown options; the compiler adapters' run stage has no v1 options (non-empty → loud `BackendError`, by design). Per-adapter option details: `etl/backends/adapters/CONTEXT.md` ("Options override"); contract: `etl/backends/CONTEXT.md` ("Backend options override").

**Value model** (owned by `core`):
- `etl.TensorSpec(shape, dtype, device=None, name=None)`; `etl.dim(name_or_int)` → `Dim`; `etl.dtype(obj)`; dtype constants `etl.float16/float32/float64/int8/int16/int32/int64/uint8/uint16/uint32/uint64/bool_/complex64/complex128` (numpy dtype objects; `bool_` to avoid shadowing the builtin)
- Concrete creators: `etl.tensor(data, dtype=None, device=None)`, `etl.zeros/ones/full/empty(shape, dtype=...)`, `etl.from_numpy(array)`, `etl.from_dlpack(capsule_or_tensor)`
- `etl.constant(tensor) -> SymbolicTensor` — graph-time only, snapshots data, warns for large constants. **Owned by `ops`** (it builds a Constant op); `core` provides the `register_constant_builder` hook that `ops` populates.
- Devices: `etl.devices(kind=None) -> list[Device]`, `etl.split_tensor(tensor, axis, devices) -> list[Tensor]`, `etl.replicate_tensor(tensor, devices) -> list[Tensor]`

**Tensor ops** (owned by `ops`; SymbolicTensor-in/SymbolicTensor-out; Python scalars auto-promote to scalar constants; concrete `Tensor` args raise `TraceError`):
`add, subtract, multiply, divide, power, remainder, maximum, minimum, abs, negate, square, sqrt, exp, log, log1p, sin, cos, tan, tanh, sigmoid, relu, gelu, erf, sign, bitwise_and/or/xor/left_shift/right_shift, logical_and/or/not, cast, equal, not_equal, less, less_equal, greater, greater_equal, select, broadcast, reshape, transpose, slice, gather, scatter, concatenate, pad, reduce_sum, reduce_max, reduce_min, reduce_mean, reduce_prod, sum, max, min, mean, prod, argmax, argmin, dot, conv, tril, triu, cumsum, solve, stop_gradient, runtime_call(callback, *operands, result=TensorSpec...), external_call(name, *operands, result=TensorSpec...)`
`sort, argsort, topk, tile, stack, flip, roll, clamp, diag, isnan, nan_to_num, eye, linspace, matmul, cumprod` (15-op batch — sorting: sort/argsort/topk · structural: tile/stack/flip/roll/diag · numeric: clamp/isnan/nan_to_num · creation: eye/linspace · linalg: matmul/cumprod)
`eigh, cholesky, qr, matrix_rank, svd, matrix_exp` (batch-3b linalg factorizations — numpy `linalg` semantics; eigh/qr/svd multi-result tuple ops; cholesky lower-triangular, non-PD raises at runtime)

**Control flow** (owned by `trace`): `etl.cond(pred, true_fn, false_fn, *operands)`, `etl.while_loop(cond_fn, body_fn, init)`, `etl.scan(f, init, xs, length=None)` — branch/body functions are traced into IR regions.

**Transforms** (owned by `transforms`, graph→graph): `etl.vectorize(graph, axes) -> Graph` (traced Graph only — a bare fn cannot yield a Graph; `TypeError` directs to `etl.vmap`), `etl.vmap(fn_or_graph, in_axes=0, out_axes=0) -> callable|Graph`, `etl.grad(fn_or_graph, argnums=None)`, `etl.jvp(fn_or_graph, tangents)`, `etl.vjp(fn_or_graph, cotangents=None)` — with a fn/Defn input these return a `TransformCallable` `(*specs) -> Graph` (transforms never execute); with a Graph input they return a `Graph`. `vjp` cotangents default `None` = scalar-one (single scalar output only). Unsupported ops (no rule) raise `TransformError` — never silently fall back. v1 restrictions (TransformError): non-zero in_axes/out_axes entries (mapped axes must be leading); vectorizing control-flow (`cond`/`while_loop`/`scan`) regions.

**Distributed** (owned by `dist`): `etl.dist.group(name, ranks) -> Group`, `etl.dist.all_reduce/all_gather/reduce_scatter/all_to_all/broadcast/collective_permute(tensor, ..., group=Group)`, graph scalars `etl.dist.rank()`, `etl.dist.world_size()`.

**Sparse tensors** (owned by `sparse`, numpy-backend-only in v1): value model `SparseTensor`, `CSRTensor`, `CSCTensor`, `SparseTensorSpec` (+ `SparseTensorSpec.from_concrete(concrete) -> SparseTensorSpec`, the derive-spec entry used by `etl.evaluate`), `is_sparse`; creators `coo(indices, values, shape)`, `csr(indptr, indices, values, shape)`, `csc(...)`, `from_dense(dense)` (polymorphic: concrete → eager validated, canonical form checked; symbolic → in-graph assembly via `from_parts`, `sparse_from_dense` op); converters `to_dense`/`to_csr`/`to_csc`/`to_coo` (polymorphic: concrete → eager, symbolic → graph op); ops `add`, `subtract`, `multiply`, `multiply_dense`, `negate`, `sum` (alias `reduce_sum`, dense result), `transpose`, `reshape`, `concatenate`, `matmul` (sparse@dense and dense@sparse; sparse@sparse → `TraceError` v1 deferral). Pytree contract: ONE registered base class (`SparseTensor`), children = tensor leaves + `dense_shape` ints + `np.dtype` + format string as static leaves, polymorphic unflatten (first child kind selects spec/symbolic/concrete rebuild). v1 deferrals (explicit errors, never silent): no sparse constant, no sparse@sparse, compiler backends defer with explicit `BackendError` (densify with `etl.sparse.to_dense`), whole-sparse `bind`, `concatenate`/`csc` vjp `TransformError`s.

**Random** (owned by `random`; `etl/random.py` is a thin re-export of the frontend in `etl/ops/random.py`): key-based functional RNG as pure graph ops — `etl.random.key(seed, algorithm="splitmix64")`, `split(key) -> (key_a, key_b)`, `split_n(key, n) -> tuple`, `uniform(key, shape, low=0.0, high=1.0, dtype=float32)`, `normal(key, shape, mean=0.0, std=1.0, dtype=float32)`, `randint(key, shape, low, high, dtype=int32)`, `permutation(key, n, dtype=int32)`, `multinomial(key, input, num_samples)` (output int32). **Multi-algorithm framework (binding)**: `key()`'s `algorithm` param accepts plain validated strings or `Algorithm` enum members (`etl.random.Algorithm` — SPLITMIX64/THREEFRY2X32/PHILOX4X32_10, `.value` = canonical names); canonical constants (`ALGORITHMS = ("splitmix64", "threefry2x32", "philox4x32_10")`, `DEFAULT_ALGORITHM`, `validate_algorithm`, `algorithm_key_type`) live in `etl/ir/op_defs/random.py` (re-exported at `etl.random` — no duplicated literals). All other random functions take NO algorithm param: they infer it from the key operand's static shape/dtype at trace time and stamp it into the op's `algorithm` attribute (all 6 random OpDefs carry it, ATTR_STR default `"splitmix64"`); unknown algorithm → `ValueError`; a key matching no form → `ShapeError`/`DTypeError` naming the three accepted forms. Design decisions (binding): **(1) Key representations — shape/dtype ARE the static algorithm tag** (JAX-style): splitmix64 → rank-0 int64 (64-bit state, two's complement; `key(seed)` masks to 64 bits); threefry2x32 → shape `(2,)` int32 (two key words); philox4x32_10 → shape `(4,)` int32 (four key words); `key(seed, algorithm=...)` derives the new-algorithm key words from the seed via deterministic SplitMix64 mixing (formula in the `etl/ops/random.py` docstring; identical inside/outside a trace). The same key + same operands ⇒ BIT-IDENTICAL values, repeatable across separate `run`/`evaluate` calls. **(2) Stream derivation** — SplitMix64 seeded with `key ^ SALT`; fixed per-op salts (hex digits of pi) so different op kinds sharing one key draw decorrelated streams; `split`/`split_n` are sugar over the `random_key_mix` op (salts 0 / golden gamma / `i*golden`); for the counter-based algorithms the 64-bit per-op salt folds into the KEY words (`salt_lo = salt & 0xFFFFFFFF`, `salt_hi = salt >> 32`; threefry `key' = (k0^salt_lo, k1^salt_hi)`, philox `key' = (k0^salt_lo, k1^salt_hi, k2^salt_lo, k3^salt_hi)`) and cipher call/block p uses counter `(p, 0)`; the full word-stream contract (element↔flat-word mapping, per-width uniform scaling — 64-bit `(w >> 11) * 2^-53` vs 32-bit `w * 2^-32` — Box–Muller pairs, randint/permutation/multinomial post-processing) is documented in `etl/backends/numpy/kernels/random.py` and is the bit-exactness reference for the StableHLO lowering. **(3) Key consumption** — ops NEVER consume/mutate a key (call `split`/`split_n` for independent keys; two ops sharing one key are correlated by construction). **(4) dtype rules** — uniform/normal → floating (default float32); randint/permutation → integer (default int32); multinomial output int32. **(5) Shapes** — `shape` accepts int / `Dim` / `DimExpr` (runtime-dynamic `None` rejected); low/high/mean/std may be Python scalars OR symbolic tensors broadcastable against shape (result shape = broadcast); `permutation` with a static Python int `n` traces to a STATIC `(n,)` result shape (a symbolic rank-0 `n` input → runtime-dynamic `(None,)`). **(6) Polymorphism** — `key()` is a polymorphic creator (concrete `Tensor` outside a trace — usable as an explicit graph input; Constant op inside); every other function is a graph op (`TraceError` outside a trace; concrete `Tensor` operands raise `TraceError`). **(7) Backend coverage** — the numpy interpreter is the reference for ALL THREE algorithms (kernels in `etl/backends/numpy/kernels/random.py`: splitmix64 unchanged; threefry2x32 = Threefry-2x32 cipher, 20 rounds, ported from the published Random123/JAX reference; philox4x32_10 = Philox-4x32-10 cipher, 10 rounds, standard M0/M1/W0/W1 constants, round-key schedule = cyclically permuted key-word pair with per-round Weyl bumps — KAT-exact at key=0; both pure-numpy vectorized, uint32 math); 5 of the 6 random ops (`random_key_mix`, `random_uniform`, `random_normal`, `random_randint`, `random_permutation`) ALSO export as v1 StableHLO — inline SplitMix64 i64 subgraph expansion in `etl/backends/stablehlo/random_export.py` (never `stablehlo.rng`), bit-exact vs the numpy kernels (uniform/randint/permutation EXACT, normal 1 ulp); `random_multinomial` stays deferred with an explicit `BackendError`. Compiler-backend coverage of threefry2x32/philox4x32_10 is tracked in `./etl/backends/stablehlo/CONTEXT.md`. **(8) Default algorithm (benchmark-driven)** — `DEFAULT_ALGORITHM` is `splitmix64`: measured fastest on both CPU targets (numpy geomean 116 vs 426/187 ms; llvm-cpu 20.4 vs 41.8/43.3 ms for threefry/philox) and tied on cuda (1.67 vs 1.63 ms), winning every ≥4M-element cuda cell, with the lowest compile times and no native-primitive dependency — full matrix in `etl/bench/rng_bench_results.md` (`python3 -m etl.bench.rng_bench`). `threefry2x32` is the explicit choice for small-sample/GPU-heavy workloads (wins the 1M-element cuda cells, native ~0.5 vs ~1.4 ms; native THREE_FRY is the iree default path for it). Transforms (`vmap`/`grad`/`jvp`/`vjp`) have no rules for random ops → `TransformError`. The 6 random OpDefs (`random_key_mix`, `random_uniform`, `random_normal`, `random_randint`, `random_permutation`, `random_multinomial`) live in `etl/ir/op_defs/random.py`, category "random", effect "pure" — usable inside `cond`/`while_loop`/`scan` regions.

**Custom ops** (owned by `block`): `etl.block(name, inputs=None, outputs=None, attributes=None, effects=None, batching=None, portable=None)` — decorator/factory returning a callable `BlockOp`; `BlockOp.impl(backend_name)`; `BlockOp.batching_rule(fn)`; `BlockOp.jvp_rule/vjp_rule(fn)`. No rule + no safe policy + no portable decomposition ⇒ `TransformError`.

**Backends** (owned by `backends`): `etl.backends.Backend` (abstract: `name`, `capabilities`, `lower`, `compile`, `load`), `etl.backends.register/get(name)`, `etl.backends.numpy_backend` (default CPU interpreter), `etl.backends.stablehlo` (`export(graph|module) -> str` MLIR text). `etl.lower/compile/load` default to `numpy_backend`.

**Persistence** (owned by `persist`, used by pipeline types): `Graph.save/load`, `LoweredProgram.save/load/.text()`, `CompiledArtifact.save/load`, `Executable.save/load`, `etl.Cache` (explicit; `FileCache(directory)` in `persist`). Loading never silently re-traces/recompiles; incompatibility fails clearly.

**Namespace**: `etl.numpy` (alias `enp`) + `etl.numpy.linalg` — numpy-style graph API producing the same IR as `ops`.

**Structured I/O**: tuple/list/dict/namedtuple/dataclass supported everywhere (trace inputs, run outputs, bind). Custom containers register via `etl.register_pytree_node`. **Pytree utilities** (owned by `core`, exported on `etl`): `tree_map(fn, *trees)`, `tree_leaves(tree)`, `tree_structure(tree)`, `tree_flatten(tree)`, `tree_unflatten(leaves, treespec)` — pure sugar over flatten/unflatten (no new semantics). Container edge behavior: `defaultdict`/`Counter` roundtrip (default_factory preserved when `None`/a class, else a clear `unflatten` error); unorderable dict keys, dataclass `InitVar`/`init=False` rebuilds, and `register_pytree_node(object, ...)` all raise plain `TypeError`/`ValueError` with actionable messages. **Structure-mismatch diagnostics**: every structural mismatch (tree_map, `Graph.flatten_inputs`/`validate_inputs`, `run`/`bind`, transforms' axes/tangent trees) reports the first divergent pytree path with expected/got node descriptions, e.g. `run-time input structure does not match the traced signature — first mismatch at pytree path [0]['z']: expected dict with keys ['a', 'b'], got list of length 3 (expected TreeSpec(...), got TreeSpec(...))` — via the shared `core.first_mismatch_path`/`format_path` helpers; per-caller lead-in wording is preserved (tests match the substrings).

## Cross-module contracts (must-expose names)

- **`core`** exports: `Tensor`, `SymbolicTensor`, `TensorSpec`, `Dim`, `DimExpr`, `Device`, `TreeSpec` (`flatten`/`unflatten`/`register_pytree_node`), pytree sugar `tree_map`/`tree_leaves`/`tree_structure`/`tree_flatten`/`tree_unflatten`, the internal structure-mismatch helpers `first_mismatch_path`/`format_path` (consumed by trace graph.py, pipeline, transforms — NOT part of the top-level `etl` surface), `dtype(obj)`, dtype constants, `ETLError` + subclasses (incl. `VerificationError`), concrete creators, device helpers, `register_operator_handlers(kind, handler)` — a hook dict (`add`/`sub`/`mul`/`matmul`/`getitem`/`truediv`/`pow`/`neg`/`lt`/`le`/`gt`/`ge`/`eq`) that `ops` populates at import time so `SymbolicTensor.__add__` etc. work without import cycles — and `register_constant_builder` (the `etl.constant` hook, populated by `ops`).
- **`ir`** exports: `Module`, `Function`, `Region`, `Block`, `Op`, `Value`, `Builder`, `Location`, `op registry` (`ir.opdef(name)`, `ir.register_opdef`, `ir.has_opdef`, `ir.op_names` — op defs declare operands/results/attrs/effects), `verify(module) -> None` (raises `core.VerificationError`), `serialize_module/deserialize_module` (versioned, self-describing payload with integrity hash — `IR_FORMAT_VERSION`), `pretty_print(module)`. **The `ir` registry is the CANONICAL op-definition source (118 ops incl. `return` terminator, the linalg factorizations `eigh`/`cholesky`/`qr`/`matrix_rank`/`svd`/`matrix_exp`, and the shift pair `bitwise_left_shift`/`bitwise_right_shift`; the dist collective is `broadcast_collective` to avoid clashing with shape-op `broadcast`). `ops` consumes `ir.opdef()` and must NOT maintain a parallel op-definition table — `ops/_opdefs.py` is superseded; any missing arity/attr specs are fixed in `ir`, not duplicated.** Effect kinds: `pure`, `write`, `read`, `collective`, `callback`.
- **`ops`** exports: every function listed above + `runtime_call`; op functions build IR into the **active builder** obtained from `trace.current_builder()`; raise `TraceError` when no trace is active or a concrete `Tensor` operand appears; operator handlers registered into `core`. `external_call` builds the `external_call` op (see "External kernels" below).
- **`trace`** exports: `defn`, `trace`, `Graph` (attrs: `module`, `input_specs`, `output_tree`, `static_values`, `source_locations`; methods: `print()`, `verify()`, `save/load`, `flatten_inputs(args) -> flat_tensors`, `unflatten_outputs(flat) -> structured`, `validate_inputs(args) -> flat_tensors`), `cond`, `while_loop`, `scan`, `current_builder()` / builder-stack context, and `Defn` (stores fn + `__etl_defn__` marker). Graph constructor accepts a prebuilt module so transforms can build new graphs.
- **`block`** exports: `block(...)`, `BlockOp` (attrs: `name`, `input_specs`, `output_specs`, `attributes`, `effects`, `batching_policy`; methods: `impl(backend_name)`, `batching_rule(fn)`, `jvp_rule(fn)`, `vjp_rule(fn)`, `portable(fn)`; `__call__(*symbolic_or_static)` builds a BlockCall op; static args specialize). Registry queryable: `block.get_block(name)`.
- **`transforms`** exports: `vectorize`, `vmap`, `grad`, `jvp`, `vjp`. Batching rules registered per-op via a registry (`transforms.batching_rules`); derivative rules via `transforms.vjp_rules`. Result graphs contain only ordinary ops (the numpy backend needs NO special vectorize/autodiff runtime support).
- **`backends`** exports: `Backend` ABC — `name: str`, `capabilities: Capabilities` (fields: `dynamic_shapes`, `dtypes`, `collectives`, `runtime_calls`, `external_calls`, `custom_blocks`, `async_collectives`, `sparse_ops`, `rng_bit_generator`), `lower(graph, options) -> LoweredProgram`, `compile(lowered, options) -> CompiledArtifact`, `load(artifact, device) -> backend executable`; **backend `Executable` protocol** — `run(flat_input_tensors) -> flat_output_tensors`, `.functions`, `.device`, optional `.save(path)` / `.load(...)` (must save artifact + reconstruct explicitly if handles are device-specific). **`LoweredProgram`** (`.text()`, `.save/.load`, `.backend`, `.signature` — records input/output TreeSpec+specs and input/output static values passed down from the Graph) and **`CompiledArtifact`** (`.save/.load`, `.backend`, `.signature`, `.target`) are **owned by `backends`**. `Signature` fields: `input_tree`, `output_tree`, `input_specs`, `output_specs`, `static_values`, `output_static_values`. Also `register/get(name)`, `numpy_backend` (default CPU interpreter; its LoweredProgram wraps a serializable program, CompiledArtifact wraps serialized IR), `stablehlo` (export utility module `stablehlo.export(graph_or_module) -> str` MLIR text — also the shared lowering input for compiler backends), and the **pluggable compiler adapters** in `etl.backends.adapters`: `iree`, `xla` (PJRT C API driven with ctypes — user-provided plugin `.so`, no jax/jaxlib), `tvm` (jaxlib only for its bundled MLIR bindings; the `jax` package is never imported) — optional, lazily activated on first `get(name)` / `lower(..., backend=name)`; each raises an explicit `BackendError` when its dependency is missing (pip hint for iree/tvm; `ETL_PJRT_PLUGIN`/`plugin_path` guidance for xla); `import etl` never imports adapter deps.
- **`dist`** exports: `group(name, ranks, backend=None)`, `rank()`, `world_size()`, `all_reduce`, `all_gather`, `reduce_scatter`, `all_to_all`, `broadcast`, `collective_permute`. Collectives build `Collective`-effect ops (kind + group attr) with local-tensor shapes (e.g. 4-rank all_gather axis=0: `[256,1024] → [1024,1024]`). Imports `core`/`ir`/`trace` (builds ops via the active-builder hook like other frontends; `trace` must duck-type `Group` for static snapshotting without importing `dist`).
- **`sparse`** exports the surface above; imports `core`/`ir`/`trace`/`ops`/`transforms` ONLY (never `pipeline` — `etl.evaluate` lazy-imports it inside the function). Batching/vjp/jvp rules register into `transforms`' public registries (`register_batching_rule`/`register_vjp_rule`/`register_jvp_rule`/`register_batched_aux_remap`) one-way at `import etl.sparse` time. No new IR value kind — sparse tensors are pytree composites over ordinary tensor values plus static leaves.
- **`block`** exports: `block(...)`, `BlockOp`, `get_block`, `BlockError`, `BatchingPolicy`. `BlockOp` attrs: `name`, `input_specs`, `output_specs`, `attribute_schema` (alias `attributes`), `effects`, `batching_policy`; methods `impl(backend_name)`, `batching_rule(fn)`, `jvp_rule(fn)`, `vjp_rule(fn)`, `portable(fn)`, `__call__`. Factory form `block(name, inputs=[...], outputs=[...], ...)` and decorator form over an `@etl.defn` (name defaults to fn name; `result=`/`outputs=` may declare output specs; portable impls MUST be `@etl.defn` functions). Rules register into `transforms.*_rules` under `block:<name>` keys — `transforms` never imports `block`.
- **`external`** (`etl/external.py`) exports: `register_external_kernel(name, callable_, backend=None, device_resident=False) -> ExternalKernel`, `unregister_external_kernel(name)`, `get_external_kernel(name, backend=None)` (callable-only — the numpy backend's lookup), `get_external_kernel_entry(name, backend=None) -> (callable | None, device_resident: bool)` (the mode-aware internal lookup the iree dispatch uses), `register_portable(name, fn)`, `get_portable(name)`, and class `ExternalKernel` — the PER-BACKEND run-time kernel registry behind `external_call` (see "External kernels" below; rule registration + portable-decomposition fallbacks live in `etl/external_rules.py`, a self-contained mirror of `etl/block/rules.py`). Imports NOTHING from etl at module level (stdlib only; lazy: only the numpy backend, the frontend op docstrings, and the fallback rules reference it).
- **`pipeline`** (`etl/pipeline.py`) exports: `lower/compile/load/run/bind/build/evaluate`; `Executable` (user-facing wrapper: backend executable + input/output TreeSpec + signature for validation; `.functions`, `.device`, `.save/.load` delegating to backend), and `BoundExecutable` from `bind`. Internal hot-path caching (no observable behavior): each `Executable`/`BoundExecutable` lazily caches an input plan (`_build_input_plan`: expected tree — full or bound-reduced — + per-leaf `(is_tensor, path, spec, recorded, flat_index)` layout) and an output plan (`_build_output_plan`: once-normalized output tree + per-leaf flags); `run` then validates structure and leaves in a single pass over the raw arguments (`_fast_structure_walk`, mirroring `core.flatten`'s node precedence and `first_mismatch_path` semantics with `leaf_vs_empty_is_mismatch=False`) with no runtime TreeSpec built, falling back to the slow path (`_prepare_flat_inputs_slow`) on any structural divergence so error messages stay byte-identical.
- **`persist`** exports: `save_object(path, payload_type, payload_fields, backend_info=None, signature_info=None)` / `load_object(path, expected_payload_type=None) -> LoadedObject` using a container format: magic header (`b"ETLPERS"`) + format version (`ETL_FORMAT_VERSION`) + JSON metadata + payload + SHA-256 integrity; `encode_value/decode_value` (envelope codec covering numpy arrays via base64 npy, dtype, slice, Dim, DimExpr, Device, TensorSpec, TreeSpec, containers); `Cache` interface + `FileCache(directory)` with `get(key_components, compute_fn=None)` (alias `get_or_compute`). Imports `etl.core` ONLY.

## Value-model details (binding)

- **Shapes**: `Dim(name)` symbolic; `DimExpr` supports `+ - * // % min max` over dims/ints; `TensorSpec.shape` = tuple of `Dim|DimExpr|int|None` (None = runtime-dynamic, unchecked). Rank is always known at trace time. Shape inference is `ir`/`ops`'s job via `DimExpr` arithmetic.
- **`Tensor`**: wraps numpy `ndarray` in v1 (dtype, shape, device, data); `.numpy()` returns underlying array; `__dlpack__(stream=None)`, `etl.from_dlpack(...)` (accepts objects with `__dlpack__`); equality = identity + metadata. Mutable `data` access documented as unsupported for graph constants.
- **`SymbolicTensor`**: fields `value` (ir.Value), `dtype`, `shape` (tuple of `DimExpr|int`), `location`; SSA identity = `value.id`. Must NOT define `numpy`, `data_ptr`, `__dlpack__`, `__array__`.
- **`Graph` trace semantics**: parameters become `Function` block args; static Python values specialize and are recorded in `static_values` (run validates them); closure-captured `Tensor` used in ops → `TraceError` ("make it an explicit input or use etl.constant"); `etl.constant` creates a Constant op and issues a warning above `ETL_LARGE_CONSTANT_BYTES` (default 1 MiB, env-tunable).
- **Staged sugar rules**: `etl.build`/`etl.evaluate` docstrings must state their exact expansion; no other composition APIs exist in core.

## Serialization contract (binding)

Formats versioned via constants (`ETL_FORMAT_VERSION`). Artifacts are self-describing: record backend name/version, target, input/output signature (TreeSpec + specs), static values, required custom ops, IR format version. `Graph.save` → `.etlgraph` (portable JSON container); `LoweredProgram` numpy → serialized program; stablehlo → `.mlir` text; `CompiledArtifact` → `.etlartifact`; `Executable.save` → backend-dependent (numpy: saves artifact + explicit note it is reconstructed at load). Load with mismatched backend/device/ABI → `PersistenceError`, never silent recompile.

## External kernels (binding interface contract)

A kernel-agnostic escape hatch for plugging custom (e.g. triton) kernels into `defn` graphs to bypass compiler weaknesses. **No triton (or any kernel) code lives in etl** — the mechanism only declares, registers, and dispatches; the kernel itself is written against this interface in a different repo. Two halves:

**1. Graph side — `etl.external_call(name, *operands, result=...)`** (frontend op in `etl/ops/external.py`, IR op `external_call`, effect `callback`):
- `name`: non-empty `str` — the STATIC kernel identifier; it specializes the graph exactly like any static parameter. Registration is a RUN-TIME concern: tracing does NOT require the kernel to be registered; running does.
- `*operands`: `SymbolicTensor` or Python scalars (auto-promoted to 0-d constants). No static (Python) parameters in v1 — inputs are declared tensor operands only.
- `result`: a `core.TensorSpec` (single output) or a non-empty tuple/list of `TensorSpec` (multiple outputs) — the graph's DECLARED output contract (shapes/dtypes). Specs may contain symbolic dims (resolved against runtime input bindings, like `runtime_call`) or `None` (runtime-dynamic, unchecked). Returns a `SymbolicTensor` or a tuple of them.
- Errors: `TraceError` outside a trace / for concrete `Tensor` operands (the mandated three-option message); `TypeError` for a bad `name` or `result`.
- Works inside `cond`/`while_loop`/`scan` bodies on the numpy backend.

**2. Run-time side — the registry (`etl/external.py`, stdlib-only module-level imports; all `etl` imports lazy)**:
- `etl.register_external_kernel(name, callable_, backend=None, device_resident=False) -> ExternalKernel` — process-global, PER-BACKEND registry: each name maps to a dict of backend slots (`None` = the DEFAULT slot, used by every backend with no exact slot). Registers into the given slot, OVERWRITING any previous registration in that slot — callable AND mode (last wins — documented; enables hot-reload and adapter re-registration). `backend` may be `None` or any string (backend-neutral — no registry check). **`device_resident=True` (explicit opt-in, no magic) registers a DEVICE kernel — it REQUIRES an explicit per-backend slot (`TypeError` when combined with `backend=None`: the default slot is also dispatched by the numpy backend, which passes host numpy arrays, never device tensors); any non-None backend string is accepted as today — backend-neutral, and in v1 only the iree adapter consumes the flag.** `TypeError` for a non-str/empty name, a non-callable kernel, a non-bool `device_resident`, or a non-None/non-str backend. RETURNS an `ExternalKernel` handle for the name (previously returned `None` — additive).
- class `etl.ExternalKernel` (the handle; attr `name`) — decorator-friendly (every method returns `fn`): `impl(backend, fn=None, device_resident=False)` per-backend kernel registration (both `handle.impl("numpy", fn)` and `@handle.impl("iree", device_resident=True)` forms work), `portable(fn)` (= `register_portable`), `batching_rule(fn)` / `vjp_rule(fn)` / `jvp_rule(fn)` register transform rules under `external:<name>` (lazy imports).
- `etl.register_portable(name, fn)` — the OPTIONAL graph decomposition: `fn` must be an `@etl.defn` function (the `__etl_defn__` marker is validated at registration — clear `TypeError` naming the kernel otherwise); it is traced LAZILY when a fallback rule fires. ALSO pre-registers the decomposition FALLBACK rules under `external:<name>`: the vjp fallback ALWAYS, the batching fallback only when no explicit batching rule exists yet (explicit rules win; explicit rules registered later overwrite the fallbacks — last-wins).
- `etl.get_portable(name)` — the registered portable (`@etl.defn` fn) or `None`.
- `etl.unregister_external_kernel(name)` — removes ALL kernel slots AND the registered portable for the name; `KeyError` if the name was never registered (neither slots nor a portable — loud). Does NOT touch the `transforms` rule registries (rules are graph-level and survive; re-register the portable to restore the fallbacks).
- `etl.get_external_kernel(name, backend=None)` — resolution: the exact `backend` slot → the default (`None`) slot → `None`; returns just the CALLABLE. `get_external_kernel(name)` (no backend) returns the default slot — backward compatible. `etl.external.get_external_kernel_entry(name, backend)` (internal, mode-aware) returns the full `(callable, device_resident)` slot entry with the same resolution — the iree dispatch uses it to select host vs device dispatch.
- Callable signature (binding): **HOST mode (default)** `fn(*np_arrays) -> ndarray | core.Tensor | tuple/list of them` — the number, dtype, and shape of the returned arrays MUST match the specs declared by the invoking `external_call` op. The numpy backend validates count (`BackendError`), dtype exactly (`BackendError` — no silent coercion), and shape (`ShapeError`); anything else the kernel returns is a `BackendError` (never a guess). The numpy interpreter and the iree host-mode dispatch share ONE validation implementation (`etl/backends/external_validate.py` — canonical message wording). **DEVICE mode (`device_resident=True`, iree only in v1)**: `fn(*tensors) -> core.Tensor | duck payload (shape/dtype/device/to_host()) | raw iree DeviceArray | ndarray | tuple/list mixing these` — operands are the boundary's device-resident `core.Tensor`s (`.data` is an `IreeDevicePayload`), passed DIRECTLY (never `.numpy()`-staged); results are validated METADATA-ONLY (count/dtype/shape, same canonical wording — device results are NEVER host-copied; numpy results wrap as host tensors staged back by the next segment's input machinery).

**Execution semantics (v1)**: the numpy interpreter dispatches the op by name at its position in block op order (effect `callback` — the op anchors ordering; no async execution), resolving `get_external_kernel(name, "numpy")` (host mode always — the numpy backend passes host numpy arrays, whatever the registered mode); the iree dispatch resolves `get_external_kernel_entry(name, "iree")` and dispatches in the REGISTERED mode (host or device — both fall back to the default slot automatically; a default-slot kernel is always host mode). Kernel outputs are wrapped in `core.Tensor` (CPU host tensors for host mode; device-resident tensors for device mode) and consumed by downstream ops normally. Unknown name at run time → `BackendError` naming the kernel and pointing at `register_external_kernel`.

**Transforms**: rules live under the namespaced key `external:<name>` in transforms' public registries (`batching_rules`/`vjp_rules`/`jvp_rules` — looked up automatically via `transforms.batching._rule_key` / `transforms.autodiff._rule_name`); explicit rules register through the `ExternalKernel` handle (`batching_rule`/`vjp_rule`/`jvp_rule`). WITHOUT explicit rules, a registered PORTABLE makes `vmap`/`vectorize`/`grad`/`jvp`/`vjp` work through pre-registered decomposition fallbacks (`etl/external_rules.py` — a self-contained mirror of `etl/block/rules.py`'s fixed pattern): batching re-traces the portable over the batched operand values in the active transform builder (MappedAxes tracked through the inlined ops in creation order; result axes = union of operand axes — the longest contiguous leading tuple); vjp re-traces the portable and runs a LOCAL reverse sweep over ONLY the inlined ops, seeding cotangents on the POST-inline result values, with nested `block_call`/`external_call` ops resolved via their own `block:<name>`/`external:<name>` keys through the public `require_vjp_rule` registry (all-zero cotangents short-circuit to zeros without inlining; `constant` ops skip the sweep — nothing to propagate). Missing rule AND no portable → `TransformError` naming the op (never a silent fallback); the message hints at the handle API.

**Persistence**: the registry is NEVER serialized — graph artifacts carry only the `name` string (JSON-safe attr; `result_specs` round-trips through the standard ValueType wire encoding). `Graph.save`/`load` work; any process that runs a saved graph must re-register its kernels first (else the run-time `BackendError` above). Self-describing artifacts: the numpy `compile()` records external kernel names in `required_custom_ops` alongside block names (self-description only — kernels resolve LAZILY at run time, never a load-time requirement; block names are still load-time validated from the module's actual `block_call` ops).

**Compiler backends (iree split + host/device dispatch)**: the iree adapter declares `Capabilities.external_calls=True` and executes external-call graphs through a SPLIT + dispatch model (implementation: `./backends/external_split.py` + `./backends/compiler.py` + the iree adapter): at `lower()` the graph is cut at every top-level `external_call` op (op order) into SEGMENT programs — plain graphs with no external calls inside — plus a JSON-safe kernel-call PLAN (payload `stablehlo-segments`); `compile()` produces one vmfb per segment (artifact `iree-vmfb-segments`); at `run()` the segments execute strictly in plan order on the HAL device and at each `external_call` boundary the kernel is dispatched through the SAME name-keyed registry in its REGISTERED MODE (`etl.register_external_kernel` — kernels are never embedded in artifacts; unknown name at run time → `BackendError` naming the kernel and pointing at the registry): a **HOST-mode kernel** (the default — every pre-existing registration) receives the boundary's operand tensors staged to host numpy arrays and its validated host results (count/dtype/shape vs the declared specs — never silent coercion) are staged back into the following segment; a **DEVICE-mode kernel** (`device_resident=True`, explicit per-backend slot only) receives the segment's device-resident `core.Tensor` operands DIRECTLY (never `.numpy()`-staged) and may return `core.Tensor`s with device payloads, duck-typed payloads (`shape`/`dtype`/`device`/`to_host()`), raw iree `DeviceArray`s (wrapped with the run's `core.Device`), numpy arrays, or tuple/list mixes — device results are validated METADATA-ONLY (count/dtype/shape vs the declared specs, same canonical wording — the adapter NEVER materializes a host copy of kernel results) and occupy the plan's result slots, where the next segment's same-device pass-through consumes them with ZERO host round-trips (numpy results are staged back by the same machinery, backward compatible). Carried plain values that are NOT kernel operands stay device-resident across segments (zero extra host round-trips). The once-per-executable staging `UserWarning` fires ONLY when a boundary actually stages host↔device (a host-mode kernel, or device-mode results that are host-backed numpy) — a fully device-resident boundary emits NO warning. **Public interop surface:** the device payload is `etl.backends.adapters.iree.IreeDevicePayload` (`.device_array` — the iree `DeviceArray` HAL buffer handle, `.shape`, `.dtype`, `.to_host()`, `.device`) so kernel authors can isinstance-check the operands a device kernel receives and run further vmfb modules on the SAME HAL device via `iree.runtime` — the adapter itself never forces host copies. Determinism contract: kernels are assumed PURE (same inputs → same outputs) and segments execute sequentially in plan order, so the graph's `callback` effect ordering is preserved.

Restrictions (explicit `BackendError` at `lower()`, never silent): no `external_call` inside `cond`/`while_loop`/`scan` bodies (data-dependent control flow around a host call is not splittable); single-function graphs; at least one tensor operand (a zero-operand call has no staging boundary — express the value via `etl.constant` or an explicit graph input); result dims must be STATIC integers (staging needs concrete shapes — symbolic/`None` dims are rejected); single-block regions when cloned (the region-cloning path supports single-block regions in v1).

**Other compiler backends (contract)**: the stablehlo exporter and the xla/tvm adapters reject `external_call` with an explicit `BackendError` (`Capabilities.external_calls=False`; the exporter additionally lists it in `DEFERRED_OPS`) — UNLESS the kernel has a registered PORTABLE: a companion package wires the compiler-side decomposition, inlining registered portables into the exported graph with a warning (kernels with neither a portable nor an explicit rule still fail with the explicit `BackendError` — never a silent fallback). Example (numpy backend + iree host-dispatch):

```python
import etl
# elsewhere, in the kernel repo (e.g. a triton kernel):
etl.register_external_kernel("relu_custom", my_numpy_or_triton_fn)

@etl.defn
def model(x, w):
    h = etl.external_call("relu_custom", x, result=etl.TensorSpec((N, D), etl.float32))
    return etl.dot(h, w)          # downstream ops consume the kernel output

y = etl.evaluate(model, x_np, w_np)   # numpy backend: dispatches my_numpy_or_triton_fn
y_iree = etl.evaluate(model, x_np, w_np, backend="iree")  # split + dispatch on llvm-cpu

# DEVICE-resident kernel (iree, GPU): operands arrive as core.Tensor with
# IreeDevicePayload .data — the kernel may run its own vmfb modules on the
# SAME HAL device and return device results; NO per-boundary host staging.
etl.register_external_kernel("relu_cuda", my_device_fn,
                             backend="iree", device_resident=True)
y_cuda = etl.evaluate(model, x_np, w_np, backend="iree", device=etl.Device("cuda", 0))
```

## Design decisions (15-op batch)

`sort/argsort/topk` (sorting), `tile/stack/flip/roll/clamp/diag/isnan/nan_to_num/eye/linspace` (structural), and `matmul/cumprod` (linalg): 8 new IR ops (`sort`, `argsort`, `tile`, `flip`, `roll`, `diag`, `cumprod`, `nan_to_num` — registry 118 total incl. `return`), 7 frontend compositions (`topk` = sort/argsort + gather, `stack` = reshape + concatenate, `clamp` = maximum/minimum, `eye`/`linspace` = Constant compositions, `matmul` = dot sugar, `isnan` = comparison composition). `linspace` defaults to float64 — deviation from the etl float32 creation convention (explicit `dtype` param; symbolic bounds → `TraceError`, v2 deferral). No vjp/batching rules for the 8 new IR ops + eye/linspace (`TransformError`, the random-op pattern); clamp/matmul/isnan/stack/topk inherit their composition's rules. Numpy backend = full reference; compiler backends export `sort`/`argsort`/`tile` as v1 StableHLO and defer `flip`/`roll`/`diag`/`cumprod`/`nan_to_num` with explicit `BackendError` (compositions work via their components). Detailed notes in `./ops/CONTEXT.md` and `./ir/CONTEXT.md`.
