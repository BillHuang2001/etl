# etl.bench — conformance & benchmark harness

## Intent

A standalone harness subpackage that runs curated example etl programs against pure-numpy references and — optionally — PyTorch references, reporting **precision** (conformance: max-abs/max-rel errors, pass/fail per reference) and **speed** (benchmark: best-of-N wall-clock ms per implementation + speedup ratios). It is a verification/measurement tool for the etl pipeline (`etl.build` + `etl.run`, or the explicit lower/compile/load path for transform-produced graphs), usable on **any registered backend and device** (default: numpy backend, CPU). Coverage spans four categories: **micro** (small canonical programs), **grad** (gradient conformance: `etl.grad` vs float64 central finite differences vs torch autograd), **vectorize** (`etl.vmap` auto-vectorization vs MANUALLY batched numpy/torch references), and **large** (transformer block, n-body step, big matmul/conv/layernorm, batched vmap MLP). It is not part of the etl runtime.

## torch-optionality constraint (binding)

- The etl project must NOT depend on torch: `import etl` / `import etl.bench` MUST always succeed without torch installed.
- torch is imported ONLY lazily inside function bodies (see `_torch.py` — `torch_available()` / `require_torch()`; every example's `torch_ref` factory goes through `require_torch()`). NEVER at module top level, never at import time.
- Missing torch → a clear `ImportError` mentioning `pip install etl[bench]` (never a raw `ModuleNotFoundError` escaping). `use_torch=True` / `--torch` require torch; `use_torch=None`/`--torch` default = auto (torch comparisons run iff `import torch` succeeds).

## API surface (public, via `etl.bench`)

- `conformance(examples=None, *, use_torch=None, tolerance=None, rtol=1e-5, atol=1e-5, seed=0, backend="numpy", device=None, **backend_options) -> ConformanceReport` — signature is STABLE. Per example: generate seeded inputs, stage (`stage_example`), `etl.run`, compare vs numpy ref (always) and torch ref (if enabled) with the documented rule: `tolerance=None` → allclose-style `|a-b| <= atol + rtol*|b|` per element (float64); numeric `tolerance` → `max_abs_error <= tolerance`. NaN fails. **Per-example tolerance resolution**: each `Example` may carry `rtol`/`atol`/`tolerance` overrides (all three independent); the effective value is the example's when not None, else the global argument. Effective values are recorded on each `ExampleResult` (`rtol`/`atol`/`tolerance` fields). The conformance table prints one compact **"tol" column** (between "torch" and "etl_ms"): "-" when the example used the global defaults, else `abs 1e-4` (tolerance) or `rtol 1e-3 atol 1e-3`. Per-example failures are recorded in the report (`error` field, `overall_pass=False`), not swallowed.
- `benchmark(examples=None, *, use_torch=None, repeats=20, warmup=2, seed=0, backend="numpy", device=None, **backend_options) -> BenchmarkReport` — best-of-`repeats` ms after `warmup` untimed runs for etl/[numpy]/[torch]; speedup = `reference_ms / etl_ms`. Tolerances do not affect benchmark.
- **`examples` argument**: `None` → ALL registered examples; a string or iterable of **names AND/OR category names** (`"grad"`, `"large"`, `["micro", "matmul"]` — categories expand via `expand_names`). `list_categories() -> list[str]` returns `["micro", "grad", "vectorize", "large"]`.
- `list_examples() -> list[str]`, `get_example(name) -> Example` (unknown → `UnknownExampleError` listing available names), `Example.generate_inputs(seed)` / module `generate_inputs(example, seed)`.
- **`Example` (frozen dataclass)** fields, in order: `name, description, specs, graph, numpy_ref, torch_ref=None, rtol=None, atol=None, tolerance=None, category="micro", inputs_fn=None`. `graph` is an `@etl.defn` (staged via `etl.build`) OR a plain callable `(*specs) -> Graph` (transform products — `etl.grad(...)`/`etl.vmap(...)` TransformCallables — staged via `example.graph(*specs) → Graph` then `etl.lower → etl.compile → etl.load`; see `stage_example` in `_util.py`; options go to BOTH lower and compile). `inputs_fn(seed) -> list[np.ndarray]` overrides default RNG input generation (e.g. non-negative gather indices); `numpy_ref(inputs)` must return the same structure as `etl.run` (single ndarray or tuple; grads as a tuple matching the `argnums` subset); `torch_ref(inputs, device=None)` lazy.
- **`backend`**: any registered etl backend name (validated up front via `etl.backends.get` — unknown names / missing adapter deps raise `core.BackendError` BEFORE any example runs; the CLI maps that to exit 2).
- **`device`**: `None` → `core.Device("cpu", 0)`; a `core.Device` (kind `"cpu"`/`"cuda"`); or a `"KIND[:INDEX]"` string. The report records the formatted device string.
- **`**backend_options`**: passthrough to `etl.build`/`etl.compile` (compile options for compiler backends). Device-derived default: any non-numpy backend without an explicit `target_backends` gets `["cuda"]` on a cuda device, `["llvm-cpu"]` otherwise. An explicit option always wins.
- Torch references run on the same device kind when it is cuda AND torch CUDA is available AND the index is within `torch.cuda.device_count()` (`resolve_torch_device`); otherwise CPU. Every `torch_ref` factory has signature `(inputs, device=None)`.
- Report types: `ExampleResult` (fields: name, description, max_abs_error, max_rel_error, numpy_pass, torch_pass, etl_ms, numpy_ms, torch_ms, speedup_vs_numpy, speedup_vs_torch, error, **rtol, atol, tolerance** — the last three = effective conformance tolerances used, None on errored/benchmark results), `ConformanceReport` / `BenchmarkReport` (fields include `backend: str = "numpy"`, `device: str = "cpu"`); `print_report(report)` and `str(report)` render human-readable tables — the header shows `backend=... device=...` ONLY when non-default. `to_dict()`/`to_json()` include the new fields naturally.
- CLI: `python -m etl.bench [--examples NAME[,NAME...]|CATEGORY[,CATEGORY...]] [--conformance|--no-conformance] [--benchmark|--no-benchmark] [--torch|--no-torch] [--repeats N] [--seed N] [--backend NAME] [--device KIND[:INDEX]] [--backend-option KEY=VALUE ...]`; exit 0 = ok, 1 = conformance failure, 2 = usage error. `--examples` accepts names OR categories (help text lists the categories dynamically). `--backend-option` values parse JSON-first with raw-string fallback; later duplicates override.

## Gradient & vectorize conformance design

- **`fd_gradient`** (base.py): per-element central finite differences, h=1e-4, ALL computation in float64 (inputs converted inside; value_fn receives float64 arrays); non-floating inputs → zero float64 gradient arrays; `sg_inputs` = indices whose perturbation is frozen (`frozen={i: original}` passed alongside the perturbed copy; value_fn models stop_gradient via `frozen.get(i, inputs[i])`). Every grad example's numpy_ref = fd gradient on the float inputs, returning ONLY the `argnums` subset (matching the `etl.grad` output structure).
- **FD-step sanity (measured)**: fd (h=1e-4, fp64) vs torch autograd agree max_abs ≈ 2.6e-6 (grad_mlp) and 1.2e-12 (grad_stopgrad); etl fp32 grads vs fp64 fd: grad_mlp 2.28e-6, grad_mix 3.41e-6, grad_stopgrad 1.8e-12, grad_structural 2.67e-7 (numpy backend, seed 0) — hence rtol=atol=1e-3 per-example defaults (measured 8e-4 worst-case for matmul-MSE at grad magnitude ~4; all examples measure 2-3 orders below).
- **vjp-rule coverage** (66 keys in `etl.transforms.vjp_rules`; 48 covered in committed examples): grad_mix covers add, subtract, multiply, divide, power, remainder, maximum, minimum, abs, negate, square, sqrt, exp, log, log1p, sin, cos, tan, tanh, sigmoid, relu, cast, select, broadcast, dot, reshape, transpose, slice, pad, concatenate, sum/reduce_sum, mean/reduce_mean, max/reduce_max, min/reduce_min, prod/reduce_prod (frontend forms are sugar for the reduce_* IR ops), plus zero-grad less/equal/greater/logical_and; grad_stopgrad covers stop_gradient; grad_structural covers gather, scatter, solve. NOT covered (one-line justifications in grad.py docstring): **sign** (genuine bug — no rule impl despite registry entry, see Known Issues), **conv** (documented v1 deferral), **erf/gelu/cumsum/tril/triu** (rules exist and are numpy-validated; StableHLO v1 export deferral blocks them on iree), **argmax/argmin** (index outputs, zero-vjp), **bitwise_\*** and **logical_or/not/not_equal/less_equal/greater_equal** (same `_zero_vjp` class as the covered comparisons).
- **vmap design**: each example = per-sample `@etl.defn` + `etl.vmap(fn, in_axes=..., out_axes=0)` TransformCallable as `example.graph` (plain callable returning a Graph). v1: mapped axes leading; `None` in_axes entries supported (shared weights). numpy_refs are hand-written per-sample loops — auto-vectorization is genuinely validated, and on the numpy backend the vectorized graphs match the manual refs EXACTLY (max_abs 0.0; vmap_softmax cross-checked against a manually batched `@etl.defn` with an IDENTICAL op sequence). `vmap_grad_mlp` uses the supported **vmap∘grad composition** (`etl.vmap(etl.grad(loss, argnums), in_axes=...)`) — literal `etl.grad(vmap(fn)(*specs))` is impossible in v1 (vmap'd output is the batched loss VECTOR, grad requires a scalar: ShapeError, documented). References: fd per-sample stacked; torch = autograd of the summed separable loss (sum, not mean, so the gradient is exactly the per-sample stack).
- **conv2d_large torch ref** disables `torch.backends.cudnn.allow_tf32` inside the body: cuDNN TF32 (torch default for conv) degrades fp32 conv precision to ~0.036 abs on cuda (measured) vs 8.4e-5 with TF32 off — TF32 is a perf optimization, not fp32 semantics; the reference must stay accurate.

## Constraints

- Deps: stdlib + numpy + etl only (torch optional/lazy). CPU only for the reference path; GPU runs go through compiler backends. No edits outside `./etl/bench/`.
- Numpy conv references mirror etl's conv semantics exactly (VALID; SAME = TF convention `out=ceil(d/stride)`, pad split `(total//2, total-total//2)` per spatial axis — see `etl/backends/numpy/kernels/linalg.py`).
- The numpy backend is CPU-only — its `load()` rejects non-CPU devices with an explicit `BackendError`; the harness does NOT special-case around that (the explicit error is the contract, recorded per-example).
- The harness NEVER selects a GPU implicitly — the caller chooses the device explicitly (`--device cuda:N` / `device=`). Operational GPU policy (runners, not the harness): scan first with `nvidia-smi --query-gpu=index,memory.free --format=csv,noheader`, use the most-free GPU, release promptly. etl `Device("cuda", N)` maps to iree device_id N+1 (1-based; verified empirically in `etl/backends/adapters/iree.py`).
- Argument errors (bad `backend`/`device`/`tolerance`/`repeats`/`warmup`, unknown backend, unknown example, `use_torch=True` without torch) raise up front; per-example EXECUTION failures (e.g. a backend's `BackendError` during build/run/compile) are recorded in the report — never swallowed, never crash the run.
- Budget: default numpy/cpu CLI run ≈ 2.5 min; iree cpu / cuda full runs ≈ 3–5 min (compile dominates). matmul is sized 1024 for the iree cpu budget (see Known Issues).

## Known Issues

- **Genuine core bug — `etl.sign` VJP is registered but unimplemented**: `etl.transforms.vjp_rules` lists `'sign'`, but `_pointwise_vjp` has no `_UNARY_DERIV`/`_POINTWISE_VJP` entry for it. Repro: `@etl.defn def f(x): return etl.sum(etl.sign(x))`; `etl.grad(f)(TensorSpec((4,), etl.float32))` → `TransformError: grad/vjp: no VJP rule for op 'sign'`. `abs`'s derivative uses the sign OP (works as a forward op) — only differentiating THROUGH sign is broken. `sign` is deliberately excluded from grad_mix; the harness reports it, it does not work around it.
- **Genuine core bug — StableHLO exporter emits invalid `stablehlo.dot_general` for rank-mismatched batched dot (3-D @ 2-D)**: `etl.dot` on [1,512,768] @ [768,2304] lowers to `dot_general` with `lhs_batching_dimensions = [0], rhs_batching_dimensions = []` — StableHLO requires the same number of batching dims on both operands; iree-compile rejects it ("lhs and rhs should have the same number of batching dimensions"). Repro: `@etl.defn def f(x, w): return etl.dot(x, w)` with `TensorSpec((1,512,768), float32)` + `TensorSpec((768,2304), float32)`; `etl.lower(..., backend="iree")` succeeds, `etl.compile` raises `BackendError`. The numpy backend computes the same graph correctly. Consequence: **`transformer` fails on iree** (per-example BackendError, recorded — the example deliberately keeps the prescribed 3D@2D form). Fix belongs in the exporter (emit a non-batched dot_general with contracting dims only, or batch-expand the lower-rank operand).
- **Genuine core limitation — symbolic dims in the StableHLO exporter block all vmap graphs on iree** (two error classes): (a) `vectorize` replaces mapped static dims with symbolic `Dim("batch")` (by design); the exporter renders them as unbounded `?`, and iree-compile rejects `stablehlo.reshape` with a dynamic result dim ("'stablehlo.reshape' op result #0 must be statically shaped or single bounded dimension tensor ... got 'tensor<?x1xf32>'") — hit by the keepdims reductions and rank/batch-aligning reshapes of every shape-changing vmap graph. Repro WITHOUT vmap: softmax `@etl.defn` traced with `TensorSpec((etl.dim("B"), 16))` fails identically; a reshape-free symbolic-spec graph compiles and runs. (b) the exporter cannot broadcast operands with symbolic `DimExpr` dims: "cannot broadcast operand of shape (DimExpr('max', left=Dim('batch'), right=Dim('batch_1')), 1, 32) to the elementwise result shape ..." — vmap_mlp / vmap_grad_mlp / vmap_mlp_large hit this. All six vectorize examples + vmap_mlp_large record documented per-example BackendErrors on iree (cpu and cuda); the numpy backend handles them all exactly (max_abs 0.0 / 1.28e-05). Fix belongs in core (bounded dims, reshape-free keepdims lowering, or `stablehlo.dynamic_reshape`).
- **mlp fails the strict defaults on the iree backend (CPU and CUDA)** — deterministic `max_abs_error ≈3.8e-05` (CPU) / `≈6.1e-05` (CUDA) exceed `atol + rtol*|b|` at the strict defaults. Verified NOT a harness bug: IREE's fp32 output is *closer* to a float64 ground truth than the numpy fp32 reference itself (fp32 accumulation-order noise / FMA contraction). mlp carries `tolerance=1e-4` (passes comfortably); the numpy backend is exact (shared kernels).
- **attention passes strict defaults on iree (measured)**: max_abs 2.38e-07 (cpu) / 2.38e-07 (cuda) — no relaxation needed.
- **matmul sized 1024** (`matmul_1024`): a [4096,4096] fp32 matmul measured **384 s/run** on iree llvm-cpu (~0.18 GFLOPS — generic-CPU codegen, no microkernels; [2048] → 26 s/run, [1024] → 3.9 s/run), which would make the default iree/cpu CLI run take hours. Sized 1024 with measured justification; the numpy backend still exercises a 2 GFLOP matmul (etl_ms ≈ 1.9 ms). iree/cpu measured max_abs 2.06e-4 → atol=5e-4 (~2× margin; torch 8.4e-5, iree/cuda 2.14e-4).
- **cumsum fails on the iree backend**: explicit `BackendError` (StableHLO v1 defers cumsum export — documented, intentional limitation), recorded per-example.
- **gather/scatter/solve StableHLO export deferred**: `grad_structural` runs on numpy (max_abs 2.67e-7) but raises `BackendError: stablehlo export: op 'gather' ... not supported in v1` on iree — the documented per-example failure class (same as cumsum).
- **conv VJP is a documented v1 deferral** (TransformError: "no VJP rule for op 'conv' — the IR has no transposed-convolution op (v1 gap)") — probed at dev time, conv deliberately not in any grad example.
- iree-base-runtime emits `nanobind: leaked ...` warnings at interpreter shutdown (upstream teardown noise; harmless for exit codes and report output — but when pytest's stdout is redirected to a file/pipe, the noise can swallow the final "N passed" counts line; count via `--collect-only -q` sums and `-rs` skip lines).
- Older torch installs or a torch without CUDA silently fall back to CPU torch references when a cuda device is requested (`resolve_torch_device` → None).
