# etl.bench — conformance & benchmark harness

## Intent

A standalone harness subpackage that runs curated example etl programs against pure-numpy references and — optionally — PyTorch references, reporting **precision** (conformance: max-abs/max-rel errors, pass/fail per reference) and **speed** (benchmark: best-of-N wall-clock ms per implementation + speedup ratios). It is a verification/measurement tool for the etl pipeline (`etl.build` + `etl.run`, or the explicit lower/compile/load path for transform-produced graphs), usable on **any registered backend and device** (default: numpy backend, CPU). Coverage spans three categories — **op** (73 examples: single ops and op-level compositions), **block** (17 examples: whole-block compositions), and **e2e** (7 examples: multi-run end-to-end procedures via the optional `Example.runner` path — `e2e_train_*` — plus in-graph control-flow inference examples — `e2e_infer_*`, T-token autoregressive decoding, PSO, k-means, power iteration). Each example also carries a tuple of **tags** (16 distinct: `micro`, `grad`, `vectorize`, `large`, `basic`, `control-flow`, `vmap`, `custom`, `xla`, `transformer_block`, `rnn`, `conv`, `mlp_block`, `optimization`, `train`, `infer` — in first-appearance order). It is not part of the etl runtime.

## torch-optionality constraint (binding)

- The etl project must NOT depend on torch: `import etl` / `import etl.bench` MUST always succeed without torch installed.
- torch is imported ONLY lazily inside function bodies (see `_torch.py` — `torch_available()` / `require_torch()`; every example's `torch_ref` factory goes through `require_torch()`). NEVER at module top level, never at import time.
- Missing torch → a clear `ImportError` mentioning `pip install etl[bench]` (never a raw `ModuleNotFoundError` escaping). `use_torch=True` / `--torch` require torch; `use_torch=None`/`--torch` default = auto (torch comparisons run iff `import torch` succeeds).

## API surface (public, via `etl.bench`)

- `conformance(examples=None, *, use_torch=None, tolerance=None, rtol=1e-5, atol=1e-5, seed=0, backend="numpy", device=None, **backend_options) -> ConformanceReport` — signature is STABLE. Per example: generate seeded inputs, stage (`stage_example`), `etl.run`, compare vs numpy ref (always) and torch ref (if enabled) with the documented rule: `tolerance=None` → allclose-style `|a-b| <= atol + rtol*|b|` per element (float64); numeric `tolerance` → `max_abs_error <= tolerance`. NaN fails. **Per-example tolerance resolution**: each `Example` may carry `rtol`/`atol`/`tolerance` overrides (all three independent); the effective value is the example's when not None, else the global argument. Effective values are recorded on each `ExampleResult` (`rtol`/`atol`/`tolerance` fields). The conformance table prints one compact **"tol" column** (between "torch" and "etl_ms"): "-" when the example used the global defaults, else `abs 1e-4` (tolerance) or `rtol 1e-3 atol 1e-3`. Per-example failures are recorded in the report (`error` field, `overall_pass=False`), not swallowed. **Examples without a torch reference are SKIPPED for the torch comparison when torch is enabled** (`torch_pass` stays `None`) — never an error, never a `ValueError`; `overall_pass` counts only executed comparisons (36 of the 97 registry examples deliberately have no torch ref: control flow, op_grad2, block_opt, op_xla, e2e_*, op_gather_scatter, op_stop_gradient, conv_block_stride2).
- `benchmark(examples=None, *, use_torch=None, repeats=20, warmup=2, seed=0, backend="numpy", device=None, **backend_options) -> BenchmarkReport` — best-of-`repeats` ms after `warmup` untimed runs for etl/[numpy]/[torch]; speedup = `reference_ms / etl_ms`. Tolerances do not affect benchmark. Same skip rule as conformance: examples without a torch reference are skipped for the torch timing (`torch_ms` stays `None`), never an error.
- **`examples` argument**: `None` → ALL registered examples; a string or iterable of **names AND/OR category names AND/OR tag names** (`"e2e"`, `"infer"`, `["micro", "matmul"]` — each entry expands via `expand_names`). **`expand_names` precedence per entry (binding): (1) category name → all examples of that category; (2) exact example name (an exact name wins over a same-named tag — `conformance(["mlp"])` runs the micro `mlp` example, not the block_mlp set); (3) tag name → all examples carrying that tag.** No tag collides with an example name (`mlp_block`/`transformer_block` are tag-only). `list_categories() -> list[str]` returns `["op", "block", "e2e"]`; `list_tags() -> list[str]` returns the 16 distinct tags in first-appearance order.
- `list_examples() -> list[str]`, `get_example(name) -> Example` (unknown → `UnknownExampleError` listing available names), `Example.generate_inputs(seed)` / module `generate_inputs(example, seed)`.
- **`Example` (frozen dataclass, 13 fields in order)**: `name, description, specs, graph, numpy_ref, torch_ref=None, rtol=None, atol=None, tolerance=None, category="op", inputs_fn=None, tags=(), runner=None`. `graph` is an `@etl.defn` (staged via `etl.build`) OR a plain callable `(*specs) -> Graph` (transform products — `etl.grad(...)`/`etl.vmap(...)` TransformCallables — staged via `example.graph(*specs) → Graph` then `etl.lower → etl.compile → etl.load`; see `stage_example` in `_util.py`; options go to BOTH lower and compile). `category` defaults to `"op"`. `inputs_fn(seed) -> list[np.ndarray]` overrides default RNG input generation (e.g. non-negative gather indices); `numpy_ref(inputs)` must return the same structure as `etl.run` (single ndarray or tuple; grads as a tuple matching the `argnums` subset); `torch_ref(inputs, device=None)` lazy; `tags` is a tuple of subgroup selectors; `runner` is an optional runner factory (see the runner contract below).
- **`backend`**: any registered etl backend name (validated up front via `etl.backends.get` — unknown names / missing adapter deps raise `core.BackendError` BEFORE any example runs; the CLI maps that to exit 2).
- **`device`**: `None` → `core.Device("cpu", 0)`; a `core.Device` (kind `"cpu"`/`"cuda"`); or a `"KIND[:INDEX]"` string. The report records the formatted device string.
- **`**backend_options`**: passthrough to `etl.build`/`etl.compile` (compile options for compiler backends). Device-derived default: any non-numpy backend without an explicit `target_backends` gets `["cuda"]` on a cuda device, `["llvm-cpu"]` otherwise. An explicit option always wins.
- Torch references run on the same device kind when it is cuda AND torch CUDA is available AND the index is within `torch.cuda.device_count()` (`resolve_torch_device`); otherwise CPU. Every `torch_ref` factory has signature `(inputs, device=None)`.
- Report types: `ExampleResult` (fields: name, description, max_abs_error, max_rel_error, numpy_pass, torch_pass, etl_ms, numpy_ms, torch_ms, speedup_vs_numpy, speedup_vs_torch, error, **rtol, atol, tolerance** — the last three = effective conformance tolerances used, None on errored/benchmark results), `ConformanceReport` / `BenchmarkReport` (fields include `backend: str = "numpy"`, `device: str = "cpu"`); `print_report(report)` and `str(report)` render human-readable tables — the header shows `backend=... device=...` ONLY when non-default. `to_dict()`/`to_json()` include the new fields naturally.
- CLI: `python -m etl.bench [--examples NAME[,NAME...]|CATEGORY[,CATEGORY...]|TAG[,TAG...]] [--conformance|--no-conformance] [--benchmark|--no-benchmark] [--torch|--no-torch] [--repeats N] [--seed N] [--backend NAME] [--device KIND[:INDEX]] [--backend-option KEY=VALUE ...]`; exit 0 = ok, 1 = conformance failure, 2 = usage error. `--examples` accepts names, categories, OR tags (help text lists the categories and tags dynamically). `--backend-option` values parse JSON-first with raw-string fallback; later duplicates override.

## Runner contract (binding)

`Example.runner(backend: str, device: core.Device, opts: dict) -> callable(inputs) -> outputs` — an optional runner FACTORY for multi-run end-to-end procedures (e.g. a Python-level training loop). It receives the resolved backend name, the resolved `core.Device`, and the resolved backend options dict (with the device-derived `target_backends` default already injected), and returns a RUN-CALLABLE taking the SAME inputs list as `generate_inputs(seed)` (a list of numpy arrays) and returning the same outputs structure as `numpy_ref` (single ndarray or tuple). The runner builds its executables ONCE (its own staging: `@etl.defn` → `etl.build(..., backend=backend, device=device, **opts)`; TransformCallable/Graph-builder → `graph(*specs)` → `etl.lower` → `etl.compile` → `etl.load`) and runs them N times internally (Python-level loops). **Runner bodies MUST NEVER call `stage_example` — `stage_example` routes examples with a `runner` straight to the runner factory, so calling it would recurse infinitely.** The harness uses the runner path for BOTH conformance and benchmark when set; `numpy_ref` mirrors the FULL procedure in pure numpy (same iteration count, lr, update rule). **Rationale (binding):** v1 has NO VJP rule for `if`/`while` (`TransformError: grad/vjp: no VJP rule for op 'if'|'while'` — probed), so grad-based training loops cannot live inside the graph; the runner moves the loop to Python, and each etl graph it stages contains only forward+backward ops (no control flow).

## Gradient & vectorize conformance design

- **`fd_gradient`** (base.py): per-element central finite differences, h=1e-4, ALL computation in float64 (inputs converted inside; value_fn receives float64 arrays); non-floating inputs → zero float64 gradient arrays; `sg_inputs` = indices whose perturbation is frozen (`frozen={i: original}` passed alongside the perturbed copy; value_fn models stop_gradient via `frozen.get(i, inputs[i])`). Every grad example's numpy_ref = fd gradient on the float inputs, returning ONLY the `argnums` subset (matching the `etl.grad` output structure).
- **FD-step sanity (measured)**: fd (h=1e-4, fp64) vs torch autograd agree max_abs ≈ 2.6e-6 (grad_mlp) and 1.2e-12 (grad_stopgrad); etl fp32 grads vs fp64 fd: grad_mlp 2.28e-6, grad_mix 3.41e-6, grad_stopgrad 1.8e-12, grad_structural 2.67e-7, op_grad2 all <= 1.5e-9 (numpy backend, seed 0) — hence rtol=atol=1e-3 per-example defaults (measured 8e-4 worst-case for matmul-MSE at grad magnitude ~4; all examples measure 2-3 orders below).
- **vjp-rule coverage**: the legacy grad set covers add, subtract, multiply, divide, power, remainder, maximum, minimum, abs, negate, square, sqrt, exp, log, log1p, sin, cos, tan, tanh, sigmoid, relu, sign (constant-regime term `sign(x1+5)` — gradient exactly 0, matching FD and torch; the rule still fires, which is the coverage point), cast, select, broadcast, dot, reshape, transpose, slice, pad, concatenate, sum/reduce_sum, mean/reduce_mean, max/reduce_max, min/reduce_min, prod/reduce_prod (frontend forms are sugar for the reduce_* IR ops), plus zero-grad less/equal/greater/logical_and; grad_stopgrad covers stop_gradient; grad_structural covers gather, scatter, solve; `op_grad2` extends coverage to erf, gelu, cumsum, tril, triu, fractional power, and the zero-vjp class through cast (grad_bitwise_zero); `op_custom` covers the explicit `block:<name>` vjp-rule registration path (custom_l2norm_grad) and the portable decomposition-diff fallback (custom_relu2_grad). NOT covered (one-line justifications): **conv** (documented v1 deferral — no transposed-conv op), **control flow** (`if`/`while`/`scan` — v1 deferral, probed), **argmax/argmin** (index outputs, zero-vjp), **bitwise_\*** and **logical_or/not/not_equal/less_equal/greater_equal** (same `_zero_vjp` class as the covered comparisons).
- **vmap design**: each example = per-sample `@etl.defn` + `etl.vmap(fn, in_axes=..., out_axes=0)` TransformCallable as `example.graph` (plain callable returning a Graph). v1: mapped axes leading; `None` in_axes entries supported (shared weights); `out_axes=1` is a v1 TransformError deferral (not registered). Per-sample formulations are **reshape-free** (per-sample rank-2 rows for dots — `etl.dot` is batched matmul rank>=2, and the exporter rejects per-sample reshape round-trips on the symbolic batch dim) and **size-one-dim-free** (v1's reduce-vjp broadcast-back sums away size-one dims via reduce_sum + dynamic reshape, which the exporter rejects — hence vmap_grad_mlp's [4,8] per-sample matrices). numpy_refs are hand-written per-sample loops — auto-vectorization is genuinely validated, and on the numpy backend the vectorized graphs match the manual refs EXACTLY (max_abs 0.0; vmap_softmax cross-checked against a manually batched `@etl.defn` with an IDENTICAL op sequence). `vmap_grad_mlp` uses the supported **vmap∘grad composition** (`etl.vmap(etl.grad(loss, argnums), in_axes=...)`) — literal `etl.grad(vmap(fn)(*specs))` is impossible in v1 (vmap'd output is the batched loss VECTOR, grad requires a scalar: ShapeError, documented). References: fd per-sample stacked; torch = autograd of the summed separable loss (sum, not mean, so the gradient is exactly the per-sample stack). iree (cpu) status: vmap_mlp / vmap_grad_mlp / vmap_linear / vmap_mlp_large COMPILE+RUN (measured max_abs 4.8e-06 / 6.9e-06 / 9.54e-07 / 9.2e-05); the rest are documented deferrals (see Known Issues).
- **conv2d_large torch ref** disables `torch.backends.cudnn.allow_tf32` inside the body: cuDNN TF32 (torch default for conv) degrades fp32 conv precision to ~0.036 abs on cuda (measured) vs 8.4e-5 with TF32 off — TF32 is a perf optimization, not fp32 semantics; the reference must stay accurate.

## Constraints

- Deps: stdlib + numpy + etl only (torch optional/lazy). CPU only for the reference path; GPU runs go through compiler backends. No edits outside `./etl/bench/`.
- Numpy conv references mirror etl's conv semantics exactly (VALID; SAME = TF convention `out=ceil(d/stride)`, pad split `(total//2, total-total//2)` per spatial axis — INCLUDING the negative-total CROP case, matching `etl/backends/numpy/kernels/linalg.py`; commit e7e37de).
- The numpy backend is CPU-only — its `load()` rejects non-CPU devices with an explicit `BackendError`; the harness does NOT special-case around that (the explicit error is the contract, recorded per-example).
- The harness NEVER selects a GPU implicitly — the caller chooses the device explicitly (`--device cuda:N` / `device=`). Operational GPU policy (runners, not the harness): scan first with `nvidia-smi --query-gpu=index,memory.free --format=csv,noheader`, use the most-free GPU, release promptly. etl `Device("cuda", N)` maps to iree device_id N+1 (1-based; verified empirically in `etl/backends/adapters/iree.py`).
- Argument errors (bad `backend`/`device`/`tolerance`/`repeats`/`warmup`, unknown backend, unknown example, `use_torch=True` without torch) raise up front; per-example EXECUTION failures (e.g. a backend's `BackendError` during build/run/compile) are recorded in the report — never swallowed, never crash the run.
- Budget (measured): default numpy/cpu full CONFORMANCE run = **97/97 PASS in ~11 s wall** (no-torch); adding the benchmark mode times each example (best-of-N). `e2e_train_transformer` is the slowest training example at ~65 ms/run (the heavy block examples are the slowest overall — e.g. `nbody` ~80 ms/run). iree cpu / cuda full runs ≈ 3-5 min (compile dominates; matmul sized 1024 for the iree cpu budget — see Known Issues).

Scan is STILL not registered: it lowers to gather/scatter IR, a documented StableHLO v1 export deferral, so compiler backends cannot run it — the suite covers the stable `if`/`while` surface only. NOTE for bench subagents: this core change landed as part of the bench expansion work; normally bench must NOT patch core — the fix is already in.

Consequence in the harness: `e2e_train_convnet` FREEZES the conv layers (the etl forward graph still runs the real conv ops every invocation; only the linear head trains via `etl.grad`) — a trainable conv is a core v1 deferral, not a bench-level choice.
- **vmap `out_axes=1` is a v1 TransformError deferral** (measured at dev time; no `out_axes=1` example is registered).
