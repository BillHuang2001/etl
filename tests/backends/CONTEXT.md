# tests/backends — backend-layer test suite
## Intent
pytest suites validating `etl.backends` (sibling: `../../etl/backends` — read its CONTEXT.md and `../../etl/CONTEXT.md` before changing expectations): the backend interface/registry/program contracts, the numpy interpreter backend (the numerical reference), the StableHLO exporter, and the iree / xla / tvm adapters.
Tests are the executable spec of the backend contract: graphs executed by the numpy backend must match direct numpy references computed with the SAME formulas as the kernels in `etl/backends/numpy/kernels/`.

## Conventions (binding for this directory)
- Run from repo root: `python3 -m pytest -q tests/backends` (the root `conftest.py` handles sys.path). Pure-lower/golden files are numpy-only, CPU-only, small shapes, <2 s; the adapter/parity/plugin files run REAL compilers or a gcc build (`test_adapter_{iree,xla,tvm}.py`, `test_iree_*parity*`, `test_iree_eigh_diag_parity.py` with n up to 100, `test_external_*iree.py`, `test_build_cache_iree.py`, `test_pjrt_*`/`test_xla_*`), so the <2 s rule does not apply there — keep compile counts low and reuse one compiled executable per graph.
- **Inventory (this HEAD):** 1233 tests collected across 38 reporting files — 1194 passed, 37 skipped, 3 xfailed, 0 failed, ~128 s (dominated by iree compiles); `test_adapter_xla.py` skips at import without a PJRT plugin (10 tests, 1 collection skip), so reported items = 1234. The 37 skips are 27 `nvidia-smi` cuda guards, 9 PJRT-plugin-absent xla items and that collection skip. The summary line is swallowed by iree nanobind atexit noise — read it via `2>/dev/null` or `--junit-xml`.
- **Compiler-free runs (no `iree`/`tvm`/torch/PJRT plugin):** every REAL-compiler leg skips through its per-test `pytest.importorskip`, while the helper-level fake-adapter legs must still PASS — a fake that only installs the submodule (no parent package) silently turns into a `ModuleNotFoundError` failure there. Measured: `test_options_override.py` = 82 passed / 11 skipped / 3 xfailed in a compiler-free env, 90/3/3 with `iree` present (tvm absent), 96 collected either way.
- Execute graphs via `etl.evaluate(fn, *args, backend=etl.backends.numpy_backend)` or `etl.build`+`etl.run`; results are `etl.Tensor` — unwrap with `.numpy()`.
- Numerical references re-implement the kernel formulas (never import etl kernels): `math.erf` for erf, `0.5*x*(1+erf(x/sqrt(2)))` for gelu, manual dilate→pad→cross-correlate loops for conv. Exact equality for int/bool; float32 rtol=atol=1e-6, float64 rtol=atol=1e-12; result dtype asserted.
- Documented etl quirks encoded as tests (do NOT "fix" etl here): `etl.slice` lengths are spans (limit = start+length, numpy `x[s:s+l:st]`); `solve` needs rhs `(..., n, k)` for batched `a`; getitem supports only static int/slice; `dot` requires rank ≥ 2; `etl.scan` desugars to while+gather+scatter at trace time (its stablehlo export error names `gather`).
- Shared state hygiene: the collective-executor hook and rank context are process/thread global — tests touching them use fixtures to save/restore.
- **Explicit device placement (binding).** A run input must ALREADY live on the executable's device: place it with `Tensor.to(device)` BEFORE `etl.run` — host ndarrays and cpu:0 tensors are rejected at the run boundary with `core.DeviceError` naming the input path (no implicit host→device transfer there) — and materialize outputs through the explicit `out.to(Device('cpu', 0)).numpy()` hop, since `.numpy()` on a non-cpu-kind payload raises `core.DeviceError`. llvm-cpu executables keep the UNCHANGED host-input path (raw ndarray / cpu:0 `core.Tensor` inputs via `asdevicearray`) with lazy per-call `.numpy()` on cpu-kind payloads.
- **ROCm/HIP placement** is the same model on the AMD target: gate GPU legs with `_rocm_guard.require_rocm()` (returns the etl `Device("rocm", 0)`), compile with `target_backends=["rocm"]` and run with `device=Device("rocm", idx)` (the iree `hip` driver's `device_id = idx + 1`; `"hip"` is the accepted etl alias, label preserved, so place inputs with `Tensor.to(Device("hip", idx))` for a `"hip"`-labelled executable). Mind the stage asymmetry `etl.build` hides: `target_backends` is a COMPILE-stage option (accepted-and-ignored at lower/load), so the explicit pipeline is `lower(graph, backend="iree", target_backends=["rocm"])` → `compile(lowered, target_backends=["rocm"])` → `load(artifact, backend="iree", device=rocm)`. ROCm uploads take the generic `iree.runtime.asdevicearray` path (no cuda-only persistent-staging tiers).
- **No `nvidia-smi` on the ROCm path** — never port the cuda suites' most-free-GPU scan to ROCm; use `_rocm_guard`'s `hip` capability probe. Keep GPU legs to short correctness checks (no timing) since the box may be shared.
- **Env-gating convention for adapter-fake tests (binding).** Where a test pins an adapter helper that internally does `import <dep>...` without needing a real compiler, the fake must be COMPLETE — install a fake top-level PACKAGE module (`types.ModuleType("<dep>")` with `__path__ = []`) in `sys.modules` as well as the submodule, otherwise the in-function `import <dep>.<sub>` raises `ModuleNotFoundError` before the submodule entry is consulted (a compiler-free environment must still RUN the test — never `importorskip` it). When the REAL package is already imported, patch its existing attribute (e.g. `runtime`) instead of clobbering the real module. Every install goes through `monkeypatch.setitem`/`setattr` so the sys.modules entries and attributes are restored on teardown; nothing leaks between tests. Reference implementation: `test_options_override.py::_install_fake_iree_runtime` (fake `iree` + `iree.runtime` + `iree.runtime.flags`).
- **Adapter test conventions** (`test_adapter_{iree,xla,tvm}.py` + `_adapter_utils.py`): each pins the SHARED `etl/backends/compiler.py` CompilerBackend contract and its adapter, is guarded by module-level `pytest.importorskip(<dep>)` calls BEFORE the etl imports, uses `NAME = "iree"/"xla"/"tvm"`, and shares every graph/input/tolerance via `_adapter_utils` (import as `from tests.backends import _adapter_utils as u`). fp32 parity tolerance is 1e-5 (cross-compiler), not 1e-6.
- **BUG(etl) policy:** when a test exposes a real etl bug, keep the assertions intact and report it upward with a minimal repro. Never fix etl and never weaken the test. Two equivalent mechanisms: a plain failing test with a `# BUG(etl): <description>` comment, or — where the node must stay green for sibling suites — `@pytest.mark.xfail(strict=True, reason="BUG(etl): …")` with the same comment above it (the assertions still exercise the CORRECT result and the pin XPASSes — failing loudly — the day etl is fixed, which is the signal to delete the marker). One pin remains in this node (see Known Issues).
- **Exporter-option goldens (eigh / split reduction):** pin markers from the ACTUAL emitted text and mind the quoting form — `stablehlo.remainder` is emitted bare/functional (count the UNQUOTED substring), while generic ops (`"stablehlo.while"`, `"stablehlo.reduce"`, `"stablehlo.transpose"`, `"stablehlo.if"`, `"stablehlo.slice"`) use the quoted custom-op form. Option VALUES are validated by the Writer (loud `BackendError` naming the accepted set), option KEYS by `options.validate_options`.
## Known Issues
- v1 collective-protocol limitations (asserted as-is): `reduce_scatter`'s `reduce_op` is not forwarded to the executor; `all_to_all` forwards only `split_axis`; `dist.broadcast` records the default `src_rank=0` in IR even when the user passes another value.
- **`split_reduction_threshold` / `split_reduction_non_exact` are exporter-only** (plumbing gap): the StableHLO Writer normalizes and honours them, but no adapter declares them in `KNOWN_OPTIONS["lower"]` and `CompilerBackend._exporter_options` does not forward them, so they are unreachable through `lower()`/`build()` (loud unknown-option `BackendError`). Consequence: `test_split_reduction.py` drives them by calling `stablehlo.export(graph, options=...)` directly, `test_iree_split_reduction_parity.py` goes through the real adapter via a file-local `_compile_with_exporter_options` helper (export with options → swap `mlir_text` into a `LoweredProgram` → compile/load), and `test_options_override.py::test_split_reduction_sub_options_forwarded_through_lower` pins the DESIRED public plumbing as a strict xfail (3 parametrized cases = the node's 3 xfails). Only the plain `split_reduction` and `eigh_algorithm` keys are plumbed.
- **`eigh_algorithm` / `split_reduction` env rows live outside this node:** `etl.pipeline_options.ENV_OPTION_TABLE` holds three `(backend, "lower")` rows (`iree`/`xla`/`tvm`), each with `ETL_EIGH_ALGORITHM` → `eigh_algorithm` (value validated by the Writer: `jacobi` | `jacobi_batched`) and `ETL_SPLIT_REDUCTION` → `split_reduction` (`normalize_bool_option`), applied by `pipeline.lower` with explicit-kwarg > env > adapter-default precedence; their env-half tests are in the sibling `tests/test_pipeline_options.py`. This node covers only the explicit-kwarg/exporter plumbing, and the two sub-knobs above have NO env row.
