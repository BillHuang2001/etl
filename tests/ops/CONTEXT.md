# tests/ops — frontend tensor-operation contract tests

## Intent

pytest suite asserting the op contracts in `../../etl/ops/CONTEXT.md` and `../../etl/CONTEXT.md` (siblings — read-only). Each test traces a small function via `etl.trace` (plain fn or `@etl.defn`), inspects the built IR (op name, effect, attributes, result `ValueType`s, SymbolicTensor dtype/shape, locations), evaluates numerically via `etl.evaluate` (numpy backend), and checks the documented error paths (`TraceError`/`ShapeError`/`DTypeError`/`TypeError`, no silent fallback).

`conftest.py` provides shared helpers (no per-file duplication): `trace_fn(fn, *specs)`, `ops_of(graph, name=None)`, `run_numpy(fn, *args)`. Its docstring holds the stable IR-inspection facts (`graph.module.functions[0].region.blocks[0].ops`; `Op` fields `.name/.operands/.results/.attributes/.effect/.location`).

## Notes for agents

- Keep tests small/fast (CPU only, shapes ≤ ~256×256); `pytest.raises(..., match=...)`, `pytest.warns`/`recwarn`, heavy parametrization.
- A real etl bug contradicting the documented contract must NOT be papered over: keep the test plain-failing with `# BUG(etl): <one-line description>` and report a minimal repro; the parent delegates etl fixes (this dir is read-only w.r.t. etl).
- Contract divergences that turned out to be *documented* behavior are tested as such (e.g. `ops.dot` is rank-≥2 only; numpy-scalar and `Dim`-valued getitem keys are non-static → TraceError; float scalar + int tensor → float64 per NEP-50/result_type, NOT float32; `diag` rank>2 and `tile` negative reps raise ShapeError where numpy raises ValueError; `linspace`/`eye` accept only static Python numbers — symbolic bounds are a documented v2 deferral).
- Locations: for pretty_print equality, set `ETL_DISABLE_LOCATIONS=1`; for location assertions, user-frame calls in plain fns and `@etl.defn` both capture real `file:line` in `Op.location`.
- Compiler-adapter tests in this suite are env-INDEPENDENT by default: PREFER installing the real adapter singleton directly into `etl.backends.registry._registry` for the duration of the test (a `@contextlib.contextmanager` helper that imports the module named by `registry.OPTIONAL_ADAPTERS[name]`, reads `getattr(module, f"{name}_backend")`, saves the previous entry, assigns, and restores — or `pop`s when there was none — in `finally`; same save/restore mechanism as the `iree_stub_registered` helpers in `tests/pipeline_env_defaults_test.py` and `tests/test_pipeline_options.py`). Adapter MODULES obey the repo's heavy-import rule (no compiler at module scope; `iree`/`iree.compiler`/`iree.runtime` are lazy in-function imports) and `CompilerBackend.lower` never compiles, so bypassing only the `register()`/`check_available()` probe lets adapter capability/lower contracts be asserted STRICTLY in every environment — no `pytest.skip`, no weakened `match=`. The `pytest.skip`-on-adapter-missing pattern (`tests/ops/test_external_call.py`, `tests/sparse/test_backends.py::test_sparse_op_defers_on_tvm`) is reserved for paths that genuinely require a real compiler at run/compile time.
