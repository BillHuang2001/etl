# tests — etl test suite

## Intent

pytest suite validating the `etl` package (sibling — see `../etl/CONTEXT.md` for the API contract being tested). Tests are the executable spec of design principles: explicitness, no hidden magic, local-tensor semantics, sugar transparency.

## Structure

Mirror the package: `tests/core/`, `tests/ir/`, `tests/ops/`, `tests/numpy/`, `tests/trace/`, `tests/block/`, `tests/transforms/`, `tests/backends/`, `tests/dist/`, `tests/persist/`, `tests/bench/` (`etl.bench` harness — see its own CONTEXT.md), plus:

- `tests/pipeline_test.py` — end-to-end staging pipeline (trace→lower→compile→load→run), bind, build, evaluate; run/bind **boundary device enforcement** (explicit placement, R5): every input tensor must already live on the executable's device — a cuda-kind tensor (fake duck-typed payload, no GPU) fed to the cpu executable raises `DeviceError` naming the input pytree path (`input at path [0]['b'] is on device Device(kind='cuda', index=0), but the executable runs on device ...` — nested-path variant included) with the `t.to(...)` remedy; raw host ndarrays auto-wrap as cpu:0 and run fine, and the explicit `t.to(cpu)` transfer unblocks the foreign tensor (positive control)
- `tests/pipeline_env_defaults_test.py` — process-wide backend/device defaulting env vars (`ETL_BACKEND`/`ETL_DEVICE`/`ETL_TARGET_BACKENDS`) for `etl.build`/`etl.evaluate`: explicit kwargs win, env read lazily at call time, stub-backed full-path tests (registered `"iree"` stub; never imports a real adapter)
- `tests/test_pipeline_options.py` — per-backend option env vars (the options-override env half, `etl.pipeline_options.apply_env_options`/`ENV_OPTION_TABLE`): per-stage application (`ETL_IREE_COMPILE_ARGS` at compile, `ETL_IREE_RUNTIME_ARGS` at load), explicit > env > default precedence, empty/whitespace = unset, lazy per-call reads, tvm target + pass-configs JSON, xla base64 decode, malformed values → `BackendError` naming var+value, unknown backend no-op, **`ETL_OPT_LEVEL`** (the first etl-defined+etl-validated option — applied at the compile stage of every compiler backend normalized to int 0..3, explicit kwarg wins, malformed → `BackendError` naming the variable and value, blank = unset, numpy no-op, stage-scoped; full-path through the registered iree stub: env value reaches compile as `opt_level=2`, explicit kwarg beats env); **the `lower` stage** — `ENV_OPTION_TABLE`'s key set is exactly the 7 documented `(backend, stage)` pairs (iree compile/load/lower, xla compile/lower, tvm compile/lower), and each `(_, "lower")` row holds exactly two entries: `ETL_EIGH_ALGORITHM` → `eigh_algorithm` (whitespace stripped; the stablehlo Writer validates the VALUE — `jacobi` | `jacobi_batched`, Writer default `jacobi_batched`, so an invalid value surfaces at `etl.lower(...)` as `BackendError` `invalid eigh_algorithm option 'banana' (expected one of jacobi, jacobi_batched)`) and `ETL_SPLIT_REDUCTION` → `split_reduction` (a real `bool` through `etl.backends.options.normalize_bool_option` via its lazy in-function import — `1/0/true/false/yes/no/on/off`, case- and space-insensitive; garbage → `BackendError` naming the variable, the value and the accepted forms, never the `bool("0") is True` trap); rows are `lower`-scoped only (compile/load/run and `numpy`/`None` stay `{}`), explicit kwarg beats env per key, blank = unset, and the autouse `_clean_option_env` fixture clears every var the module drives; two gated END-OF-FILE pins drive the real iree adapter through `etl.lower(g, backend="iree", target_backends=["llvm-cpu"]).payload["mlir_text"]` — a (10,10) f32 `eigh` graph is 148 lines by default and 132 under `ETL_EIGH_ALGORITHM=jacobi`, that text being byte-identical to `stablehlo.export(g, options={"eigh_algorithm": "jacobi"})`, and a (10001,) f32 `reduce_min` graph emits 1 `stablehlo.reduce` / 0 `// etl split reduction:` markers under `ETL_SPLIT_REDUCTION=0` (byte-identical to explicit `split_reduction=False`) vs 2 reduces / 1 marker under `=1`; stub full-path tests (compile args reach compile, runtime args reach load, run options forwarded, numpy documented-ignore, `BoundExecutable.backend`); every other test stays adapter-free — the shared per-test import guard is described in Notes for agents — and the backend half is `tests/backends/test_options_override.py` (+ the 53-test `tests/backends/test_opt_level.py` port)
- `tests/test_build_cache.py` — unit coverage for the `build_cached`/`CompileCache` memoized-build sugar (`etl.build_cache`): the cache key is computed BEFORE any tracing from (fn identity with keepalive, the full `*specs` tree incl. static content, resolved backend name, resolved device, canonicalized options); key sensitivity, per-call env defaults resolution (malformed-value errors count NO miss), LRU eviction/`clear()`/counters, error propagation (trace-time failures never cache, unencodable static leaves → pre-cache TypeError naming the component path, `cache=` type checks, non-callable/Graph `fn` rejection), zero pipeline work on hits (monkeypatched `etl.pipeline`/`etl.trace` spies), thread-safety (concurrent distinct-key compiles + the same-key race — first-insert-wins), static args stay in the run signature; pure numpy except a guarded iree-llvm-cpu leg (31 tests)
- `tests/test_meta_programming.py` — genetic-programming end-to-end for `build_cached` (5 tests): a miniature GP harness generates random arithmetic expression programs ENCODED AS TENSORS (a small `@etl.defn` over `etl.random.randint`, key-based deterministic), prefix-decoded Python-side into static int-only tuple trees; each DISTINCT program is built once through `build_cached` (keyed on the tree's static content BEFORE tracing) and its executable is reused across an inner evaluation loop; asserts `cache.misses` == #distinct trees, repeated and REGENERATED identical programs hit with the SAME executable object, a different TensorSpec misses, and every executable matches a pure-numpy reference tree evaluator; numpy default + iree-llvm-cpu (function-local importorskip) legs
- External-kernel suites (the `etl.external_call` custom-kernel path): `ops/test_external_call.py` (registry semantics incl. the device-resident registration contract — `device_resident=True` requires an explicit backend, non-bool → TypeError, `get_external_kernel_entry` `(callable, mode)` tuple semantics with default-slot fallback, re-registration overwrites callable AND mode, `ExternalKernel.impl` direct/decorator device forms, device registration under non-iree backend strings allowed; op building, dispatch, validation errors, TransformError, cond/while bodies, save/load, stablehlo deferral) + `ops/test_external_rules.py` (per-backend registry + default-slot fallback, `ExternalKernel` handle, portable validation, fallback-rule installation, grad/vjp/vmap through portables, unregister semantics), `backends/test_external_call_iree.py` (split + host-dispatch, per-backend slot resolution at run, once-per-executable staging warning; device-resident dispatch round — device tensors in/out via the public `IreeDevicePayload`, second-vmfb-on-the-operand's-HAL-device interop, numpy/mixed/`core.Tensor`/duck-payload returns, metadata-only validation with canonical errors, fully-device-resident boundaries emit zero staging warnings, cuda GPU-guarded bit-exactness + operand residency) + `backends/test_external_portable_fallback.py` (tvm-gated: portable-inline fallback with warning, no-portable BackendError, result-spec validation), `block/test_portable_vjp_regression.py` (fixed post-inline-seeding vjp fallback incl. constant-in-portable)
- `tests/test_spec_compliance.py` — design-principle compliance:
  - no implicit tracing/eager mode: ops outside a trace → TraceError; direct `Defn` call raises helpfully
  - closure-captured Tensor in ops → TraceError; `etl.constant` opt-in works (warns above `ETL_LARGE_CONSTANT_BYTES`)
  - `SymbolicTensor` has no `.numpy()` / `__dlpack__`; `bool(symbolic)` → TraceError
  - `etl.build`/`evaluate` = documented shorthand (same result as explicit pipeline); stage types distinct, wrong stage → TypeError
  - `bind` never alters graph/compile; missing/wrong-named binding fails
  - `vmap(f, in_axes, out_axes)` ≡ `vectorize` on the traced function (same IR up to naming)
  - concrete creators (`etl.zeros`) return Tensors with DLPack (+ torch interop via importorskip); `enp.zeros` inside defn produces a graph op
  - serialization round-trips for Graph/LoweredProgram/CompiledArtifact; corrupt file fails
  - Python values → Python semantics (static specialization; `if etl.sum(x) > 0` fails at trace)
  - collectives (`etl.dist.*`) are explicit IR ops only — no implicit insertion
  - explicit device placement (`TestExplicitPlacement`, group 15, 7 tests): placement is explicit — host memory cannot be relabeled (`Tensor`/concrete-creator `device=` non-cpu → `DeviceError`), `.numpy()` on a non-cpu-kind payload raises (no implicit device-to-host transfer), `Tensor.to` is the only transfer API (same-device → self; to-cpu materializes a fresh host copy), and the run/bind/`etl.constant` boundaries reject foreign-device tensors with the explicit-transfer remedy
  - sparse explicitness (`TestSparseExplicitness`, group 14, 21 tests): sparse tensors obey the SAME discipline — ops/converters build IR inside a trace (no eager numerical mode), polymorphic creators take concrete OR symbolic components but never a `TensorSpec` or a mix, symbolic sparse leaves have no concrete escape hatches, `etl.constant` is rejected, closure-captured sparse values raise, static leaves are snapshotted and run-validated, `etl.evaluate` derives a `SparseTensorSpec` from concrete args, and the v1 deferrals are explicit (sparse@sparse matmul, whole-sparse `bind`, some vjps)
  - error messages include source locations (`file.py:line`)

## Constraints

- CPU only; numpy backend is the reference for correctness.
- torch-dependent tests use `pytest.importorskip("torch")` (interop is optional).
- No GPU usage. No network. Keep tests fast (<2s per file, no large shapes beyond ~256×256 unless needed).

Tree/pytree UX coverage (validated green against the tree-UX implementation in `../etl/`, no skips/xfails):

Explicit device placement coverage (validated green; no GPU needed for the core pins — duck-typed fake payloads stand in for device-resident buffers):

## Notes for agents

- **IREE 3.12 toolchain validation (rc20260905, tools /tmp/iree312/, runtime wheel /tmp/iree_rt312_x/):** the 3.12 compiler builds NSGA2/MOEAD while-loop graphs fine (no SIGSEGV), but the 3.12 runtime has two run-time failure modes: (1) **local-task driver** fails on BOTH NSGA2 and MOEAD with `transient_buffer.c:80 FAILED_PRECONDITION; transient buffer has not been committed ... hal.fence.await` (new 3.12 transient-buffer machinery; NSGA2 at bytecode module@2:3234, MOEAD at module@4:5308), while **local-sync executes NSGA2 successfully** (the 3.12 Python binding works under `driver='local-sync'`: `rt.load_vm_flatbuffer(open('/tmp/bisect/nsga2_312b.vmfb','rb').read(), driver='local-sync')` then `m.main(*np.load(...) for i in range(10))` — same numerics as iree-run-module); (2) **MOEAD additionally fails under local-sync** with `ref.h:223 INVALID_ARGUMENT; ref is null` at `hal.buffer_view.create` (bytecode module@4:7160, resume PC of the failing buffer_view.create after `hal.fence.await`) — invariant across default/O0 opt levels, `async-internal` execution model, and flags (3.12 MOEAD wrapper has 5 `execute.indirect` sites vs 3 in NSGA2; the 3.9-compiled MOEAD has none and works). **3.12 numeric result of NSGA2 is NOT a miscompile**: O0 and O3 outputs are bit-identical, and vs the 3.9/numpy ground truth the apparent maxdiffs (0.93/1.74/4.0/nan on out0–out3) are a **row-permutation artifact** — the selected set is IDENTICAL (100/100 out0 rows match exactly, injectively), out1 matches within 2.4e-7 after permutation, out2 ranks are 100/100 consistent per individual (zero rank flips, same front histogram), out7 noise is 1–15 ulps; only the sort ORDER of equal-front individuals differs. **3.9.0-compiled artifacts CANNOT load on the 3.12 runtime even with the v15→v17 bytecode patch**: `vm/context.c:287 INTERNAL; import function hal.command_buffer.dispatch signature mismatch ... expected 0rriiiiICiDCiirIID_v but got 0rrIiiiICiDCiirIID_v` — the HAL import ABI changed in 3.12. **Pure-pinned fallback verified:** iree-compiler 3.9.0 + iree-base-runtime 3.9.0 (cp311 manylinux_2_28 x86_64 wheel from PyPI; ships `iree/_runtime_libs/iree-run-module`, run with `LD_LIBRARY_PATH=<extracted>/iree_base_runtime.libs`) executes the UNPATCHED 3.9.0-compiled NSGA2/MOEAD modules under local-task with FULL parity vs the numpy ground truth (NSGA2: 8/10 outputs bit-exact, out1/out7 ≤2.4e-7; MOEAD: 9/12 bit-exact, out1/out9 ≤2.4e-7, out2 ≤2.4e-8) — no bytecode patch needed when compiler and runtime versions match.
- **IREE toolchain gotcha (MO while-loop graphs):** the installed iree-compiler 3.10.0/3.11.0 SIGSEGVs when compiling NSGA2/MOEAD-style `stablehlo.while` graphs from evox_etl (100x3x10 and 1000x3x30, llvm-cpu). iree-compiler 3.9.0 (extracted wheel at /tmp/iree3_9_0_x) compiles them fine, but emits VM bytecode v15.0, which the 3.11 runtime rejects at load: `INVALID_ARGUMENT; bytecode version mismatch; runtime supports 17.0, module has 15.0` (verifier.c:180 — major version must match exactly). Verified workaround: patch the `bytecode_version` u32 field in `module.fb` inside the vmfb zip from `0x000F0000` to `0x00110000` (raw offset 64+56 for NSGA2-100x3x10, 64+52 for MOEAD-100x3x10 — locate by pattern search, not by zip central-directory offsets). The patched artifacts then LOAD and RUN under the 3.11 runtime with full numpy parity (floats max-abs ≤ 2.4e-7, ints bit-exact). Do NOT repack the vmfb zip with python zipfile — the flatcc verifier requires the member at a 64-byte-aligned offset ("buffer header not aligned"); patch in place instead.
- **GPU environment & ROCm detection:** on the AMD Instinct MI300X VF box (ROCm 7.1, gfx942) there is NO NVIDIA GPU and no `nvidia-smi`, so every cuda-guarded suite skips while the ROCm suites (`backends/test_iree_rocm_device_resident.py`) run. Keep ROCm GPU work to short correctness checks: the GPU is shared with other agents, so do not add timing/benchmark tests there.
