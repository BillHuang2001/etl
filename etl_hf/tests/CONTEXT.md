# etl_hf/tests — colocated pytest suite for the `etl_hf` package

## Intent

Colocated test suite for `etl_hf`: the package is a separate top-level distribution, so its tests live here rather than under `./tests/`, which mirrors the `etl` package only (`pyproject.toml` `testpaths = ["tests", "etl_hf/tests"]`, package list `include = ["etl*"]` with `etl_hf.tests` excluded).
The suite pins the **external** contracts: config parsing, checkpoint reading, canonicalisation, graph assembly, whole-graph export, compiled parity, and parity against an independent oracle.
It also pins the **functional shape of the public API** — a loading half (`etl_hf.load`), a compute-function half (`etl_hf.program`) and a staging half (`etl_hf.pipeline`), joined only by ordinary values (`ModelConfig`, a host params dict, an `@etl.defn` forward, an `Executable`).
Everything runs offline and numpy-only by default — no torch, no compiler — so the contract is verifiable on a bare `uv run --with pytest` install; only the guarded checkpoint readers touch the network.

## Test Strategy

`test_config.py` pins per-family `config.json` parsing: `llama`/`mistral`/`qwen2` routing, GQA/MQA head counts, `num_key_value_heads` defaulting, derived vs explicit `head_dim`, RoPE/`rms_norm_eps` defaults, GPT-2 `n_*` key normalisation (`n_inner: null` → `4·n_embd`, `activation_function` fallback, tie defaulting true) — plus `from_dict`/`from_json`/`from_dir` agreement, `digest` stability/order-independence, frozen-ness, `raw` excluded from equality, and an explicit-error table (missing/non-positive/non-integer fields, `hidden_size % heads`, `heads % kv_heads`, bad `head_dim`, non-bool tie, `rope_scaling` rejection, non-dict payload).
`test_weights.py` drives the readers from locally written files: safetensors round-trip bit-exactness (dtypes, scalars, empty shapes, metadata, writable arrays, corrupt header/offset/shape/dtype), the torch **zip** reader (offsets and strides incl. negative-stride views, empty tensors, bf16/f16 storages, `_rebuild_parameter` and `{"state_dict": …}` unwrapping, unknown storage type, arbitrary pickled globals rejected, non-tensor entries rejected) and the **legacy** reader (`_LEGACY_MAGIC` + `_LEGACY_PROTOCOL` 1001, per-storage int64 element count prepended to each blob, trailer-key order, truncated/unknown-key rejection) — then `load_checkpoint`'s candidate order, safetensors preference, direct file paths, shard/index error paths, the float32-widening policy and parameter counting.
The whole torch-format surface is exercised **without torch**: a `pickle.Pickler` subclass emits real torch storage persistent ids and `torch._utils._rebuild_tensor_v2` globals through fake `torch`/`torch._utils` modules registered in `sys.modules` for the duration of the pickle and always removed again.
`test_reference.py` validates the oracle against hand-written float64 formulas (softmax incl. axis 0, biased-variance LayerNorm, mean-free RMSNorm, SiLU/tanh-GELU/erf-GELU/ReLU, the exact additive causal mask, RoPE tables and `rotate_half`, attention vs a brute-force triple loop incl. GQA and mask broadcasting, `param_count`), asserts `MASK_NEG` really underflows `exp` to 0 in f32, and pins that the module imports **no** `etl` graph code (`import_lines == ["from etl_hf.errors import HFUnsupportedError"]`).
`test_ops.py` builds every composition (`softmax`, `layer_norm`, `rms_norm`, activations, `causal_mask`, `rope_cos_sin`, `rope_tables`, `apply_rope`, `split_heads`, `merge_heads`, `repeat_kv`, `_common.linear`/`attention`/`gated_mlp`/`two_layer_mlp`) as a real graph through `etl.evaluate` on the numpy interpreter and compares against an expectation computed **in the test file** (no `etl_hf.reference` import) — pinning graph *semantics* rather than a reference against itself.
`test_llama.py` / `test_gpt2.py` pin each family twice: numeric parity of `run(build(forward_fn(cfg, seq_len=…, batch_size=…), cfg), params, ids)` against `reference_logits(cfg, params, ids)` (GQA/MQA/MHA, batch 2, layer counts, sequence lengths, tied and untied heads, activation variants, explicit `head_dim`, `rtol=1e-5`/`atol=1e-6`, plus a non-collapse guard on the oracle), and canonicalisation exactness (key set, `(in_features, out_features)` orientation, values, tie resolution, ignored buffers, and one explicit error per failure mode: unexpected/missing key, llama bias, wrong shape, wrong fused-QKV width, position-table mismatch, foreign-family config).
`test_families.py` is about consistency rather than numerics: registry keys ↔ `FamilySpec.name`, read-only mapping, frozen specs, spec callables being the family modules' own functions, `model_types` agreeing with `FAMILY_BY_MODEL_TYPE` and each module's `MODEL_TYPES`, `families.__all__` being exactly `{FAMILIES, FamilySpec, family_for_model_type, get_family, resolve_family}`, `get_family`/`family_for_model_type` failing with `HFUnsupportedError` naming the supported set, and a subprocess pin that importing the registry pulls in no optional dependency.
`test_build.py` covers the two staging modules end-to-end from synthetic configs, synthetic param trees and a hand-written safetensors checkpoint directory (no download, no torch, no `safetensors`) — parity of `build`+`run` vs `reference_logits`; the documented default-option matrix of `pipeline.resolve_build_options` (llvm-cpu flags, `opt_level="O3"`, the all-ROCm `"O1"` rule, "explicit wins", `ETL_OPT_LEVEL`/`ETL_BACKEND`/`ETL_TARGET_BACKENDS` env defaults, the caller's dict never mutated, numpy returned unchanged); memoisation (`forward_fn` identity per `(family, cfg.digest, seq_len, batch_size, pack_weights)` with `_GRAPH_CACHE_MAX`-bounded cache, one `Executable` per specialisation, a private cache isolating); the **static specialisation** (`seq_len`/`batch_size` belong to `forward_fn`, junk is rejected there, and an explicit-but-disagreeing value passed to `build` is rejected rather than silently building a mismatched ids spec); the pre-trace erf-activation gate; explicit input handling (integral ids → int32, `DTypeError`/`ShapeError` otherwise, an `etl.Tensor` of ids forwarded to `etl.run` **verbatim**, etl's pytree errors propagating untouched); `place_params`/`place_ids` as one visible `Tensor.to` per leaf plus their error tables; `predict` as the ONE host-facing shorthand (device params refused with the device-resident recipe named via a metadata-only `_FakeDevicePayload` that raises if `to_host()` is called); and `load_hf`/`LoadedModel` (data record, documented default `seq_len` living on the forward, explicit errors).
`test_public_api.py` pins `import etl_hf` in a fresh **subprocess** (numpy + `etl` only), `__all__` completeness/duplicate-freedom/reachability, docstrings and documented arguments, star-import equality, submodule attributes and importability, the error hierarchy under `etl.core.ETLError`, and the functional-design invariants: `HFModel`/`build_model`/`run_model` exist nowhere in any submodule, `etl_hf.build` is a **function** of `etl_hf.pipeline` while `etl_hf/build.py` is deleted and unimportable, `load_hf` returns a plain `LoadedModel` NamedTuple (no methods, no `seq_len`), `load_config` + `load_params` reproduce `load_hf` exactly (same digest, keys, array-for-array values), `forward_fn` is memoised and captures **no** parameters (traces from `param_specs` alone, `len(param_specs) + 1` graph inputs), the staging stages are distinct public functions, `build` is memoised, `run` returns a `Tensor` on the executable's device, and `reference_logits` agrees with a numpy-backend forward.
`test_export.py` proves the "one graph" property at the IR level with numpy only: each family module's `graph(cfg, seq_len, batch)` is traced against its own `param_specs(cfg)` + an int32 ids spec, verified, and exported through `etl.backends.stablehlo.export`, then the text is checked for the whole forward's constructs (attention dots, reductions, softmax exp, in-graph RoPE `cos`/`sin`, RMSNorm `sqrt`/`divide`, SiLU logistic, causal compare, embedding gather) with deliberately loose lower-bound op/line counts; "weights are inputs, not payloads" is pinned structurally (`tensor_specs == params + 1`, a `stablehlo.constant` ceiling, an O(`seq_len`) bound on the largest literal), plus determinism, config sensitivity, layer-count scaling and a static batch extent at `batch_size=2`. Its `_count_ops` helper is imported by `test_real_checkpoints.py`.
`test_iree_llvm_cpu.py` proves the same property behaviourally on `iree`/llvm-cpu for both families and a real `tiny_llama` checkpoint: parity of `run(build(forward_fn(...), cfg, backend="iree"), params, ids)` vs `reference_logits` *and* vs the numpy interpreter, bit-identical reruns, the one-program structure (one compiled entry function, no `external_call`/`runtime_call` ops), and the two measured plumbing pitfalls — `iree_compile_args` must reach `etl.compile` (pinned by spying on `etl.pipeline.compile`, never by timing) and llvm-cpu needs `--iree-llvmcpu-target-cpu=host` (the pure-options test is ungated).
`test_pack.py` pins the packed-weights mode: shape-driven `(dtype, rank, shape[1:])` bucketing (input counts per family and tie state, every canonical key covered exactly once, contiguous prefix-sum offsets, dtype/device preserved), plan determinism and rejection table, the host `pack_params(plan, params)` → in-graph static-slice round trip being bit-identical per key, packed-vs-unpacked logits bit-identical on numpy and within `1e-6` on `iree`/llvm-cpu, unpacked staying the default, `run` mismatch errors in both directions, the "no baked weights" export bounds, `predict(loaded, ids, pack_weights=True)` end-to-end, the pack→place leaf-count reduction, the `_pack_plan_for` memo, and the real-size packed plan (3 inputs from 196 keys) under `ETL_HF_BIG=1`.
`test_iree_rocm.py` pins the **GPU** leg on this host's AMD MI300X (gfx942, ROCm 7.1) through the documented recipe `load_hf` → `forward_fn` → `build(..., backend="iree", device=Device("rocm", 0))` → `run(exe, place_params(...), place_ids(...))` → ONE explicit `.to(cpu)`: the all-ROCm `opt_level="O1"` default vs llvm-cpu's `"O3"`, ROCm visibility with the 1-based HAL `device_id`, device-resident forwards for `tiny_llama`/`tiny_gpt2` with parity vs the numpy interpreter **and** the stored goldens (relative-to-absmax tolerances), host params/ids rejected at the run boundary with `etl.DeviceError`, the same-device loop (bit-identical outputs, `asdevicearray` spy = 0 calls, outputs still device-resident), packed-vs-unpacked device parity, `dot_precision="HIGHEST"` as a true-fp32 no-op, and the `ETL_HF_BIG`-gated `distilgpt2` / 124M `gpt2` packed device-resident cases (4 declared inputs, 3 staged leaves, 5 / 10 bit-identical runs).
`test_real_checkpoints.py` is the guarded real-checkpoint suite (`require_model` download → `load_hf` → `forward_fn`/`build`/`run` → `reference_logits`; loading knows nothing about `seq_len`): real config values, canonical key/parameter counts, the tied contract on real weights (a tied tree carries exactly one embedding array and **no** `lm_head.weight`, so `tiny_gpt2` is 36 keys / 102,714 params), `inputs == keys + 1` (weights are always explicit inputs), traced op count, export size with zero compiler, logit parity, explicit float32/no-guessing placement, and a loudly-failing mutated config — including `sshleifer/tiny-gpt2` (legacy-format checkpoint, ordinary ~0.1285 logits) and an exact-erf `tiny-random-Mistral` that runs numpy-backend-only; a `ETL_HF_BIG=1`+iree-gated case pins the packed-124M payoff (3 `packed.*` inputs, element count equal to the canonical 124,439,808, 12 consecutive bit-identical runs, parity vs numpy and the `gpt2` golden).
`test_torch_oracle.py` is the optional **external** oracle (real `transformers` + `torch`, CPU) that can catch a canonicalisation bug both etl_hf implementations would share: golden-fixture parity (`../bench_logs/hf_goldens/`), in-process HF-forward parity (1e-4 abs for tiny checkpoints, 1e-3 abs **and** 1e-5 relative for real-size ones), strict fixture-format validation, and `test_etl_hf_never_imports_torch`.
Its oracle is gated lazily (`_oracle_available()` probes `importlib.util.find_spec` for the `skipif`, `_oracle()` imports and caches the pair inside a test), so its eight torch-free cases (five golden parities, `test_golden_slugs_resolve`, the fixture-format check, the import-hygiene check) collect and run without torch.
Golden→checkpoint resolution is **strict**: only `hf_download.DownloadUnavailable` may skip, while an unmappable golden raises `AssertionError` naming the slug, its `<slug>.meta.json` and the contract — an unexercised golden is a red test, never a silent skip.

## How to run

`pytest` is not in the base uv environment: `uv run --with pytest python -m pytest etl_hf/tests -q` (add `--extra iree` for the compiled path, `uv run --isolated --extra iree …` for GPU work — the base env has no iree, so `etl.devices()` shows only cpu).
Prefer `--junit-xml` for authoritative counts: iree's nanobind teardown can abort at exit and swallow pytest's `-q` summary line; also export `PYTHONUNBUFFERED=1` on a GPU host so buffered `print()` diagnostics survive a redirect.
Never assert timings (the GPU is shared): every measured number lives in a module-level `MEASURED` dict or an assertion message (`test_export.py`, `test_iree_rocm.py`, `test_iree_llvm_cpu.py`, `test_real_checkpoints.py`).
Use `$TMPDIR` (never `/tmp`) for downloads and scratch files, and never write into `./bench_logs/` or `./etl/` — both are out of scope for this package.

## Network and environment gates

Network access is guarded two ways and never fails a run: `hf_download.require_model` converts any `DownloadUnavailable` into `pytest.skip` (`test_real_checkpoints.py`, `test_torch_oracle.py`, `test_pack.py`, `test_iree_rocm.py`), while `test_weights.py`'s own `_download` helper returns `None` on failure and the test skips.
An offline machine therefore reports every checkpoint test as skipped, never failed and never hung.
Checkpoints are cached under `$ETL_HF_MODELS_DIR` when set, otherwise `$TMPDIR/etl_hf_models`; a cached file is trusted only when it is non-empty and, for `*.safetensors`, when its 8-byte header length parses and fits inside the file.
`ETL_HF_BIG=1` re-enables 6 real-size cases across `test_real_checkpoints.py`, `test_iree_rocm.py` and `test_pack.py`; each additionally guards memory (`/proc/meminfo` `MemAvailable`, since the packed 124M path peaks around 1.7 GB RSS plus device buffers) and checkpoint/golden availability, so a small or offline host skips instead of failing.
`@requires_iree` (module-level `importlib.util.find_spec` probe) gates the compiling tests; `test_iree_rocm.py` adds `@requires_rocm`, composing that probe with an `etl.devices()` rocm/hip lookup so a CPU-only host's skip reason distinguishes "iree not installed" from "no rocm device" (nothing imports iree at module scope).
No test requires torch: the compiled/conformance path is numpy-only, and every other optional dependency is imported lazily inside a function or detected in a subprocess.

## Golden fixtures

`../bench_logs/hf_goldens/` (resolved from the repository root, never the process cwd) is the read-only contract between this suite and a separate torch-golden harness; it carries five fixtures (`tiny_random_llama`, `tiny_random_mistral`, `tiny_gpt2`, `distilgpt2`, `gpt2`) and nothing here writes it.
One pair per model: `<slug>.npz` with the required arrays `input_ids` (int32, `(batch, seq_len)`) and `logits` (float32, either `(batch, seq_len, vocab_size)` or `(batch*seq_len, vocab_size)`), and `<slug>.meta.json` carrying an HF repo id under `model` or `model_id` (`model` wins) plus informational keys such as `revision`/`dtype`.
Reading uses `allow_pickle=False`; the meta repo id wins over the slug mapping, and `dtype` is informational only — the stored logits must still be float32.
An absent directory makes the golden-parity test skip with a message restating the contract; a malformed fixture is reported by `test_golden_fixture_format` and an unmappable one by `test_golden_slugs_resolve`.
Measured parity (numpy interpreter vs the stored HF logits): `tiny_gpt2` bit-exact, `tiny_random_llama` 8.9e-8, `tiny_random_mistral` 1.2e-7, `distilgpt2` 1.07e-4 (1.3e-6 of an 82.1 absmax), `gpt2` 1.53e-4 (1.1e-6 of 138.7).

## `hf_download.py` contract

Stdlib-only test utility (imports `argparse`/`json`/`os`/`sys`/`tempfile`/`time`/`urllib`/`pathlib`; `pytest` only inside `require_model`), so it imports and runs standalone from the CLI — the `etl_hf` library never imports it.
Exports `HF_BASE`, `MODELS` (`tiny_llama` → `hf-internal-testing/tiny-random-LlamaForCausalLM`, `tiny_mistral`, `tiny_gpt2` → `sshleifer/tiny-gpt2`, `distilgpt2`, `gpt2` → `openai-community/gpt2`, plus the golden aliases `tiny_random_llama`/`tiny_random_mistral` → the tiny repo ids), `ALIASES`, `BIG_MODELS` (`{"distilgpt2", "gpt2"}`), `DEFAULT_SLUGS` (the three tiny checkpoints), `DownloadUnavailable`, `models_dir`, `fetch`, `download_model`, `is_available`, `require_model`, `ensure_models`, `main`.
Aliases resolve to the canonical slug's repo id **and** cache directory; an import-time invariant checks every alias is a `MODELS` key with its canonical repo id and belongs to neither `DEFAULT_SLUGS` nor `BIG_MODELS`.
`fetch(url, dest, *, timeout=120.0, retries=2)` is atomic (`<dest>.part` + `os.replace`, capped exponential backoff, HTTP 4xx except 429 fails immediately) and always raises `DownloadUnavailable` naming the URL; `download_model` fetches `config.json` first, then `model.safetensors` → its index + shards → `pytorch_model.bin` → its index + shards, raising one error listing every candidate; cache dirs are named from the slug with `/` → `__`.
`is_available` checks the cache without touching the network; `ensure_models` collects failures into one error and never returns a partial dict.
CLI: `python etl_hf/tests/hf_download.py [--slugs a,b] [--root DIR] [--check]`, one line per model (directory, weight-file count, size in MB), non-zero exit on any failure.

## Known Issues / quirks

`sshleifer/tiny-gpt2` (slug `tiny_gpt2`) is an ordinary oracle case: its legacy `pytorch_model.bin` is read correctly (the trailer's per-storage int64 element count is consumed), its 33 tensors match `torch.load`, and its logits are ordinary (`max |logit| ≈ 0.1285`, 2.2e-8 vs HuggingFace at `seq_len=8`, argmax identical at every non-tie position).
A shifted legacy parse still yields correctly-shaped tensors that agree with `etl_hf`'s own numpy reference, so only that external comparison (or `test_weights.py`'s exact-consumption check) can catch it — the `~1e-44` figure in `../bench_logs/hf_feasibility_findings.md` describes such a shifted parse, not the checkpoint.
ROCm specifics: `Device("rocm", 0)` maps to HAL `device_id = 1` (1-based; `create_device(0)` raises), fp32 `dot` is true fp32 on iree/ROCm, and the first `.to(cpu)` readback plus the first `place_params` leaf each pay a one-time driver/transfer init (tens to hundreds of ms) that must never be charged to a per-call loop.
`tiny-random-Mistral` uses exact `erf`-GELU, a documented StableHLO v1 deferral, so it is numpy-backend-only — never compiled here.
The compiled-path modules must not pin absolute latencies; they store what they measured and re-state it in failure messages instead.
Restoring a green suite after a public-API change means updating `test_public_api.py`'s removed-name/reachability tables first — it enumerates the whole surface and fails loudly on drift.
